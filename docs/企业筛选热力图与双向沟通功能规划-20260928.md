# 企业筛选热力图与双向沟通功能规划

日期：2026-09-28。本文档由用户口述需求润色整理而来。前九节保留原始规划和当时盘点，最新实施状态见第十节；不能将规划当作已验收能力。

## 一、原始需求（润色前留档）

> 企业端通过关键词和对应需求进行筛选，需要岗位热力图，进行对照，可以通过点击打开对应排名的简历匹配度详情如代码、个人匹配报告；对简历进行多维度分析，不同技能的雷达图体现；一键生成 AI 对个人简历的评估报告和后续安排；增加消息通知的功能模块，具有完整的沟通流程，通过简历的邮箱发送，AI 准备对应的发送模板。
> 学生端，对方已读不回的状态来让用户判断自己是否能入职或者进入面试阶段；HR 下载了简历，增加对应的状态回应，让双方做好下一步的准备。
> MCP 视觉功能再补强。

## 三、企业端功能

### 3.1 关键词与需求筛选

企业按岗位要求维度（技能关键词、岗位要求条目）对投递候选人进行筛选排序：

- 筛选入口挂在企业岗位详情页，维度来自既有 `JobRequirement`（skill_name、weight、is_required）。
- 排序键：岗位整体匹配度（现有 MatchReport.overall_score），支持按单一要求维度聚焦（如"只看 SQL 维度达标的候选人"）。
- 边界：筛选只读取已有匹配报告，不触发重新评分，不改变 evidence-v3 公式。

### 3.2 岗位匹配热力图

提供"岗位要求 × 候选人"匹配度矩阵热力图，作为企业对照浏览的主视图：

- 行为岗位要求条目（含权重），列为候选人（按 overall_score 排名），格子值为该候选人在该要求的 final_score，颜色梯度表达匹配强弱。
- 缺证据/仅自述/低支持用与正常支持可区分的样式（对应 verdict：supported / claimed_only / gap），不让"没证据"伪装成"低分有证据"。
- 点击任意格子或排名项下钻到 3.3 的匹配度详情。

### 3.3 简历匹配度详情（点击下钻）

从热力图/排名打开单个候选人的完整匹配视图：

- **代码证据**：每条要求的证据引用展示（文件路径、行号、snippet，来自既有 MatchItem 证据结构），可下钻查看项目文件预览（已有 portfolio 预览端点）。
- **个人匹配报告**：该候选人的 MatchReport 全文，含评级理由与引用。
- **授权语义（需在投递流程中明确固化）**：学生向岗位投递即授权该岗位所属企业查看其投递材料的匹配报告；未投递学生对企业完全不可见，延续"企业无法读取学生未授权材料"的硬约束。

### 3.4 简历多维分析与技能雷达图

- 以岗位要求维度为轴、final_score 为值渲染技能雷达图，一候选一图。
- gaps 与 claimed_only 维度在雷达图上以明显区分呈现（空心/描边），不与有证据的维度混淆。
- 数据全部来自既有匹配结果，可视化层不产生新的评分口径。

### 3.5 一键生成 AI 简历评估报告与后续安排

企业在候选人详情页一键触发，产出两部分：

1. **AI 评估报告**：对候选人该岗位匹配情况的综合评估（优势、缺口、风险提示），引用必须走现有引用校验与白名单，AI 可降级、可提任务，**不能提升证据等级**。
2. **后续安排建议**：面试/笔试/婉拒等下一步动作的候选建议（决策仍由企业做出）。

生成走既有任务框架（异步任务 + SSE + AiUsageLog 审计），提示版本独立管理。

### 3.6 消息通知模块与完整沟通流程

**站内通知（新实体 `Notification`）**：事件驱动，覆盖投递确认、企业查看、简历下载、回复/面试邀请等节点，双端各看各的。

**完整沟通流程状态机**（学生投递 → 企业查看 → 企业下载 → 企业回复）：

```
submitted（已投递）
  → viewed（企业已查看匹配详情）
  → downloaded（HR 已下载简历）
  → replied（已回复：面试邀请 / 继续沟通 / 婉拒）
```

每个状态迁移记录事件留痕（谁、何时、什么动作），状态变更写入既有审计纪律。

**邮件发送（通过简历所留邮箱）**：

- 邮箱取自学生简历材料中的联系方式，学生端可核对/修改；发送前学生可见授权状态。
- **AI 准备发送模板**：AI 按沟通场景（面试邀请、进展说明、婉拒）起草邮件模板，模板生成**必须经过既有文字外发凭据过滤**；采用"AI 起草、企业确认后发送"的受控模式，发送内容留痕可审计。
- 邮件外发记录入库（`EmailRecord`：模板哈希、AI 生成标记、发送状态），原始简历材料永不改写。

## 四、学生端功能

### 4.1 投递状态回应

学生端"我的投递"列表逐条展示状态回应：

- **HR 下载了简历** → 学生端看到"简历已被下载"状态回应（downloaded）。
- **企业已查看** → "企业已查看你的匹配详情"（viewed）。
- 状态来自平台内真实行为事件，事件不可伪造、不覆盖，失败记录保留（延续既有审计纪律）。

### 4.2 "已读不回"与下一步判断

- 学生端展示"对方已查看但尚未回复"状态（viewed 且未 replied），附距上次状态的时间。
- 用途：让学生据此自行判断跟进节奏、是否继续投递其他岗位。**系统只呈现事实，不自动得出"已读不回 = 无机会"的结论**。
- 双方做好下一步准备：企业侧 3.5 的后续安排建议落地后，学生侧同步展示企业的明确回应（面试邀请/继续沟通/婉拒），形成双向闭环。

## 六、数据模型与端点草案

新增/接线（均需随实现另立迁移与测试）：

| 项 | 内容 |
| --- | --- |
| `Application` 接线 | 现有空壳表接入路由；status 扩展为状态机枚举；投递 = 建立该岗位对学生的材料授权作用域 |
| `ApplicationEvent` | 状态事件留痕表（application_id、actor、事件类型、时间），状态变更只追加不覆盖 |
| `Notification` | 双端站内通知（接收人、类型、关联实体、已读标记） |
| `EmailRecord` | 邮件外发留痕（收件邮箱、模板哈希、AI 生成标记、发送状态、发送人） |
| 企业筛选端点 | 岗位候选人列表（排序+按要求维度过滤），只读复用 MatchReport |
| 热力图/雷达图端点 | 聚合端点或直接复用 match-reports 由前端渲染；不新增评分口径 |
| AI 评估报告端点 | 异步任务 + SSE + 用量审计，走既有任务框架 |
| 通知/邮件端点 | 通知列表与已读；企业确认发送邮件（AI 模板起草在先） |

前端（`jianli/`）对应新增：企业候选人筛选页、热力图与雷达图组件、候选人详情页、通知中心；学生端投递列表与状态时间线。

## 七、纪律与边界（延续既有工程纪律）

- **授权作用域**：企业读取学生材料仅限其投递岗位对应的授权范围；未投递学生对企业不可见。投递授权语义需独立验收，确保不破坏 MCP 已验收的作用域隔离纪律。
- **评分口径**：热力图/雷达图/筛选是既有匹配数据的可视化与读取，不引入新评分公式；AI 评估报告不能提升证据等级，等级规则（1–5、自动最高 3 级）不变。
- **AI 起草、人发送**：邮件由 AI 准备模板、企业确认后发送；模板必须过凭据过滤；发送留痕。
- **已读口径**："已查看/已下载"以平台内行为事件为准。**邮件已读回执在主流邮箱客户端普遍被屏蔽，不可靠，不作为状态承诺**。
- **学生端不做自动结论**："已读不回"仅呈现事实状态，不产生入职概率或淘汰推断。
- **用量与审计**：所有 AI 生成走 DeepSeek 官方 API 与 AiUsageLog 审计；缓存 Tokens 计入输入数不重复相加；账单未核对不称免费。

## 八、建议实施顺序

1. **Application 接线 + 状态机 + 事件留痕**（最小闭环：投递 → 查看 → 下载 → 回复），授权语义随本步固化。
2. **企业筛选与匹配度详情**（复用 MatchReport，只读），热力图/雷达图紧随（纯可视化）。
3. **AI 评估报告与后续安排一键生成**（受控生成 + 审计 + 提示版本管理）。
4. **站内通知** → **邮件发送 + AI 模板**（需 SMTP 配置；企业确认发送模式）。
5. **MCP 视觉补强**（待用户明确方向后另立验收）。

每步按"已实现 / 已验收 / 待验证"推进并更新能力矩阵；真实 API 验收用合成数据；浏览器验收待测试窗口授权。

## 十、2026-09-28 实施更新

第一轮范围：可恢复材料归档、当前账号导入统一 CP 案例、学生投递固定报告、企业授权候选人对照与回复、学生撤回与状态时间线。

- 接线 `Application`，保存明确授权的时间/版本及投递时报告快照；报告后来修改不覆盖已投递依据。企业只通过本岗位投递作用域查看固定报告，原学生私有报告及材料接口仍拒绝企业访问。
- `ApplicationEvent` 与独立审计追加事件。查看先于下载和回复，重复查看不重复增加首次事件；回复限三种动作加人工正文，需确认发送，已发送回复本期不可覆盖。
- 下载仅限本报告的简历版本，版本哈希与实际文件哈希都验证成功才记录“平台已交付下载响应”。不声称对方已保存/阅读，不推断入职概率。学生撤回后，企业列表、查看、下载及回复均拒绝；已下载副本无法追回。本期撤回后不重新投递同岗位。
- 同岗位重复投递相同报告复用，不覆盖其他已投递版本；初版限制滚动24小时20次。企业读取最近100份授权投递，关键词过滤与维度排序、热力对照及雷达展示复用快照分数，不调用模型、不改变公式。引用片段可在详情查看，尚未开放企业读取整个项目文件的旁路。
- 材料归档按已知旧合成名称及文件名双重判据，只归档，不删除文件或报告；普通选择不再显示，材料页可恢复。CP01—CP09 与真实简历不纳入自动清理。演示页为其他学生提供本人账号导入单套案例的入口。
