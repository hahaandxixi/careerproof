# CareerProof 功能演示

更新：2026-10-19。按当前网站导航和按钮整理，供课堂、答辩和本人功能体验使用。启动安装另见[使用与启动](使用与启动.md)，正式提交要求见[比赛交付](比赛交付.md)。本文按已确认功能整理，演示步骤不区分版本批次；当前运行版本与待验范围见任务清单（开发仓库内部记录，未随评审包分发）。

学生核心页面顶部提供“准备材料 → 推荐职业与岗位 → 查看岗位匹配 → 补充材料 → 确认投递”操作指南。靛蓝与“当前位置”只表示当前页面，不表示前面步骤已完成；可以往返，也不要求补证完成才能投递。确认投递仅在具体报告页链接到原有确认区，其他页面显示文字。手机可横向滑动步骤条，页面会提示“左右滑动查看全部 5 步”。职业推荐先看岗位概要，点击岗位展开补证建议，再按需展开推荐依据与代码；展开岗位使用浅靛蓝选中态。

## 先选演示路线

职业规划生成失败时，点击“保留材料，返回重试”保留已选简历、项目与同意勾选；确认材料后再次点击生成才会发起新请求。材料列表加载失败使用“重新加载材料”；历史读取失败使用“重新读取历史规划”，不会自动生成新规划。

| 路线 | 适合场景 | 演示内容 | 准备条件 |
| --- | --- | --- | --- |
| 5分钟功能预览 | 先了解网站、网络不稳定 | 合成热力图、已保存报告、折叠证据、补证工作台 | 网站启动；热力图无需账号，报告需学生账号及已保存结果 |
| 10—15分钟双端业务演示 | 课堂、比赛讲解 | 学生授权投递→企业查看/回复→通知→撤回→重新投递 | 同一岗位的学生报告；对应企业账号 |
| 另加10—20分钟补证演示 | 展示AI参与及成长闭环 | 选择一条缺口→任务→新版材料→新报告→逐项对比 | 合成新版材料；生成报告需要等待，真实AI步骤单独确认发送与费用 |

演示主线：**岗位要求有出处，报告结论有引用，缺口能转成补证任务，企业只看学生明确授权的固定快照。** 不以固定分数或录用结论作为演示成功条件。

### 开发者：不用外部模型准备完整合成链

Docker Engine和本地PostgreSQL就绪后，在实际仓库的 `backend` 目录运行：

```powershell
.\.venv-dependency23\Scripts\python.exe -m evals.release_smoke --run-id release-demo-01 --prepare
```

复用既有Start-E2E入口，使用3001/8001、专属同名cp_e2e库/storage和独立生产构建，完成上传解析、报告、企业授权/具名问题、通知、新版/逐项变化、撤回重投。报告由Mock/规则降级产生，不称真实DeepSeek成功；HTTP准备不能替代网页可用性验收。

运行ID必须全新、仅小写字母/数字/连字符且最多32字符。已有结果拒绝覆盖，失败保留证据，不重复执行或播种。确保3001/8001空闲，保留3000/8000。结果在 `backend/.tmp/release-smoke/<run>.json`；新合成学生凭据在相邻 `<run>.credentials.json`，企业凭据在 `backend/.tmp/e2e/<run>.json`，均不展示或提交。保存基准/新版/任务ID可用于讲解；旧投递已撤回，新版已重新授权。

停止用 `scripts/Stop-E2E.ps1 -RunId release-demo-01`，库和材料保留。恢复沿用同run隔离环境、SkipBuild/SkipSeed和合成核验配置，不清除记录；账号不可混用3000。首次生成与停止后恢复分别验收，见交付检查（历史记录保留在开发仓库）。

## 开始前准备

1. 按[使用与启动指南](使用与启动.md)启动：已有账号与样例时双击 `Start-Local.cmd`；首次演示初始化用 `Start-Demo.cmd`。不要重复播种已有演示数据，也不要为恢复展示使用 `-Reseed`。
2. 打开 [演示入口](http://127.0.0.1:3000/demo)。当前日常网站使用3000，独立开发验收使用3001，账号和报告不同。8124上的设计原型不能保存业务操作。
3. 3000的演示账号在本机本机 `backend/.tmp/demo-credentials.json`（首次演示初始化生成，不随包分发）读取 `studentEmail`、`enterpriseEmail` 和 `password`；3001的企业账号使用 `backend/.tmp/e2e/<RunId>.json` 内 `accounts.enterprise`。自行注册账号使用自行设置的密码。完整对应表见[先找到登录账号](使用与启动.md#先找到登录账号)，不要跨环境使用凭据。密码不展示在视频、截图或本文里。
4. 双端演示建议用两个浏览器或独立浏览器配置分别登录学生、企业；同一浏览器的普通标签页会共用会话，3000/3001端口也不隔离登录Cookie。退出学生后再登录企业也可以；保持同一环境和岗位所属企业。
5. 在“我的匹配报告”预先选定一份报告，记下岗位与材料版本（报告页「本报告固定材料：…」那一行即可，学生端不显示材料编号）。若演示版本变化，再准备同岗位更早报告及新版报告。首次初始化会准备合成账号、岗位和材料，**不保证已有报告、授权投递、企业回复或通知**。

### 推荐一套案例

首次体验从“岗位发现”选择标有“体验样例”的 Python 后端、React 前端或接口测试开发岗位，在详情下载配套虚构简历与项目包，再按[五步路线](使用与启动.md#学生先走通这五步)上传、选版本和生成报告。这三套材料不会自动写入所有学生账号，不预设评分或投递。

下表是演示页保留的历史 CP 案例，可用于复看已有报告；从发现页收起旧岗位不删除报告、投递或固定快照。首次体验优先使用上面的三套场景。

从 `/demo` 下载同编号的简历TXT、项目ZIP和测试步骤，或者复用演示学生账号已解析的同编号材料。其他学生账号可用“导入这套材料到我的账号”；导入不生成AI报告。

| 编号 | 职业 | 展示重点 |
| --- | --- | --- |
| CP01 | Python后端 | 接口/数据库/测试源码有支持，Redis和运行记录仍有缺口；建议优先使用 |
| CP02 / CP03 | 前端 / 软件测试 | 组件或断言的静态证据，不能冒充实际交互测试与执行成功 |
| CP04 / CP09 | 数据分析 / 数据工程 | 数据处理与查询；源码不能证明已产出图表、因果结论或真实运行 |
| CP05 / CP06 | 产品 / 用户运营 | 方案、验收条件和文案，不冒充真实访谈或活动效果 |
| CP07 / CP08 | 运维 / 数据库DBA | 对应静态操作材料，仍需运行和贡献核对 |

简历、项目与岗位尽量使用同编号；不要把CP01简历配到CP08项目来追求更高分。样例经历和指标均为虚构。

## 演示一：不用账号也能看热力图（约2分钟）

入口：[企业热力图交互示例](http://127.0.0.1:3000/demo/heatmap)，或演示页“打开热力图交互演示”。

1. 先指明顶部“合成界面演示”：3位虚构候选人、4项要求，状态与分数预设，不是实际投递。
2. 点击候选人B的SQL格子，雷达与详情一起切到该要求；再点雷达轴标签或下方要求按钮切换，可用Tab与Enter/空格操作。
3. 将“聚焦岗位要求”设为“SQL聚合查询”，“证据状态筛选”设为“缺材料”，应仅显示候选人C。
4. 恢复全部要求/状态，查看候选人C的自动化测试项：不可评显示“—”，不要解释成0分。
5. 输入不存在的关键词，展示空结果；点击“清除筛选”，候选人和详情恢复。窄屏时只横向滚动表格。

讲解：颜色和文字表示材料支持状态；雷达点表示原报告分数，空心点表示仅自述，缺材料不绘点。没有能力总分排名，也不能根据图形面积作录用判断。真实企业列表只能来自学生主动授权，列表为空时也能打开这个合成示例。

## 演示二：学生报告与折叠证据（约3分钟）

1. 用学生账号登录。顶部主导航是“岗位发现”“职业推荐”“我的匹配报告”；点击“学生账户 · 姓名”，下拉查看“个人材料”“个人投递”“通知”。
2. 打开“我的匹配报告”，选择已保存报告，先核对本次岗位，再读「下一步补证计划」区块里那行**「本报告固定材料：…」**——它在区块标题下方、“下一步：…”上方，格式是「材料标题（简历 v2） · 材料标题（项目 v2）」，末尾还会写“补证或上传新版不会替换本报告”。
3. 报告顶部先看基于已保存状态的一句话概括，再到“下一步补证计划”。四个状态按钮可展开或收起对应要求，优先展开有内容的“待补材料”，没有时依次展示“部分支持”“未覆盖或需复核”“有证据支持”；仍可自行切换或收起。数量与列表都来自本报告全部逐项要求，不受最多3条已保存建议限制。有建议时显示真实来源，同句缺口不重复；全支持时页面会提示核对引用后可直接投递，补证不是投递的前置条件；需要时再点“核对来源与逐项解释”。
4. 下方逐项证据先只看状态、简短解释和缺口。需要细看时展开“查看判断依据与AI解释”或“查看来源证据”；点击引用也会定位并展开来源。
5. 展开“本人核对记录（可选）”说明用途即可，不需要为演示随意采纳/驳回。它是学生对证据的意见记录，不是老师或企业认证，也不是继续补证的必填步骤。

如果没有报告：去“个人材料”确认简历和项目解析完成，再在“岗位发现”选择对应岗位和材料版本。不勾选外部AI同意，点击“生成我的匹配报告”，即可先体验不外发材料的本地规则报告。需要AI解释时，再阅读发送范围和费用说明，明确同意后生成；实际结果仍需区分AI完成与规则降级。

## 演示三：真实授权投递与企业热力图（约3分钟）

开始前，学生打开岗位页，先核对本岗位已保存的投递状态：进行中的投递会显示状态、下一步及“查看本岗位投递状态”链接；生成新报告不会替换该投递。已撤回记录会单独说明。状态读取失败可“重试读取”，不影响选择材料或生成报告；没有提示不等于已确认从未投递。

1. 学生报告页找到“向该岗位投递本份报告”，阅读分享范围，勾选同意后“确认投递”。企业获得的是本次固定报告、引用片段及本次简历下载权限，不是学生的全部材料。
2. 成功后点“查看投递进度”，或在账户菜单“个人投递”查看记录。卡片先显示岗位、状态、回复和下一步；“投递记录”默认折叠，按需展开。已保存相同报告的有效投递会复用，不需要反复点击创建。
3. 企业登录后，从“岗位管理”打开自己对应岗位，点击“查看本岗位已授权投递与匹配对照”。发布岗位本身不会得到学生私有报告。
4. 在“岗位要求 × 投递候选人”中筛选关键词、要求和状态，点击候选人姓名或格子，打开“投递时固定报告”。只有一名投递学生时只能展示一列；多人对照需要多名合成学生分别明确授权，不能用公共示例替代真实投递。
5. 核对报告引用：展开引用后每行先给引用编号、文件路径与行号，下一行给「证据类型 · 材料版本（本报告固定版本／历史版本未记录）· 内容摘要」。报告区另有可展开的「本次使用的材料版本」，列出这次投递固定的材料标题、版本号与编号（标题相同的材料靠编号区分）。企业不能预览材料原文，只能看到报告内已授权的引用片段。如需展示下载，使用“下载本次授权简历”。查看/下载只是平台行为，不表示通过筛选；下载副本无法靠撤回追回。

成功标志：学生能看到自己的记录；对应企业能查看该新编号；无关企业和未授权学生仍不可见。真实列表分数来自固定报告，不重新生成评分。

记录较多时，“个人投递”、企业候选人、匹配报告和补证任务每页20条，按页查看总数和更早记录，不再只显示最近100条。企业关键词/要求/状态筛选仅作用于当前页及通知额外定位的候选人。通知目标经过单独核对后可能补在当前页，不增加本页记录数或总数；没有足够数据时不强行演示翻页。

## 演示四：企业问题、通知与补证入口（约3分钟；加演示发送失败约 +40秒）

1. 企业先打开报告，从“证据联动”雷达点选要求，展开该项授权引用。少于3项或多于8项使用按钮与详情，避免绘图拥挤。在“发送站内回复”里先**选回应类型**（继续沟通／面试邀请／暂不推进）；AI功能位于折叠的“AI核验建议与沟通问题（按需查看）”中，已有建议时优先“读取已保存建议”；如需生成，单独阅读DeepSeek发送范围并同意，点击“生成或复用核验建议”。
2. “加入回复草稿”只填写草稿，不发送。发送前依次核对三件事：**当前收件人**（姓名＋投递编号前 8 位，写明只发给该投递对应学生）、正文、以及正文引出的要求与引用编号；然后勾选“我已核对正文，确认发送给这位投递学生”，再点击“确认发送站内回复”。
3. 发送成功后，该段显示为“已发送回复 · 回应类型 · 含 N 处原报告定位”，**本期不可覆盖**，下一条草稿不会顶掉已有结果。若发送失败，会出现“未确认发送的回复草稿”面板：草稿可编辑可复制、**没有发送按钮**、平台不会自动重发，需先刷新并核对该投递的回复状态。
4. 学生从账户菜单打开“通知”，刷新后查看企业回复通知，再“核对授权并打开投递”。通知支持全部/未读、分页、单条和全部标为已读；没有足够记录时不强行演示翻页。
5. 在“个人投递”查看企业回复正文及其原报告定位；有对应要求链接时点“带着这项问题补证”。手写回复没有定位引用时，可以先打开原报告，再从对应缺口进入。

讲解：AI辅助组织问题；企业核对后主动发送，学生再主动补证。没有自动发送邮件或自动替学生回复。发送失败时平台只保留可编辑草稿、不自动重发——这条可以现场展示，不必等出故障。

## 演示五：一条缺口到新版报告（扩展路线）

准备材料：在 `/demo` 的 CP01 卡片展开“继续演示补证：下载 Redis 合成新版”，下载补证项目 v2 和补证步骤。先用该卡片的首版简历、首版项目生成 Python 岗位报告，再按步骤更新原项目；不要将 v2 当成另一编号的新项目，也不要同时选 v1 和 v2。该新版只补 Redis 读写静态源码，不能证明运行成功或个人贡献。

1. 从工作台“从这条缺口开始补证”进入对应要求。已有任务时打开原任务，不重复创建；没有任务时填写缺口类型、具体交付物、执行步骤、核验条件，点击“保存并进入补证”。
2. 合格AI建议可补入空白项，再人工修改；没有建议时手动填写即可。示例交付物可选“为现有API补充参数校验和失败用例，附运行记录”，不要把未运行的样例写成已测试通过。
3. 在任务中上传新版材料。选定新版简历和项目后，必须点击“保存本次材料选择”；上传或临时改选本身不改变已保存分析范围。
4. 核对发送范围，确认后点“生成新报告”，等待完成。不要为避开等待反复创建任务。
5. 从任务查看固定基准与新报告的逐项差异，核对材料版本、支持引用、状态、解释和仍未解决的缺口；没有升级也是有效结果。
   分析中或已有新报告时，本轮材料区为只读，不再引导上传到这个已锁定任务。需要下一轮补证，点击“从新报告选择下一条缺口”，在新报告中重新选择；分析失败时仍可重新选择并保存材料后发起。
6. 报告页“查看版本变化”→“与上一份报告对比”，比较的是同岗位最近一份更早报告，**不保证等于任务固定基准**。展示任务闭环优先用任务里的对比。
7. 切回企业查看原投递，确认仍是投递时旧快照；新报告和私人补证任务不会自动分享。如果要分享新版，按下一节撤回并重新确认投递。

现场等待较长时，可以先展示已保存的基准/新版报告并说明本次没有重新调用模型；不能把预录或历史结果说成当场生成。

## 演示六：撤回后重新投递（约2分钟）

1. 学生“个人投递”→“撤回投递授权”→阅读说明→“确认撤回授权”。旧记录保留，状态变为已撤回。
   返回岗位页时，若显示撤回记录，它不代表进行中的投递，也不能据此断定没有其他有效记录；可进入本岗位投递状态核对，再从报告页重新确认授权。
2. 企业刷新授权投递列表，旧投递消失；旧通知不能再打开旧报告。已下载的文件不因此被删除。
3. 学生点击已撤回记录的“重新确认授权并投递”，在原报告分享区重新勾选授权并确认；如要分享新版，从新版报告分享区操作。
4. 学生列表同时显示新编号已投递、旧编号已撤回；企业只可打开新编号。旧回复、事件和固定快照保留，新投递不继承旧回复。

同一学生同岗位同时只允许一份有效投递；分享另一报告前先撤回旧有效投递。撤回后重新投递也计入24小时20次上限。岗位关闭时不能重新投递。

## 哪些操作会调用AI

| 操作 | 对模型/数据的影响 |
| --- | --- |
| 启动、登录、热力图示例、阅读已保存报告/对比 | 不触发新的外部模型生成 |
| 合成材料导入、上传解析、静态扫描 | 不生成AI报告；本地解析/OCR，上传代码不会被执行 |
| 保存补证任务、保存材料选择、本人核对 | 写入本人数据，不自动生成新报告或分享给企业 |
| 确认投递、企业查看/下载/回复、撤回 | 操作本地投递/授权/站内通知，不调用生成模型 |
| 岗位匹配、生成新报告、职业规划、AI提取岗位要求 | 可能调用真实DeepSeek，按页面同意、配置与预算执行 |
| 生成或复用企业核验建议 | 命中已有合格结果可复用；需要新生成时可能调用真实DeepSeek |
| 截图AI观察 | 单独的外部视觉请求；不同于本地OCR |

模型限额、失败或无可用证据可能保存降级报告；展示时保留模式/错误提示，不称其为真实AI成功。站内通知是业务事件记录，不是邮件送达证明。

## 现场问题速查

| 现象 | 下一步 |
| --- | --- |
| 没有热力图内容 | 公共示例直接打开 `/demo/heatmap`；真实企业页面需先由学生主动投递 |
| 企业看不到投递 | 核对登录企业、所属岗位、学生授权状态和刷新结果；不要改快照造数据 |
| 找不到账号密码 | 打开本机凭据文件；不要把3001隔离账号拿来登录3000 |
| 逐项来源默认不显示 | 展开来源，或点击引用；本人核对不是必须操作 |
| 上传新版后旧报告不变 | 这是固定报告行为；保存新版选择并主动生成新报告 |
| 没有版本对比 | 需要同岗位更早报告；切换岗位不能当成同岗位补证对比 |
| AI超时或预算不足 | 看任务记录与降级标记；演示已保存结果，不重复发起扣费请求 |
| 重新投递仍被拒绝 | 核对岗位是否关闭、是否另有有效投递、次数上限；刷新到最新服务版本 |

## 首次独立用户走查

**当前状态：尚未由首次使用者执行。** 交给一位未使用过本项目的人，只提供本节与材料；准备者记录但不口头引导。自动脚本、作者操作和模型审查不能代替这项验收。先走规则模式，真实AI质量由另一份独立人工评审表核对。

### 准备者先完成（不计入独立体验）

1. 确认3001/8001空闲、Docker和依赖就绪，使用全新隔离RunId，例如在根目录执行 `powershell -NoProfile -File scripts/Start-E2E.ps1 -RunId first-user-20261020 -SyntheticVerification -BackendVenv .venv-dependency23`。示例解释器是本机已安装环境，换机器按后端安装指南选择；已有RunId不得重复播种。该命令创建专属 `cp_e2e_<RunId>` 与存储，外发关闭，不操作3000正常库；本节整理未执行该启动命令。
2. 在隔离站注册一个本次专用学生账号，使用新邮箱/名称；账号和密码仅私下交给体验者，不写入仓库或截图。企业登录资料由启动后生成的本机 `backend/.tmp/e2e/<RunId>.json` 的 `accounts.enterprise` 查找，不打包口令。使用两种浏览器/独立配置分开角色会话，避免Cookie串号。
3. 企业在隔离站发布本次专用合成岗位，例如“首次走查-Python-日期”，确认三条要求：Python数据处理、SQL查询、pytest测试。岗位属于该企业，不复用正常网站岗位或旧报告ID。不让准备者替学生上传、生成或投递。
4. 将[三份材料](../../demo/first-user/)交给体验者：`resume.txt`、`v1.zip`、`v2.zip`。确认网页网址是3001；未准备好隔离环境时暂停写数据走查，不能改到3000凑结果。停止沿用 `scripts/Stop-E2E.ps1 -RunId <RunId>`，保留数据与凭据，不另起相同编号。

### 交给体验者的路线

1. 登录给你的学生账号，进入材料页，上传 `resume.txt` 与 `v1.zip` 到一个新项目，等解析结束。预期：简历和项目版本可选择；失败时按页面重试，不新建重复项目。
2. 从岗位发现选择准备者告知的岗位名称，选择刚才的简历和项目版本；不勾选外部AI同意，生成报告。预期：等待态有实际阶段，最终有已保存报告；规则模式不应冒充真实AI成功。
3. 在报告中找一条依据与一条缺口，打开原文核对路径/行号。没有依据时应明确缺失，不能靠声明当实现。记下你认为最该补的材料，不要求猜固定分数。
4. 阅读授权和接收企业，明确确认投递。企业用自己的隔离账号找到该学生的投递，核对授权报告/引用，写一条站内回复；学生在通知中打开并定位该条投递。预期：收件企业、报告版本与回复归属对应，不发送邮件。
5. 学生从一条缺口进入补证任务，将 `v2.zip` 上传到**原项目的新版本**；回任务保留简历、选择新版并保存，再主动生成规则新报告。查看固定基准与新版的逐项变化，用自己的话说出变了什么、哪些仍无证据。预期：比较对应保存版本，原报告与原投递快照不被新版覆盖。补证不要求撤回或重投。
