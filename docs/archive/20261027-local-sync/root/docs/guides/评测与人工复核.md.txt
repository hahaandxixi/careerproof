# 评测与人工复核

更新：2026-10-13。常规测试与以下离线 runner 使用合成数据，不调用外部模型。程序结构、引用合法性、来源一致性、建议可执行性、材料/岗位变化解释、人工语义质量分别报告。

## 可复跑入口

在 `backend` 目录使用已核验的升级环境；每次选新的输出名，避免覆盖基线：

```powershell
.\.venv-dependency23\Scripts\python.exe -m evals.run_quality_dimensions --output .tmp/quality-dimensions-new.json
.\.venv-dependency23\Scripts\python.exe -m evals.run_quality_review_benchmark --output .tmp/quality-review-new.json
```

前者处理固定三维合成用例，后者联合结构与已保存盲评。缺网站实际生成样本、独立人工标注时保持空值；旧作者草稿的 3/8 不能解释为网站准确率。当前签收范围见独立评测检查点（历史记录保留在开发仓库）和任务清单（开发仓库内部记录，未随评审包分发）。这次整理只核对命令入口，不重跑评测。

保存结果的漂移对照可用 `-m evals.check_output_drift --baseline <旧文件> --current <新文件> --output <新输出>`，不加 `--live`。旧供应商的结果可作为历史基线，不能恢复为当前产品配置或用来证明今日模型质量。

## 独立人工评审

固定难例、两轮补检索样例与评审表（历史记录保留在开发仓库）集中保留原合成输入/输出，不在本页重复展开。评审者逐项核对源码位置、完整上下文、判据上限、本人/第三方归属、矛盾、自述、注入及缺材料情况；分别标记支持、部分支持、不支持和无法判断，填写引用与理由。若某检查项对当前材料不适用（例如材料本身不是空实现，则“是否识别空实现”不适用），结论列填“不适用”并写明理由；不得代填或修改已有判词。

检索评审需独立标注真相关片段，包含近义干扰、跨文件上下文与多行边界；不能只对作者自选正例计算效果。建议须说明具体可交付物和核验点，明确未实现时先补实现；不把“上传日志”当缺失实现的替代品，不把材料补齐宣称能力提升的因果证明。

机器检查与另一个模型审查不能冒充真实人员签署。评审材料不得混入真实简历或凭据；自动生成包放证据目录，保留输入/输出/源码版本及 SHA256，不修改旧报告或自动签字。

## 真实模型评测与停止条件

需要新外部请求时另列具体合成输入、模型、请求数、输入/输出限制与费用范围。没有对应授权就只用保存结果，不因开发客户端获准或剩余额度充足自动调用网站模型。保留失败、未知用量和未执行样本，不通过多次重试掩盖失败；引用越界、来源矛盾或预算不可信时停止交棒。
