## 修复内容（retrieval.py，仅 `search_owned_chunks` + 导入/logger）

- 排序改为在 `WITH owned_chunks AS MATERIALIZED (SELECT … WHERE source_id IN (:allowed_ids))` 之上做距离排序，`limit` 照旧外层截断 → 过滤先于排序，召回与计划无关。选 MATERIALIZED 而非普通子查询的依据就是上表两行 fix-shape 对照。窗口函数 `count(*) OVER ()` 在同一查询里顺带取回自有命中总数，不额外发 COUNT。
- 计数器进每个返回行的既有 `metadata` dict：`requested` / `delivered` / `ownedMatches` / `shortfall`（`shortfall = delivered < min(limit, ownedMatches)`，语料本身小于 limit 不算 short）。`KnowledgeSearchResult.metadata: dict` 原样透传，无需改 schema（已核对 schemas/portfolio.py:13-18）。
- 每次检索一行结构化日志（JSON，`outcome` ∈ ok / no-profile / no-allowed-sources / no-indexed-chunks / engine-unavailable / invalid-query-vector），空表与短召从此可区分。
- 不变量核对：`select_query_engine`、`queryEngine`/`mixedEngines`、`local_embedding`、SEMANTIC_ENGINE 嵌入路径、`_valid_vector`、返回 dict 形状 `{id,sourceType,sourceId,content,metadata}` 全部未动；`index_sources`、`delete_source_chunks` 未动；未加/改/删任何索引或迁移。SQLAlchemy 2.0.43 的物化写法是 `cte(...).prefix_with("MATERIALIZED")`（该版本 CTE 无 `.materialized()` 方法，已用编译输出验证）。
