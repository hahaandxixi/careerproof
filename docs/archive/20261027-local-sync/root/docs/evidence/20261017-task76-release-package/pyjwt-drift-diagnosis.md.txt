## 结论：环境漂移，不是源码依赖不一致

`pyproject.toml` 的声明与锁定的意图本身**自洽**（单值 pin，无冲突）；失败来自
**当前虚拟环境里实际装的版本落后于声明**。即：源码要求 2.15.0，环境里仍是 2.10.1。

| **声明**（唯一真源） | `PyJWT==2.15.0` | `backend/pyproject.toml:22`（`[project].dependencies` 内） |
| **锁定 / 约束文件** | **不存在**：`backend/` 下无 `poetry.lock` / `requirements*.txt` / `uv.lock` / `constraints.txt` | `Get-ChildItem backend -Filter '*lock*'`、`-Filter 'requirements*.txt'` 均为空 |

| **检查结果** | `AssertionError: pyjwt: installed 2.10.1 != pin 2.15.0` → `1 failed` | 本轮实跑 |

## 判定依据

1. 测试 `test_installed_pins_match_pyproject_exactly` 的设计就是"已装 == 声明"，它读的是
   `pyproject.toml` 的 `[project].dependencies`（`_project_pins()`），失败信息直接给出两侧版本。
2. 声明侧只有一个 `==2.15.0`，`_project_pins()` 内的 `assert len(requirement.specifier) == 1`
   也未触发，说明**声明本身没有格式或范围冲突**。
3. 仓库内**没有**任何锁文件可以"覆盖"该声明，因此不存在"锁文件与 pyproject 互相矛盾"的情况；
   唯一的偏差在**已安装环境**。
4. 该失败在 Z61 交棒与本轮 task76 全量中**稳定复现于同一断言**，且本轮未触碰 `pyproject.toml`
   与任何依赖文件（`git status` 中无 `pyproject.toml`、无锁文件改动）。
