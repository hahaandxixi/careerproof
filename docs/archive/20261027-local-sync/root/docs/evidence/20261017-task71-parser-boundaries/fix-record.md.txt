## 3. 修复（`backend/app/tools/document_parser.py`）

- 新增两个窄元组，**不使用 `except Exception`**：

```python
_UNREADABLE_PDF = (fitz.FileDataError, fitz.FileNotFoundError, ValueError)
_UNREADABLE_DOCX = (BadZipFile, KeyError, ValueError)
```

  - `fitz.EmptyFileError` 是 `fitz.FileDataError` 子类，故零字节文件被第一个元组覆盖；
  - 加密 PDF 的 `ValueError` 发生在**遍历页面**时（`fitz.open` 本身成功），所以 `try` 包住了
    open + 遍历，不是只包 open；
  - `_UNREADABLE_DOCX` 中的 `KeyError` 对应损坏 OOXML 缺关键部件。
- 两处 `raise AppError(...) from error`：保留原始异常链，便于日志区分，但对外统一为可读拒绝。
- **未吞掉的**：既有 `AppError`（4024 无可析文字 / 4026 像素上限）在 `try` 内抛出但**不在元组中**，
  原样穿透——`test_existing_no_text_rejection_keeps_its_own_message` 与
  `test_pixel_budget_rejection_still_reports_its_own_code` 守住这一点。
- **资源清理**：`with fitz.open(...)` 保持原样，异常路径下上下文管理器仍负责关闭文档。
  （第二轮复核更正：第一轮用 `path.unlink()` 证明"已释放"是**假测试**——引用计数会兜底关闭。
  现已改为开/关计数相等断言，并如实声明"无法区分显式 with 关闭与 GC 终结器关闭"。
  详见 `review-round2.md` 第 2 节。）
