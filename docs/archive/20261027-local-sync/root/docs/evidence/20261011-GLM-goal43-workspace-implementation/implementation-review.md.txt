## 实质发现（3 项，均有定位）

### F1（P2）收起后再次点击同一缺口 CTA 无任何响应——新工作台主路径上的死链

- **定位**：ReportEvidenceWorkspace.tsx:21 CTA `<Link href="#growth-{id}">` + GrowthTaskStart.tsx:25-31 仅靠 `hashchange` 触发 `openFromAnchor`。
- **复现**：点"从这条缺口开始补证"→面板打开；点"收起补证任务"；再点同一 CTA——hash 未变，不触发 hashchange，浏览器同 hash 也不重滚，面板保持收起，链接看似失效。这是工作台最可能重复使用的一条路径。
- **本轮可修**（小改）：在 GrowthTaskStart 的锚点按钮或链接上加 click 兜底（如 hash 相同时手动 setOpen(true)+scrollIntoView），或 CTA 改为受控打开。**网站验收**：UX-02 完整 Tab 序列一并覆盖该路径。

### F2（P3）"仅简历声明"被并入"待补材料"统计，计数标签与逐项徽章口径不一致

- **定位**：evidence-workspace.ts:6 将 claimed_only 计入 gaps；ReportEvidenceWorkspace.tsx:15 该桶标签"待补材料"；同文件 ：19 徽章又区分"仅简历声明"，ReportDetail.tsx:20 VERDICTS 亦区分。
- **问题**：指标行把"材料存在但不完整"（gap）与"仅有简历自述、无任何材料"（claimed_only）合并显示，学生看计数无法区分两种严重度不同的状态；工作台 caption（:16）只声明了"未覆盖和已驳回或修正项需单独核对"，未声明此合并。
- **本轮可修**（文案级）：标签改"待补材料（含仅简历声明）"或拆成第五格。不阻塞验收。

### F3（P3）hash 打开面板的新路径无焦点管理与播报

- **定位**：GrowthTaskStart.tsx:24-31 打开面板时不移动焦点、无 live 播报；焦点停留在被点击的链接上，展开内容在下方，读屏/键盘用户无"面板已打开"的可感知信号（toggle 按钮 aria-expanded 会更新，但 hash 路径不经过任何按钮）。
- **问题**：这是本次新增的打开路径（旧 enterpriseReply 路径同病，但本次改动了该 effect 却未补焦点管理）；与设计说明"焦点……不可随布局改写"及 UX-02"焦点有可理解落点"的要求有差距。
- **本轮可修**：openFromAnchor 打开后聚焦 toggle 按钮（tabindex=-1）或在面板容器加 aria-live。也可并入 UX-02/UX-07 网站待验清单统一复验。
