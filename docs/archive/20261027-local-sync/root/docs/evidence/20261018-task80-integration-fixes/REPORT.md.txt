## 二、第 1 项：解析异常边界（已复现 → 已修）

### 红（修复前，`probe-parser-red.raw.out`）

用真实 `parse_document` 只替换失败协作者，得到：

| 用例 | 修复前 | 期望 |
| --- | --- | --- |
| `page.get_text` 抛内部 `ValueError` | **`AppError(4024)`**（被当成文件损坏） | 传播 |
| OCR `recognize_image` 抛 `ValueError` | **`AppError(4024)`** | 传播 |
| `_docx_text` 抛内部 `ValueError` | **`AppError(4024)`** | 传播 |
| `_docx_text` 抛内部 `KeyError` | **`AppError(4024)`** | 传播 |
| 损坏 PDF / 零字节 PDF / 加密 PDF | `AppError(4024)` | 保持 4024 |

根因：PDF 分支用整段 `try/except (FileDataError, FileNotFoundError, ValueError)` 包住"打开+读页+OCR"；
DOCX 分支把 `_docx_text`（本项目自己的遍历）也包进 `(BadZipFile, KeyError, ValueError)`。

### 修复（`backend/app/tools/document_parser.py`）

- 只把**打开文件**这一步视为输入问题：`fitz.open` 的窄捕获 `(fitz.FileDataError, fitz.FileNotFoundError)`；
  `Document(path)` 与其 `element.body` 取的窄捕获 `(BadZipFile, KeyError, ValueError)`。
- **加密改为显式判定**：打开后检查 `document.needs_pass`，命中即 `AppError(4024)`「已加密，需要密码」，
  不再依赖遍历时抛出的 `ValueError`。
- 读页、`get_pixmap`、OCR、`_docx_text` 全部移到捕获之外，内部异常照常传播；
  既有 `AppError`（4024 无可析文字 / 4026 像素预检）不在任何捕获元组内，原样保留。
- 上下文管理保留（`with document:`），失败路径仍关闭文档；`from error` 保留诊断原因。

## 三、第 2 项：材料预览加载状态（复现受阻，已做最小修复）

**代码路径确认缺陷可达**：外层 effect 切上下文时重置了 `selected`/`fileError`/`fileRequest`，
但**未重置 `fileLoading`**；在途文件请求被撤销后 `current=false`，其 `finally` 不再执行，
因此若新材料没有 `initialFileId`，旧文件的"正在加载文件…"会残留。

**修复**：外层 effect 增加 `setFileLoading("")`（附带注释说明为何必须在此重置）。

**未能用真实组件复现（明确阻塞）**：本机与四个已交付依赖 stage 均无 `jsdom`/`happy-dom`/`linkedom`/
`react-test-renderer`/`@testing-library/react`，React 19 的 effect 无法在 Node 内驱动；
按卡不安装、不绕行环境，故**未取得组件级红→绿**。该修复按代码路径判断为最小且严格增量
（只清空一个加载字符串），但**标为未经测试验证**。
