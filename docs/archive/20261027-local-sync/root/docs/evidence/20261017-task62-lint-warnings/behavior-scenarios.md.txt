## 环境阻塞项（如实）

- **S4（NotificationCenter 轮询竞态：依赖变化时在途旧轮询不得覆盖新数据）未能驱动**：本会话 IAB 标签页真实处于 `document.hidden`（面板失焦，`browser.capabilities.visibility.set(true)` 无法置前），而该组件按设计在 hidden 时不发轮询；且该 IAB 的 `document` 实例有**不可配置的 own `visibilityState` getter**（原型重定义无效），无法在页面内模拟可见性翻转。已观察到的部分：hidden 分支执行了真实失效（数据清空）。留待有可见视口的环境复验（Codex 复验路径：可见状态下刷新通知发起 R1 → 切走再切回标签页 → R2 返回后释放 R1 旧数据 → 断言无覆盖）。
- 页面水合存在 mock 安装竞态（layout 的 AuthProvider effect 可能先于页面模块 mock 执行，users/me 打到真实代理 500）：验证台以「mock 就绪后点重试」恢复，不影响组件行为结论；此为 stage 验证台局限，非产品缺陷。

## 组件改动（本轮真实修复，替代上一轮的等价赋值写法）

- NotificationLink：票据与取消标志收进 effect 闭包（`let cancelled/ticket`），清理只置 `cancelled=true`——**ref 全部移除**。
- MaterialPreview：文件选择改为状态驱动（`fileRequest` state + 专责 effect + 局部 `current` 旗标），身份切换 effect 体内 `setFileRequest(null)` 撤销在途请求——**ref 全部移除**；重复点击同文件仍会重新加载（请求对象带 seq）。
- NotificationCenter：`generation` 只在 effect 体/act/可见性处理推进（清理不读取）；新增 `alive` 旗标，清理中**仅做常量赋值** `alive.current=false`（不读取 ref 值，不落入规则关注的"清理读取过期 ref"场景），所有票据检查双门（`alive && ticket===generation`）。
