项目所有者已明确偏好比赛结束前不公开源码。私有仓库仅用于保留远程提交历史；若赛事要求评审访问，须按官方说明单独授予指定评审者权限或提交可访问的代码包。不要把私有仓库链接误写为公开可访问。赛后公开前，仍须处理下述 PyMuPDF 许可选择与第三方依赖核查。

## 已确认事实

- 项目业务代码形成独立 Git 仓库，首次提交是 2026-09-17 的可运行基线，没有伪造更早历史。
- 已配置并推送 GitHub 私有仓库 `hahaandxixi/careerproof`；可见性已核验为 `PRIVATE`，默认分支为 `main`。
- 后端直接依赖 `PyMuPDF==1.26.4`；本地包元数据标明 AGPL-3.0 或 Artifex 商业许可。
- 其余已登记的直接生产依赖使用 MIT、BSD、Apache、Unlicense 或 MIT-CMU 等许可。
- 本仓库没有复制 DeepSeek 网页反向代理项目代码，也不包含第三方网页 Cookie 或用户令牌。
- 2026-09-23 新增的本地语义模型 [paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) 模型卡标注 Apache-2.0；其 ONNX 权重不进入仓库，下载脚本固定提交与校验值。最终第三方清单需加入 FastEmbed 及其传递依赖。

## 可选方案

| 方案 | 适用目标 | 工作量与约束 |
| --- | --- | --- |
| AGPL-3.0-or-later | 比赛开源提交、愿意公开完整对应源码 | 改动最少；发布和网络服务场景必须按 AGPL 履行源码提供等义务，并确认赛事平台接受该许可证 |
| 替换 PyMuPDF 后采用 MIT/Apache-2.0 | 希望后续宽松复用、商业化或作为通用作品集 | 需要替换 PDF 文本提取和扫描页渲染，重新通过文本 PDF、扫描 PDF、OCR、超时隔离和材料任务回归 |
| Artifex 商业许可 | 希望保留 PyMuPDF 且不采用 AGPL | 需要额外采购与法务确认，不适合作为默认学生竞赛方案 |

## 当前建议

不要在未确认的情况下加入 MIT。若比赛要求公开源代码且团队接受 AGPL，选
AGPL-3.0-or-later 是最小改动方案；若希望作品以后以宽松许可证复用，应先替换 PyMuPDF，
再选择 MIT 或 Apache-2.0。
