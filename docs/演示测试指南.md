# 本地演示测试指南

第一次使用请按 [网站人工测试手册](网站人工测试手册.md) 操作；安装、双端使用和停止见 [完整操作流程](完整操作流程.md)。演示网页：`http://127.0.0.1:3000/demo`。

## 账号与初始化

启动 Docker Desktop 后双击根目录 `Start-Demo.cmd`。初始化会准备学生/企业账号、九个正常职业岗位，以及九套已命名的配对材料；只做本地上传解析，不生成 AI 报告。重复初始化复用同名且已完成的版本，不重置账号密码，不删除旧材料。

本机凭据在 `backend/.tmp/demo-credentials.json`，请负责人私下提供；网页不显示密码。也可配置 `DEMO_STUDENT_EMAIL`、`DEMO_ENTERPRISE_EMAIL`、`DEMO_PASSWORD`，必须三个一起设置。修改本地文件不会修改已有账号密码。

仅用于合成材料，不上传真实个人资料。项目使用 DeepSeek 官方 API，规则仅在无法获得有效 AI 结果时被动兜底。

## 职业、简历、项目和版本必须对应

| 编号 | 职业 | 对应项目/作品 |
| --- | --- | --- |
| CP01 | Python 后端 | 任务管理 API |
| CP02 | 前端开发 | 任务列表页面 |
| CP03 | 软件测试 | 任务接口测试 |
| CP04 | 数据分析 | 活动漏斗分析 |
| CP05 | 产品助理 | 校园失物登记方案 |
| CP06 | 用户运营 | 七日读书活动方案 |
| CP07 | 自动化运维 | 服务健康检查 |
| CP08 | 数据库 DBA | 任务数据库管理 |
| CP09 | 数据工程 | CSV 入库管道 |

每张网页卡片提供对应简历 TXT、项目 ZIP、人工测试步骤 TXT，文件名包含编号、职业和 `v1`。项目包内也写明配套简历和岗位。产品、运营提供方案文档，其余工程材料按职业分别准备；脚本未执行，不提供虚构通过率或运行日志。

1. 学生登录后，可以在材料选择中搜索编号，直接使用初始化的同编号简历与项目。
2. 若要验证上传功能，在 `/demo` 下载同一张卡片的三个文件，照卡片填写名称；名称末尾加本轮日期，避免与预置材料重名。简历传到简历入口、ZIP 传到项目入口，ZIP 不解压、不执行。
3. 等两份材料解析完成，预览原文。打开卡片的对应岗位入口，选择同编号、同版本，核对发送范围后授权并只点一次生成报告。
4. 查看实际 AI 状态，打开引用，核对内容是否支持解释；按该职业步骤文件检查已知缺口。没有证据不代表没有能力，不预设固定等级。
5. 保存本人复核说明，刷新、从报告列表找回。本人的采纳不是独立认证。
6. 测职业规划时也只用同一套材料；页面不自动勾选最近项目。规则预筛免费，生成 AI 规划会另外调用 DeepSeek。推荐其他方向不自动算失败，应检查理由和证据。

## 负责人维护

源清单：[职业案例清单](../demo/role-cases.json)。修改样例后在项目根目录执行：

```powershell
backend\.venv\Scripts\python.exe demo\build_role_packs.py
```

这会重新生成具名下载文件和演示页清单，不联网、不执行样例。修改下载版本时同步更新清单中的版本和文件名，保留旧报告固定的来源。

已运行的项目可在 `backend` 目录单独执行：

```powershell
.venv\Scripts\python.exe -m evals.seed_role_materials --apply
```

这只为当前本地演示学生准备配对材料，不生成模型报告。若同名版本失败、名称冲突或内容异常，停止初始化并检查，不强行覆盖。

内部历史/注入/补检索岗位已关闭，不是可投递的职业。专项 Function Calling 由负责人运行 `evals.verify_deepseek_tool_report`，历史难例由 `evals.verify_persisted_history_case` 等专用脚本准备；运行会消耗模型额度，需明确许可。专项脚本使用独立企业会话，结束或异常时尝试关闭其登记的测试岗位，保留报告，失败记录 `jobCleanup`。普通演示优先读取已保存的专项报告。
