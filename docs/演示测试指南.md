# 本地演示测试指南

第一次使用、不需要读代码的测试人员，优先按 [网站人工测试手册](网站人工测试手册.md) 逐项点击并填写通过/失败/未测。项目版本已改为收起式列表：展开“选择或更换项目版本”，搜索项目后展开版本，勾选并核对上方已选清单。

首次安装、企业端、学生端、AI断链兜底、OCR、Function Calling、测试、停止和录制顺序统一见 [完整操作流程](完整操作流程.md)。本页保留本地演示账号与样例的速查说明。

启动后打开 http://127.0.0.1:3000/demo 。登录页、学生材料页均有入口。

首次运行 `Start-Demo.ps1` 会在本机生成 `backend/.tmp/demo-credentials.json`。打开该未入库文件，按 `studentEmail`、`enterpriseEmail` 和 `password` 登录；也可以在启动前自行设置三个 `DEMO_*` 环境变量。网页不再公开展示凭据。再次启动复用同一份凭据，不会重置已有账号。

仅用于本地合成材料演示。不要在这些共享账号中上传个人资料，也不要将它们用于公开部署。

### 凭据检查与更换边界

在 `backend` 目录执行 `.\.venv\Scripts\python.exe -m evals.demo_credentials`，可离线检查两个邮箱不同、格式合法及密码长度（12–128字符）。检查不输出邮箱或密码、不连接服务、不创建账号；环境变量优先于本地文件，三个变量必须一起配置，密码按原值使用，不自动去除首尾空格。

**修改本地文件或 `DEMO_PASSWORD` 不等于账号密码轮换。** 数据库中已有账号的密码不随文件改变，旧登录会话也不会因此撤销。密码不匹配时播种停止，不重置密码、不自动重试或生成新身份；恢复原凭据可继续使用原账号及其报告。若明确需要一套新的合成演示身份，应同时填写两个新的、不同的邮箱和新密码，再执行播种；旧账号、材料、报告和会话仍保留，新身份不会继承它们。若凭据泄露，需要另行处理旧账号及会话，不能把换文件当作撤销。

播种开始前从同一份配置校验两个身份，避免企业邮箱错误或两个邮箱相同导致先创建学生账号再失败；这只排除本地配置错误，不保证两个账号的远程初始化为事务。数据库登录失败、网络故障仍可能留下此前已创建的演示资源。

## 测试步骤

1. 在演示指南下载合成简历 TXT、项目 ZIP。ZIP 不用解压。
2. 登录学生账号，进入「我的材料」。简历入口上传 TXT，项目入口上传 ZIP，分别填写名称并提交。当前支持点击选择文件，没有专门的拖拽区域。
3. 等待解析完成，可先打开解析内容确认文件已入库。
4. 进入岗位列表，搜索「合成演示」，打开「Python 后端开发实习生（合成演示）」。选择刚上传的简历、项目版本，开始匹配。
5. 查看进度和最终报告，点击证据查看原文件，保存人工复核后刷新页面确认记录保留。
6. 需要管理岗位时，退出学生账号再登录企业账号，在自己的岗位列表中查看或编辑。

新增 AI 体验：学生上传合成材料后进入「职业推荐」，生成带逐岗引用和补证任务的职业规划；上传新版本后再次生成，查看差异。企业账号进入「发布岗位」，粘贴至少 20 字的合成岗位描述，勾选同意后生成 AI 要求草稿；先定位原文并确认选中行，再手动保存草稿或发布。具体边界见 [AI 职业规划与岗位拆解](AI职业规划与岗位拆解-20260925.md)。

预期：Python、FastAPI、PostgreSQL、pytest 有不同强度的代码证据；Redis 只有简历声明。不能据此断言代码已运行成功或证明作者身份。系统始终按AI链路创建任务；模型断链或输出校验失败时才自动保存本地兜底报告。

## 受控 Function Calling 演示

演示页可直接下载 `evidence-function-call.zip`，仓库中的同源目录为 `demo/evidence-function-call/`。上传后选择“Python 受控补检索（合成验收）”岗位。报告应显示“受控补检索 1 次”，展开后看到当前上传材料范围和新增引用 `R1-E3`；该引用展示 `create_item` 的输入校验、服务调用和响应处理。

需要重新创建岗位或生成自动验收记录时，运行 `backend/evals/verify_deepseek_tool_report.py`。脚本会临时打包并通过正式本地 API 上传。浏览器和脚本重跑都会消耗真实模型额度，只在明确启用 DeepSeek 的合成测试环境运行；普通演示可以复用已保存报告。

## 新环境初始化

先按本地复现流程启动服务，在 backend 目录运行：

```powershell
.\.venv\Scripts\python.exe -m evals.seed_demo
```

若单独执行播种模块，请先运行一次 `Start-Demo.ps1` 生成本机凭据，或在当前终端设置 `DEMO_STUDENT_EMAIL`、`DEMO_ENTERPRISE_EMAIL`、`DEMO_PASSWORD`。脚本只请求本机 8000 端口。重复执行复用账号、组织和同名岗位；已有账号密码不匹配会失败，不会重置密码。演示岗位若被关闭会重新发布。不会自动上传材料或消耗模型额度。

2026-09-18 已在本机完成演示学生账号的上传、解析、选岗、授权、SSE、DeepSeek 报告、引用、人工复核、刷新和历史找回；390px 五页验收也已通过。新环境仍需重新执行初始化和主链路，不能复用本机结论冒充干净环境验收。

在岗位列表搜索「合成演示」。保持简历和项目版本相同，逐个匹配，比较引用是否支持要求、缺口是否真实。现有 ZIP 是后端样例，不是九个方向的合格样例；其余八个方向现有含缺口的合成简历与作品 TXT，可在演示页下载；不是完整工程或满分标准答案。不要用跨岗位总分代替职业适合度判断。

## 各方向材料填写与对照

新增方向各下载一份 resume.txt 和 project.txt。前者放简历入口，后者放项目作品入口。简历名称填写「方向名合成简历」，项目名称填写「方向名合成练习」，说明填写「合成测试作品，内容及未完成项见文档，不代表真实经历」。网页已逐项列出。

先匹配对应岗位，再用相同版本匹配其他岗位。重点记录每个引用实际支持了什么、缺少什么，不预设高分。TXT 里的代码片段属于作品文档，不等同代码工程的结构化检测。当前这些样例只验证材料准备与解析，尚未完成九职业匹配质量验收。

## 运维与 DBA 工程样例

演示页两张卡片新增「工程 ZIP（优先测试）」下载。简历仍使用对应 TXT；项目入口上传 ZIP，无需解压。项目名称可填写「自动化运维工程样例」或「DBA 工程样例」。说明填写「合成静态项目，未执行，不代表生产运行、性能优化或恢复演练已通过」。

运维 ZIP 包含健康检查脚本、Dockerfile、CI 配置和告警规则；DBA ZIP 包含 SQL、索引、授权、状态查询和备份命令。旧 TXT 保留为文档对照；不要把运行计划视为实际日志。
