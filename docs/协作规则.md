# Codex 与 ZCode 协作规则

更新：2026-10-10，当前用户偏好优先于历史套餐记录。

| 工作 | ZCode执行 | Codex负责 |
| --- | --- | --- |
| 有界功能与简单修复 | 实现、目标/受影响测试、首次页面验收 | 拆任务、边界与集成审查 |
| 复杂授权、并发与预算 | 按已确定协议实现独立部分 | 协议设计、安全裁决、高风险独立复验 |
| AI质量评测 | 合成样例、可重复runner、原始结果和自审 | 独立保留样例、可信引用/归因审查、P2决策 |
| 文档与交接 | 新证据文件和验收草稿 | 核对证据、定稿、当前状态和本地Git提交 |

使用BigModel个人计划；简单工作Flash，复杂问题GLM-5.3，可按难度选择最高推理。发送前核对实际套餐及用量，每周总消耗计入其他任务，最多70%，保留至少30%。不以过期截图推算余额，不为了耗额度制造任务。

ZCode每个新任务按“传智杯”序号递增并放入jbcode项目。实际仓库为 `D:\jbcode\web ai\jianli`；客户端顶部jbcode/master不能替代嵌套仓库main/HEAD检查。任务卡明确文件所有权、数据库所有权、验收和停止条件，默认不提交/推送。

同一文件、数据库夹具、Next构建目录只允许一个写入者。可并行执行互不重叠的文件任务；Codex不能同时改ZCode正在写的文件，也不能清理其未提交成果。P2暂停stash不擅自应用或删除。

ZCode交付原始命令/完整日志、失败留档、截图、源码与夹具hash、自审和一屏终态。Codex审证据与风险文件，对授权/撤回/并发/固定快照做代表独立复验，不以模型自报完成代替验证。

真实模型、真实材料外发、外部收件人、Git推送和部署须各有对应授权；ZCode个人额度许可不等于网站DeepSeek外发许可。网站合成Mock与真实模型质量/费用分别标记；缺独立人工语义复核时保持未验证。

本地代码按可验证批次提交Git，只显式暂存本轮文件。用户改动、历史临时文件、密钥及真实材料不混入提交。当前接力保持短小，阶段完成或约80–100k经验上下文阈值准备新会话，不伪造精确上下文量。

Windows操作使用computer-use，先核对唯一ZCode窗口、模型和目标任务，再发送；检测人工输入时刷新，不误发其他项目。Docker Desktop需要启动时按用户要求双击桌面图标，之后独立检查Engine、容器与数据库健康；不重置卷。

固定执行格式见[任务卡模板](templates/ZCode任务卡模板.md)、[证据包模板](templates/ZCode证据包模板.md)。历史经验保留在[历史计划与交接](archive/历史计划与交接.md)，不再维护多套协作手册。
