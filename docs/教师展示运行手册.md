# CareerProof 教师展示运行手册

适用场景：课堂汇报、指导老师检查、比赛预演和录制前走查。本文按“准备—启动—企业端—学生端—AI亮点—异常说明—结束”排列，照顺序操作即可。

## 1. 展示目标

建议用一句话介绍项目：

> CareerProof是一款面向高校学生求职准备的AI岗位证据分析Web应用。它把岗位要求、简历声明和项目原文连接起来，让DeepSeek解释材料支持了什么、还缺什么，并允许用户点击引用和人工复核。

本次展示需要让老师看到五点：

1. 企业端能够创建组织、发布和管理岗位；
2. 学生端能够上传简历与项目并查看解析结果；
3. AI真实参与证据解释、逐项初评和受控补检索；
4. 每个AI结论都能回到文件、行号和原文；
5. AI断链或输出不合格时，系统自动保存本地兜底报告。

2026-09-26 模型统一：上述学生与企业功能、截图内容观察均使用同一DeepSeek官方Key，无需智谱或百炼。可另外上传 `demo/synthetic-vision-panel.png`，在预览页单独授权原图外发后生成描述，点击估计区域、记录本人核对并刷新。图片按用量计费，不证明真实运行、不自动提高等级；OCR仍在本机处理。演示前先读[视觉验收边界](视觉证据验收-20260926.md)。

## 2. 展示前准备

### 2.1 电脑环境

确认已经安装并配置：

- Docker Desktop；
- Python 3.12；
- Node.js与npm；
- 项目后端和前端依赖；
- 若演示本地语义检索，已在 `backend` 目录运行 `python -m app.scripts.download_semantic_model`；
- `backend/.env` 中的DeepSeek官方API Key。

不要在老师面前打开 `.env`，不要在截图、视频或聊天中显示Key。

### 2.2 演示账号

运行 `Start-Demo.ps1` 后，在本机打开 `backend/.tmp/demo-credentials.json`。其中 `enterpriseEmail`、`studentEmail` 和 `password` 对应两个演示账号。文件被 Git 忽略，不要在录屏、截图或聊天中展示。账号只用于本地合成材料；公网环境不得播种演示账号。

演示前可在 `backend` 目录执行 `.\.venv\Scripts\python.exe -m evals.demo_credentials` 做离线配置检查，不会输出凭据或调用模型。不要只修改文件里的密码来尝试重置账号；已有账号密码和旧会话不会因此改变。恢复原配置，或按 [凭据更换边界](演示测试指南.md#凭据检查与更换边界) 显式建立新的合成身份。

### 2.3 演示材料

启动后打开 <http://127.0.0.1:3000/demo>，可以直接下载：

- 合成简历TXT；
- 基础项目ZIP；
- 补检索专项ZIP；
- 各职业方向的合成对照材料。

ZIP无需解压。正式展示只使用合成数据，不上传真实同学的简历。

### 2.4 推荐预演

展示前至少完整走一遍以下页面：

```text
/demo → /login → /jobs/mine → /portfolio → /jobs → /tasks/{id} → /reports/{id}
```

确认浏览器缩放为100%，关闭系统通知、密码管理器弹窗和无关标签页。提前在“我的匹配报告”中确认至少有一份成功的DeepSeek报告，以便现场网络不稳定时直接展示已经保存的结果。

## 3. 一键启动

### 3.1 启动Docker

先打开Docker Desktop，等待状态显示引擎已经运行。

### 3.2 双击启动

双击项目根目录：

```text
Start-Demo.cmd
```

脚本会自动完成：

1. 检查DeepSeek配置；
2. 启动PostgreSQL；
3. 执行数据库迁移；
4. 构建并启动前后端；
5. 检查服务健康状态；
6. 初始化企业、学生账号和九个合成岗位；
7. 打开演示指南。

看到以下提示即表示启动成功：

```text
CareerProof started successfully.
```

不要在启动完成前反复双击。脚本发现服务已经运行时不会重复启动。

### 3.3 检查页面

依次确认：

- <http://127.0.0.1:3000/demo> 可以打开；
- <http://127.0.0.1:8000/api/v1/health> 返回健康结果。

始终使用 `127.0.0.1`，不要与 `localhost` 混用。

## 4. 推荐展示顺序

完整展示约7分钟。如果课堂时间更短，可以跳过带“可选”的步骤。

### 4.1 项目定位，约30秒

打开首页并讲解：

> 普通简历匹配容易把技能关键词、依赖声明和真实项目实现混为一谈。CareerProof要求AI基于可定位的材料证据解释结论，并明确哪些内容仍未核验。

说明这是Next.js响应式Web应用，后端主要承担材料处理、AI接入、权限和证据持久化。

### 4.2 企业端，约1分20秒

1. 点击“登录”；
2. 使用企业演示账号登录；
3. 点击顶部“岗位管理”；
4. 展示预置的九个合成岗位及其状态；
5. 打开“Python后端开发实习生（合成演示）”；
6. 展示岗位描述、五项能力要求、重要程度和必要/加分属性；
7. 返回“岗位管理”，展示编辑、关闭和重新发布入口；
8. 点击“发布岗位”，展示企业组织、岗位字段和添加要求界面，不必现场提交重复岗位。

讲解口径：

> 企业端负责提供真实、结构化的岗位要求。岗位产生匹配记录后要求会锁定，防止企业修改要求后导致历史报告失真。

必须说明当前边界：企业不能直接查看学生私有简历和报告；投递与授权共享尚未实现。

### 4.3 切换学生端，约30秒

1. 点击右上角“退出”；
2. 使用学生演示账号登录；
3. 展示顶部“岗位发现”“我的材料”“职业推荐”“我的匹配报告”。

讲解口径：

> 学生决定上传哪些材料、选择哪些版本参加分析，并在发送给外部AI前看到最小发送范围。

### 4.4 上传与解析材料，约1分钟

进入“我的材料”。如果需要现场上传，填写：

```text
简历名称：教师展示合成简历
简历文件：student-resume.txt

项目名称：教师展示任务管理API
项目说明：合成测试项目，包含Python、FastAPI、PostgreSQL和pytest片段。运行情况和作者贡献未经核验。
项目文件：evidence-api.zip
```

等待解析完成后打开预览，展示：

- 简历文本；
- ZIP中的源码文件；
- 原始行号；
- 系统只做静态分析，不执行上传代码；
- 新版本不会覆盖旧报告引用的历史版本。

如果时间有限，直接打开已经解析完成的合成材料。

### 4.5 职业与岗位推荐，约40秒

1. 点击顶部“职业推荐”；
2. 保持默认选择的合成简历和项目版本；
3. 点击“生成职业推荐”；
4. 展示主要推荐方向、前五个岗位、匹配技能和一条源码依据；
5. 点击 Python 后端岗位的“查看岗位并生成完整 AI 报告”；
6. 核对岗位页已自动沿用刚才选择的合成简历和项目版本。

讲解口径：

> 推荐阶段把同一份材料一次性对照当前岗位库，不调用外部模型。它用可核对的简历声明和项目代码证据缩小选择范围；用户确定岗位后，才调用DeepSeek完成更细的逐项解释，从而控制API用量。

必须说明推荐顺序是材料证据贴合度，不是能力认证或录用概率。没有项目证据的结果只标为探索方向。

### 4.6 选择岗位与隐私授权，约50秒

1. 在职业推荐进入的岗位页核对岗位要求和已沿用的材料版本；
2. 展示“外部AI发送范围与脱敏预览”；
3. 勾选授权；
4. 点击“生成我的匹配报告”。

讲解口径：

> 系统不会把完整原文件直接发送给模型，只发送岗位要求、规则结论和每项最多三条必要证据片段。常见邮箱、手机号、身份证号和带标签姓名会再次脱敏。

未勾选授权时不能创建分析任务。

### 4.7 AI任务过程，约45秒

任务页应展示：

- 核对材料版本；
- 检索候选证据；
- 计算证据边界；
- 模型判断是否需要补检索；
- DeepSeek证据分析；
- 引用校验；
- 报告保存。

讲解口径：

> 页面展示的是可审计的执行阶段，不展示或伪造模型思维过程。SSE断开时页面改用轮询，这与模型断链是两回事。

如果现场模型响应较慢，可以直接打开“我的匹配报告”中的预存成功报告继续展示。

### 4.8 AI报告与引用，约1分30秒

打开报告后依次展示：

1. 顶部“AI证据初评 + 规则校验”；
2. 实际模型 `deepseek-flash`；
3. 模型耗时、输入Token和输出Token；
4. Python、FastAPI、PostgreSQL、pytest的逐项证据等级；
5. Redis只有简历声明，不能出现虚构实现；
6. “相关性、实质操作、完整任务”三项AI判断；
7. 信息缺口和补充建议；
8. 点击引用编号跳转到文件、行号和原文。

讲解口径：

> 当前自动初评最高到3级。4、5级需要运行验证和独立复核。评级描述材料支持度，不是考试证书、个人能力认证或录用概率。

### 4.9 Function Calling，约45秒

推荐打开已经保存的“Python受控补检索（合成验收）”报告：

1. 展开“受控补检索规划”记录；
2. 展示查询内容和“当前上传材料”范围；
3. 点击新增引用 `R1-E3`；
4. 核对 `create_item` 的校验、服务调用和返回处理。

讲解口径：

> 模型最多规划两轮，可根据上一轮结果决定继续或停止；每轮工具只能从当前学生本次选择的材料索引补一条证据，不能访问网络、任意文件或其他用户数据。

不要把这项能力说成MCP或通用多Agent系统。

### 4.10 人工复核，约35秒

1. 在一条证据下填写复核理由；
2. 点击“采纳证据”“驳回证据”或“标记已修正”；
3. 刷新页面；
4. 确认状态、备注和复核时间保留；
5. 返回“我的匹配报告”，确认历史可找回。

讲解口径：

> AI结论可以被用户核对和纠正。页面中的本人采纳只代表产品复核闭环，不冒充独立考官认证。

### 4.11 OCR与异常兜底，约40秒，可选

OCR演示：打开已经解析的合成图片或扫描PDF，展示页码、识别文本、平均置信度和“对照原图复核”提示。

异常兜底说明：使用已有的历史合成故障报告或测试记录，不要现场修改Key。说明模型出现网络失败、429、超时、鉴权错误、非法JSON、引用越界或评级越界时，系统会拒绝模型输出并自动保存本地兜底报告。

讲解口径：

> 产品只有AI分析模式。规则是模型前后的证据安全层，并且只在模型无法提供可采信结果时被动兜底，用户不能主动切换到规则模式。

## 5. 现场异常处理

| 现象 | 现场处理 |
| --- | --- |
| 启动提示Docker不可用 | 打开Docker Desktop，等待引擎就绪后重新双击启动脚本 |
| 启动提示DeepSeek配置缺失 | 检查本机 `.env`，不要在投影画面中打开该文件 |
| 提示存在旧的local run record | 新版启动脚本会在前后端都离线时自动安全清理；若仍失败，双击 `Stop-Demo.cmd` 后重试 |
| 3000或8000端口占用 | 双击 `Stop-Demo.cmd`，确认停止后重新启动；未知进程仍占用时先核对来源 |
| 页面打不开 | 检查启动窗口是否已经显示成功，不要连续重复双击 |
| 登录状态异常 | 统一使用 `127.0.0.1`，不要改用 `localhost` |
| 材料一直解析 | 点击刷新列表；查看任务状态；不要重复上传多份相同文件 |
| SSE显示连接中断 | 等待自动轮询；这不代表模型已经降级 |
| DeepSeek响应慢 | 打开已经保存的AI成功报告继续讲解 |
| 报告显示模型已降级 | 如实展示失败原因和兜底结果，不声称本次模型成功 |
| 引用或页面显示异常 | 停止现场生成，切换到预演时保存的报告 |

## 6. 老师常见问题与回答

### 6.1 这是不是简单调用大模型API？

不是。系统在模型前完成材料解析、证据检索、引用编号和评级上限；模型可进行至多两轮受控补检索规划；模型后还要经过JSON结构、要求编号、引用白名单、评级和过度结论校验。失败时不会直接展示未经验证的回答。

### 6.2 规则和AI是什么关系？

AI负责证据解释、缺口建议和1–3级初评；规则负责检索候选证据、限制模型边界和故障兜底。产品没有供用户主动选择的规则模式。

### 6.3 这是RAG吗？

当前准确表述是“可追溯的混合候选检索增强生成闭环”。系统先运行固定技能检测器，再以本地多语言 ONNX 模型检索项目文档、用有界词法排序补充代码及文本候选，随后核对文件哈希、行号和原文再交给 DeepSeek。两种补充候选都不能自动提高规则分数。语义模型需要事先安装；缺失或失败时只保留词法检索。四个固定检索小例与一次隔离进程来源核对已通过，但尚未证明真实材料上的通用向量 RAG 质量。

### 6.4 这是Agent吗？

当前是单工具、最多两轮的受控AI工作流。DeepSeek可以参考上一轮结果决定继续补检索或停止，但不是开放式通用Agent或多Agent系统。

### 6.5 为什么企业不能直接看学生报告？

这是当前隐私边界。学生报告包含私有材料，企业只有在未来实现明确投递和授权共享后才能查看；当前不因企业发布了岗位就自动开放学生数据。

### 6.6 分数能证明学生能力吗？

不能。当前已经改为逐项实践证据等级，表示本次材料对岗位要求的支持程度。代码没有被执行，测试结果、作者身份和本人贡献仍需核验。

### 6.7 为什么最高只自动评到3级？

1–3级可根据静态材料判断线索、局部操作和任务实现；4–5级需要运行结果、测试闭环、工程质量和独立复核，现阶段不自动授予，避免过度评价。

## 7. 讲解中不要使用的表述

不要说：

- “系统能准确判断一个人是否胜任岗位”；
- “AI评分就是候选人的能力分”；
- “所有岗位和职业都已经完整支持”；
- “这是通用Agent、通用RAG或MCP平台”；
- “OCR能理解图片中的业务逻辑”；
- “企业已经可以查看和排名全部候选人”；
- “DeepSeek API永久免费”；
- “代码已经运行通过”或“测试全部通过”，除非展示了真实运行记录。

建议说：

- “评级描述材料支持度”；
- “缺少证据不等于缺少能力”；
- “引用编号和原文已经校验，语义结论仍需人工复核”；
- “当前聚焦软件开发岗位的完整链路，其他方向用于覆盖边界展示”。

## 8. 展示结束

关闭浏览器后，双击：

```text
Stop-Demo.cmd
```

它会停止本项目启动的前后端进程和PostgreSQL容器，但保留数据库卷、演示账号、材料和历史报告。

看到以下提示表示停止完成：

```text
CareerProof and its PostgreSQL container have stopped. Saved data remains available.
```
