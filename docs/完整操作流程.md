# CareerProof 完整使用手册

本文覆盖系统管理员、企业用户和学生用户的完整操作流程，并作为比赛演示的统一操作依据。

如果准备课堂汇报或指导老师检查，优先使用 [教师展示运行手册](教师展示运行手册.md)，其中提供约7分钟的点击顺序、讲解口径和现场异常处理。

## 1. 产品运行原则

CareerProof 只提供一种面向用户的分析方式：**AI证据分析**。

正常流程为：

```text
上传材料
  → 本地解析与OCR
  → 按岗位要求检索候选证据
  → 本地规则确定引用范围和评级上限
  → DeepSeek解释证据并完成1–3级初评
  → 必要时申请一次受控补检索
  → 后端校验引用、评级和表达边界
  → 保存报告
```

规则引擎不是用户可选择的独立模式。它只承担三个职责：

1. 在模型调用前确定候选证据、引用白名单和评级上限；
2. 在模型返回后校验引用、评级和过度结论；
3. 在模型断链、限流、超时、鉴权失败或输出不合格时自动保存兜底报告。

如果材料完全没有可发送的证据，或账号达到每日AI用量上限，系统也会被动保存本地结果。用户未勾选外部AI授权时，前端不允许创建分析任务。

## 2. 角色与功能边界

| 角色 | 当前可以使用的功能 | 当前没有开放的功能 |
| --- | --- | --- |
| 学生 | 上传简历和项目、查看解析内容、选择岗位、生成AI报告、查看引用、人工复核、查看历史报告 | 向企业正式投递、共享报告授权、在线面试 |
| 企业 | 创建企业组织、发布岗位、设置要求和权重、编辑/关闭/重新发布岗位、管理本企业岗位 | 查看学生私有报告、候选人列表、AI候选人排序、面试邀请 |
| 管理员 | 具备受保护页面的管理访问能力 | 当前没有单独的后台运营控制台 |

学生报告默认只属于学生本人。企业发布岗位并不自动获得学生简历、项目或报告的读取权限。

## 3. 演示账号

演示账号只用于本地合成材料，不得部署到公网或存入真实个人数据。

运行 `Start-Demo.ps1` 后，在本机打开未入库的 `backend/.tmp/demo-credentials.json`：`studentEmail` 为学生账号，`enterpriseEmail` 为企业账号，`password` 为两者的密码。也可在启动前同时配置三个 `DEMO_*` 环境变量。演示网页不公开展示账号密码。

## 4. 首次安装

### 4.1 环境要求

- Windows 10/11和PowerShell；
- Python 3.12；
- Node.js与npm；
- 已启动的Docker Desktop；
- 可用的DeepSeek官方API Key。

检查环境：

```powershell
python --version
node --version
npm --version
docker version
```

### 4.2 安装后端

```powershell
Set-Location 'D:\jbcode\web ai\jianli\backend'
if (!(Test-Path .env)) { Copy-Item .env.example .env }
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

若要展示本地语义文档候选，在 `backend` 目录额外运行一次
`.\.venv\Scripts\python.exe -m app.scripts.download_semantic_model`。该命令下载约 235 MB 的
固定版本 ONNX 权重；未安装时报告继续使用词法检索和规则证据，不会在分析请求中自动下载。

编辑本机 `backend/.env`：

```dotenv
DATABASE_URL=postgresql+asyncpg://careerproof:careerproof@127.0.0.1:5432/careerproof
JWT_SECRET=本机专用且不少于32个字符的随机字符串

AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=true
DEEPSEEK_API_KEY=你的本机Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

Key只能保存在本机 `.env`，不得写进聊天、截图、视频、命令参数或Git仓库。

### 4.3 安装前端

```powershell
Set-Location 'D:\jbcode\web ai\jianli\jianli'
npm ci
Set-Location ..
```

### 4.4 启动前检查

```powershell
.\Start-Demo.ps1 -CheckOnly
```

预期看到后端依赖、Node版本、DeepSeek配置存在和AI优先预检通过。脚本不会打印Key，也不会启动服务。

## 5. 一键启动与停止

### 5.1 启动

直接双击项目根目录的 `Start-Demo.cmd`，或者运行：

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
.\Start-Demo.ps1
```

脚本会依次：

1. 检查DeepSeek配置；
2. 启动PostgreSQL；
3. 执行数据库迁移；
4. 构建并启动FastAPI和Next.js；
5. 检查前后端健康状态；
6. 初始化演示账号、企业组织和九个合成岗位；
7. 打开演示指南页面。

入口地址：

- 首页：<http://127.0.0.1:3000>
- 演示指南：<http://127.0.0.1:3000/demo>
- API健康检查：<http://127.0.0.1:8000/api/v1/health>
- API文档：<http://127.0.0.1:8000/docs>

全程使用 `127.0.0.1`，不要与 `localhost` 混用，以免登录Cookie不一致。

### 5.2 停止

可以直接双击项目根目录的 `Stop-Demo.cmd`。也可以在PowerShell中停止前后端并同时停止PostgreSQL容器：

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
.\Stop-Local.ps1 -Database
```

数据库卷和历史数据会保留。脚本不会删除上传文件。

## 6. 企业端完整流程

### 6.1 登录企业账号

1. 打开 <http://127.0.0.1:3000/login>；
2. 输入企业演示账号；
3. 登录后顶部导航应显示“岗位管理”和“发布岗位”。

新建真实企业账号时，在注册页选择“企业”角色。角色创建后不能通过前端随意切换。

### 6.2 创建企业组织

1. 进入“发布岗位”；
2. 展开“先创建你的企业组织”或“创建另一个企业组织”；
3. 填写企业名称和企业说明；
4. 点击“创建并选择企业”。

演示初始化脚本已经创建“CareerProof 合成演示企业”，通常可以直接选择。

### 6.3 发布岗位

进入 <http://127.0.0.1:3000/jobs/new>，依次填写：

| 字段 | 示例 |
| --- | --- |
| 所属企业 | CareerProof 合成演示企业 |
| 岗位名称 | Python后端开发实习生 |
| 岗位方向 | 软件开发 |
| 城市 | 深圳 |
| 工作类型 | 实习 |
| 岗位状态 | 公开发布 |
| 岗位描述 | 使用FastAPI开发接口，维护PostgreSQL数据并编写自动化测试 |

然后添加岗位要求。每条要求需要填写：

- 要求原文；
- 技能名称；
- 重要程度1–5；
- 必要要求或加分项。

推荐演示要求：Python、FastAPI、PostgreSQL、pytest、Redis。点击“发布岗位”后，应能在公开岗位列表中找到它。

### 6.4 管理岗位

进入 <http://127.0.0.1:3000/jobs/mine>：

- 使用关键词、方向、城市和类型筛选岗位；
- 查看草稿、已发布和已关闭状态；
- 编辑岗位基本信息；
- 关闭正在招聘的岗位；
- 将草稿或关闭岗位重新发布。

岗位已经产生匹配任务或报告后，能力要求会锁定。需要修改要求时应新建岗位，避免历史报告引用被改变。

### 6.5 企业端当前边界

企业打开岗位详情时只能看到岗位信息和要求。当前没有候选人投递与授权共享功能，因此：

- 企业不能查看学生私有简历和项目；
- 企业不能查看学生生成的匹配报告；
- 企业端没有候选人排名；
- 页面不会把学生数据伪装成企业可见数据。

比赛讲解时应将企业端描述为“企业组织与岗位供给端”，不能描述成完整ATS招聘系统。

## 7. 学生端完整流程

### 7.1 登录学生账号

1. 退出企业账号；
2. 打开登录页；
3. 使用学生演示账号登录；
4. 顶部导航应显示“岗位发现”“我的材料”“职业推荐”和“我的匹配报告”。

### 7.2 下载演示材料

打开 <http://127.0.0.1:3000/demo>，先下载：

- 合成简历TXT；
- 基础项目ZIP。

ZIP无需解压。所有演示数据均为合成内容。

### 7.3 上传简历

进入“我的材料”，在简历区域填写：

```text
简历名称：合成学生简历
文件：student-resume.txt
```

点击“上传并解析简历”，等待进度达到100%和状态变成解析完成。打开预览，确认提取文本与原文件一致。

简历支持PDF、DOCX、TXT、PNG、JPG/JPEG、WEBP和BMP，最大10MB。扫描PDF和图片使用本地OCR，OCR文本必须对照原图复核。

### 7.4 上传项目或作品

在项目区域填写：

```text
项目名称：任务管理 API（合成演示）
项目说明：合成测试项目，包含 Python、FastAPI、PostgreSQL 和 pytest 片段，用于测试证据匹配。运行情况和作者贡献未经核验。
文件：evidence-api.zip
```

点击“创建项目并开始扫描”。ZIP最大30MB，无需解压；打包前应移除 `node_modules` 等依赖目录。系统只做静态分析，不执行上传代码。

解析完成后打开项目预览，检查文件列表、原文行号和内容。上传新版本不会覆盖旧报告引用的历史版本。

### 7.5 获取职业与岗位推荐

1. 点击顶部“职业推荐”；
2. 选择一份已完成解析的简历；
3. 勾选要参与检索的项目版本，最多10项；
4. 点击“生成职业推荐”；
5. 查看主要推荐方向、具体岗位、匹配线索、源码证据和主要待补要求；
6. 选择一个岗位，点击“查看岗位并生成完整 AI 报告”。

推荐阶段只在本地读取已解析材料，一次比较当前已发布岗位，不调用外部模型、不产生API用量。推荐顺序是材料与岗位要求的证据贴合度，不是能力认证、跨人排名或录用概率。没有项目证据时，页面会把结果标记为“探索方向”，不能描述成强推荐。通过推荐入口进入岗位页时，页面会沿用本次选择的简历和项目；后端仍会在创建任务时检查材料归属和状态。

### 7.6 选择岗位

1. 从职业推荐进入岗位，或在“岗位发现”搜索并打开目标岗位；
2. 阅读岗位描述和要求；
3. 核对简历版本；从职业推荐进入时会自动沿用刚才选择的版本；
4. 核对要参与分析的项目版本，最多10项，也可以手动调整。

### 7.7 确认AI发送范围

页面会展示：

- 本次选择的材料；
- 岗位要求数量；
- 每项最多发送的必要证据片段；
- 邮箱、手机号、身份证号和标签姓名的自动脱敏范围；
- 不主动发送的账号身份、原始文件、完整简历和原始图片。

阅读后勾选：

```text
我已查看上述发送范围，同意将脱敏后的必要片段发送给外部AI生成带引用解释。
```

未勾选时不能创建任务。自由文本中的地址、别名或非标准个人信息不保证全部识别，因此真实使用时只选择完成分析必需的材料。

### 7.8 创建并观察分析任务

点击“生成我的匹配报告”。任务页通过SSE展示实时进度，连接中断时自动改用轮询获取任务状态。

正常记录应包括：

1. 核对材料版本；
2. 检索候选证据；
3. 计算证据边界；
4. 模型判断是否需要补检索；
5. DeepSeek证据分析；
6. 校验模型引用；
7. 保存可追溯报告。

SSE断开只影响页面实时更新，不等于DeepSeek断链。页面会改用轮询，不会因此把分析改成规则兜底。

### 7.9 阅读报告

报告顶部应显示真实处理结果：

- “AI证据初评 + 规则校验”：模型输出已经通过后端校验；
- “规则报告 · 模型已降级”：模型连接或输出失败，已被动保存本地结果。

AI成功时还应显示实际模型、耗时、输入Token和输出Token。逐项报告包括：

- 岗位要求和技能；
- 材料证据等级；
- AI对相关性、实质操作和完整任务的判断；
- 引用编号；
- 文件名、行号和原文；
- 信息缺口和补充建议。

评级含义：

| 等级 | 含义 |
| --- | --- |
| 1级 | 基础线索 |
| 2级 | 局部操作 |
| 3级 | 任务实现 |
| 4级 | 验证闭环 |
| 5级 | 工程验证 |

当前自动初评最高为3级。4、5级需要可审计的运行验证和独立复核，尚未开放自动授予。评级描述材料支持度，不是证书、个人能力认证或录用概率。

### 7.10 核对引用

展开“查看来源证据”，检查：

- 引用编号与AI解释一致；
- 文件路径和原始行号存在；
- 代码或文档片段确实支持当前结论；
- 依赖声明没有被说成完整实现；
- 代码片段没有被说成已经运行成功；
- 报告没有推断本人贡献。

### 7.11 人工复核

每条有来源的要求都可以：

- 采纳证据；
- 驳回证据；
- 标记已修正；
- 填写复核理由；
- 恢复待复核状态。

保存后刷新页面，状态、备注和时间应继续存在。该操作只代表当前用户复核，不等于独立考官认证。

### 7.12 查看历史报告

进入“我的匹配报告”，可以重新打开已完成报告。报告固定当次岗位要求和材料版本；后续上传新材料不会偷偷改写旧报告。

## 8. Function Calling专项演示

1. 在 `/demo` 下载“补检索专项ZIP”；
2. 上传为新的项目版本；
3. 打开“Python受控补检索（合成验收）”岗位；
4. 选择该项目并授权AI分析；
5. 创建报告；
6. 展开“受控补检索1次”；
7. 确认检索范围为“当前上传材料”；
8. 点击新增引用 `R1-E3`；
9. 确认定位到 `create_item` 的实际代码；
10. 确认报告仍保留运行结果、测试和本人贡献未核验的边界。

模型最多申请一次白名单补检索，不能访问任意文件、网络或其他用户数据。

## 9. OCR专项演示

1. 准备不含真实个人信息的PNG/JPG图片或扫描PDF；
2. 从简历入口上传；
3. 等待本地OCR完成；
4. 打开预览；
5. 核对页码、识别文本、平均置信度和人工复核提示；
6. 对照原图确认关键内容后再用于岗位分析。

原始图片不会发送给DeepSeek。系统只可能发送经过选择、检索和脱敏的必要文字片段。

## 10. AI断链与被动规则兜底

以下情况会触发被动兜底：

- DeepSeek网络连接失败；
- 请求超时；
- 429限流或服务繁忙；
- Key无效或鉴权失败；
- 模型输出不是可校验JSON；
- 引用不存在或跨要求引用；
- AI评级超过规则上限；
- 输出包含受保护的过度结论；
- 一次定向修正后仍未通过校验；
- 材料没有可发送证据；
- 达到账号每日用量上限。

兜底时系统不会伪造AI结果。报告会标明模型已降级，保留本地检索证据、材料缺口和可追溯来源；模型解释、AI评级和Token显示为空或按实际已发生调用记录。

用户不能从页面主动切换到规则模式。项目启动脚本也不再提供 `RulesOnly` 参数。

## 11. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 启动提示缺少DeepSeek配置 | 检查本机 `.env` 中启用开关、Provider和Key；脚本不会自动改成规则模式 |
| Docker数据库未就绪 | 等待Docker Desktop完成启动，再重新运行启动脚本 |
| 提示存在旧的local run record | 一键脚本会在前后端均离线时自动安全清理；仍失败时双击 `Stop-Demo.cmd` 再重试 |
| 3000或8000端口占用 | 如果是本项目上次启动，先运行 `Stop-Local.ps1`；不要误杀来源不明的进程 |
| 演示账号不存在 | 服务启动后运行 `backend/.venv/Scripts/python.exe -m evals.seed_demo` |
| 登录后立即失效 | 统一使用 `127.0.0.1`，清理混用 `localhost` 产生的旧Cookie |
| 文档没有可分析文字 | 打开材料预览；扫描文件使用OCR；损坏文件需要上传新版本 |
| ZIP上传失败 | 确认小于30MB、没有路径穿越、符号链接、依赖目录或过量文件 |
| 页面显示连接中断 | 这是SSE断开，页面会自动轮询；查看任务步骤判断模型是否真正降级 |
| 报告显示模型降级 | 查看任务实际记录中的失败原因，不要连续重试消耗额度 |
| 企业看不到学生报告 | 属于当前隐私边界；投递与授权共享尚未实现 |

日志位于 `backend/.tmp/local-run/`，该目录被Git忽略。

## 13. 推荐比赛演示顺序

1. 企业账号登录；
2. 展示企业组织、岗位要求和岗位管理；
3. 切换学生账号；
4. 上传合成简历和项目；
5. 查看材料解析与源码预览；
6. 用材料生成职业推荐，展开一条源码推荐依据；
7. 从推荐结果进入企业发布的岗位；
8. 展示AI发送范围并主动授权；
9. 展示SSE任务步骤；
10. 展示DeepSeek模型、Token和逐项证据评级；
11. 点击引用回到源码；
12. 展示一次Function Calling补检索；
13. 保存人工复核并刷新；
14. 展示历史报告；
15. 用已有故障记录说明模型失败时的被动规则兜底；
16. 说明企业目前不能查看学生私有报告。

正式演示不要主动关闭模型来制造“规则模式”。故障降级应使用已有自动测试或受控故障记录说明，避免临场修改Key和反复消耗额度。

## 14. 当前限制

- 企业端尚未实现投递、候选人列表与授权报告查看；
- 自动评级最高3级；
- OCR是本地图像转文字，不是通用视觉大模型；
- 当前是单工具、单次受控Function Calling，不是通用多Agent；
- 检索链路应称为可追溯的混合候选检索增强；当前使用固定检测器和有界词法排序，尚无语义embedding，不宣称通用向量RAG；
- 在线部署为可选加分项，本地演示仍需保证可复现。
