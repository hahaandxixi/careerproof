# CareerProof 完整操作流程

本文用于本地安装、比赛演示、功能验收和演示结束后的收尾。所有命令均在 Windows PowerShell 中执行，项目根目录默认为：

```text
D:\jbcode\web ai\jianli
```

演示只使用仓库提供的合成材料。不要把真实简历、API Key、Cookie、数据库密码或个人联系方式放入截图、视频和公开仓库。

## 一、先选择运行模式

| 模式 | 启动方式 | 是否调用外部模型 | 适用场景 |
| --- | --- | --- | --- |
| 规则模式 | `.\Start-Local.ps1 -RulesOnly` | 否 | 首次检查、无网络演示、稳定兜底 |
| DeepSeek 模式 | `.\Start-Local.ps1` | 取决于 `backend/.env` | 正式展示 AI 解释、评级和补检索 |
| 已保存报告 | 正常启动后从“我的匹配报告”打开 | 不新增调用 | 录制前预演、额度紧张时展示 |

首次安装和排错优先使用规则模式。确认主链路正常后，再切换 DeepSeek 模式生成一份新的合成报告。不要为了展示模型连续重复提交相同任务。

## 二、首次安装

### 1. 准备环境

需要：

- Windows 10/11 与 PowerShell；
- Python 3.12；
- Node.js 与 npm；
- 已启动并完成初始化的 Docker Desktop。

检查版本：

```powershell
python --version
node --version
npm --version
docker version
```

### 2. 安装后端依赖

```powershell
Set-Location 'D:\jbcode\web ai\jianli\backend'
if (!(Test-Path .env)) { Copy-Item .env.example .env }
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

打开 `backend/.env`，至少检查：

```dotenv
DATABASE_URL=postgresql+asyncpg://careerproof:careerproof@127.0.0.1:5432/careerproof
JWT_SECRET=本机专用且不少于32个字符的随机字符串
AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=false
```

此时保持 `AI_EXTERNAL_ENABLED=false`，先完成规则模式验收。

### 3. 安装前端依赖

```powershell
Set-Location 'D:\jbcode\web ai\jianli\jianli'
npm ci
Set-Location ..
```

### 4. 运行启动前检查

```powershell
.\Start-Local.ps1 -CheckOnly
```

预期看到：

```text
Backend dependencies OK
Preflight passed; no services started.
```

如果 Node 已安装但不在 PATH，可传入实际路径：

```powershell
.\Start-Local.ps1 -CheckOnly -NodePath 'C:\实际路径\node.exe'
```

## 三、启动系统

### 0. 比赛演示一键启动

依赖已经安装后，可以直接双击项目根目录的 `Start-Demo.cmd`。它会默认使用规则模式，依次启动 PostgreSQL、执行迁移、构建并启动前后端、初始化演示账号和九个岗位，最后打开 `/demo`。

命令行也可选择模式：

```powershell
# 默认规则模式，不调用外部模型
.\Start-Demo.cmd

# DeepSeek 模式；要求 backend/.env 已显式启用并配置 Key
.\Start-Demo.cmd ai

# 只检查，不启动
.\Start-Demo.ps1 -Mode Rules -CheckOnly
```

一键脚本不会安装依赖、写入 Key 或删除数据库。如果只检测到前端或后端其中一个服务，它会停止并要求先修复残留进程，避免在不完整环境中继续演示。

### 1. 无模型费用的规则模式

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
.\Start-Local.ps1 -RulesOnly
```

### 2. 检查服务

浏览器访问：

- 前端：<http://127.0.0.1:3000>
- 演示指南：<http://127.0.0.1:3000/demo>
- 后端健康检查：<http://127.0.0.1:8000/api/v1/health>
- API 文档：<http://127.0.0.1:8000/docs>

统一使用 `127.0.0.1`，不要与 `localhost` 混用，否则登录 Cookie 可能不一致。

### 3. 初始化演示账号和岗位

首次数据库需要执行一次；重复执行会复用已有账号和同名岗位：

```powershell
Set-Location 'D:\jbcode\web ai\jianli\backend'
.\.venv\Scripts\python.exe -m evals.seed_demo
Set-Location ..
```

预期输出包含两项账号验证和九个合成岗位验证。

演示账号：

| 角色 | 邮箱 | 密码 |
| --- | --- | --- |
| 学生 | `demo.student@example.com` | `CareerProof-Demo-2026!` |
| 企业 | `demo.enterprise@example.com` | `CareerProof-Demo-2026!` |

这些账号只用于本地合成数据，不可直接用于公开部署。

## 四、完成一次标准演示

### 1. 下载合成材料

打开 <http://127.0.0.1:3000/demo>，下载：

- “合成简历 TXT”；
- “基础项目 ZIP”。

ZIP 无需解压。标准主链路先不用“补检索专项 ZIP”。

### 2. 登录学生账号

1. 打开登录页；
2. 输入学生演示邮箱和密码；
3. 登录后进入“我的材料”。

### 3. 上传简历

在简历区域填写：

```text
简历名称：合成学生简历
文件：student-resume.txt
```

点击上传，等待状态变成“解析完成”。打开预览，确认文本可见。

### 4. 上传项目

在项目或作品区域填写：

```text
项目名称：任务管理 API（合成演示）
项目说明：合成测试项目，包含 Python、FastAPI、PostgreSQL 和 pytest 片段，用于测试证据匹配。运行情况和作者贡献未经核验。
文件：evidence-api.zip
```

点击上传，等待解析完成。打开文件预览，确认 ZIP 内多个源码文件已经列出。当前网页使用文件选择器上传，不提供专门拖拽区域。

### 5. 选择岗位并创建分析

1. 进入“岗位列表”；
2. 搜索“合成演示”；
3. 打开“Python 后端开发实习生（合成演示）”；
4. 选择刚上传的简历版本；
5. 勾选刚上传的项目版本；
6. 阅读“外部 AI 发送范围与脱敏预览”；
7. 勾选发送范围确认；
8. 点击“生成我的匹配报告”。

当前界面统一要求完成发送范围确认后才能创建任务。在 `-RulesOnly` 模式下，即使勾选确认，服务端仍禁止外部调用，只会生成规则报告。

### 6. 观察任务过程

任务页应依次展示材料核对、证据检索、规则计算、可选模型分析、引用校验和报告保存等步骤。SSE 正常时进度会自动更新，无需反复刷新。

如果任务失败：

- 临时错误可点击“重试此任务”；
- 重试只复用原材料版本；
- 文件格式或内容本身有问题时，应返回“我的材料”上传修正后的新版本。

### 7. 核对报告

至少检查以下内容：

1. 顶部标明“规则证据报告”“规则报告 · 模型已降级”或“AI 证据初评 + 规则校验”；
2. AI 模式下展示实际模型、耗时和 Token；规则模式不能声称使用了 AI；
3. Python、FastAPI、PostgreSQL、pytest 显示不同强度的材料证据；
4. Redis 只有简历声明，不应出现虚构实现；
5. 每条引用包含文件名、原始行号、原文和内容摘要；
6. 解释明确区分“材料中出现”与“代码已运行、测试已通过、本人完成”；
7. 等级按要求逐项显示，不汇总为录用概率或能力总分。

评级说明：

| 等级 | 含义 |
| --- | --- |
| 1 级 | 基础线索 |
| 2 级 | 局部操作 |
| 3 级 | 任务实现 |
| 4 级 | 验证闭环 |
| 5 级 | 工程验证 |

当前自动评级最高为 3 级。4、5 级尚未开放自动授予，需要可审计的运行验证和独立复核。

### 8. 完成人工复核

1. 展开一条要求；
2. 点击“查看来源证据”；
3. 对照解释和原文；
4. 填写复核理由；
5. 选择“采纳证据”“驳回证据”或“标记已修正”；
6. 刷新页面，确认状态、备注和复核时间仍然存在；
7. 进入“我的匹配报告”，确认历史报告可以重新打开。

页面中的人工复核只证明产品闭环有效，不等于比赛所需的独立人工语义评测。

## 五、启用 DeepSeek 真实模型

### 1. 配置本地环境

停止当前服务后，编辑 `backend/.env`：

```dotenv
AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=true
DEEPSEEK_API_KEY=你的本机Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

Key 只写入本机 `.env`，不要发到聊天、命令行参数、视频或 Git。

### 2. 运行最小连通测试

```powershell
Set-Location 'D:\jbcode\web ai\jianli\backend'
.\.venv\Scripts\python.exe -m app.scripts.check_deepseek
```

该脚本只发送合成内容，不打印 Key 和模型正文。确认返回模型名、引用数、Token 和耗时后再启动正式演示。

### 3. 启动 AI 模式

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
.\Start-Local.ps1
```

按第四部分重新生成一份报告。报告应如实显示是否调用模型；超时、限流、鉴权失败或输出校验失败时，系统应保留规则报告并标明降级。

默认用量保护包括：单报告最多 8 项要求、模型并发 1、每账号每天最多 20 份 AI 报告，以及输入输出 Token 上限。达到限额后继续生成规则报告。

## 六、Function Calling 补检索专项演示

此流程会产生真实模型调用，只在 DeepSeek 模式下执行一次。

1. 在 `/demo` 下载“补检索专项 ZIP”；
2. 将它上传到项目入口，项目名称填写“受控补检索项目（合成演示）”；
3. 在岗位列表打开“Python 受控补检索（合成验收）”；
4. 选择合成简历和该专项项目版本；
5. 阅读发送范围，勾选确认并生成报告；
6. 在任务页确认出现补检索阶段；
7. 在报告页展开“受控补检索 1 次”；
8. 确认范围为“当前上传材料”，并出现新增引用 `R1-E3`；
9. 点击 `R1-E3`，确认跳转到 `create_item` 的实际代码；
10. 确认报告仍指出运行结果、测试和本人贡献未核验。

模型最多申请一次白名单补检索，执行器只能访问本次选择材料的本地索引，不能访问任意文件、网络或数据库。

## 七、OCR 演示

OCR 在本机执行，原始图片不会发送给外部模型。

1. 准备不含真实个人信息的 PNG/JPG 图片或扫描 PDF；
2. 在“我的材料”的简历入口选择该文件；
3. 填写“合成 OCR 简历”并上传；
4. 等待解析完成；
5. 打开预览，确认页码、OCR 文本、平均置信度和人工复核提示；
6. 对照原图检查关键字段；
7. 若要继续匹配，只选择确认无误的 OCR 材料。

支持 PDF、DOCX、TXT、PNG、JPG/JPEG、WEBP、BMP 简历，单文件上限 10MB。默认最多 OCR 10 个无文本 PDF 页，低置信度文字会被过滤。空白图、损坏文件或无法识别的图片应明确失败，不能生成猜测文本。

## 八、多岗位对照演示

`/demo` 提供九个合成方向：Python 后端、前端、软件测试、数据分析、产品助理、用户运营、自动化运维、数据库 DBA、数据工程。

操作原则：

1. 每个方向分别下载对应简历 TXT 和作品材料；
2. 简历文件传到简历入口，作品 TXT/ZIP 传到项目入口；
3. 匹配同方向的合成岗位；
4. 再用同一材料匹配其他方向，观察证据和缺口变化；
5. 运维和 DBA 优先使用工程 ZIP；
6. 不将跨岗位评级直接解释成职业适合度；
7. “暂不支持评估”不等于没有该能力。

## 十、常见问题处理

| 现象 | 处理方式 |
| --- | --- |
| Docker 数据库未就绪 | 确认 Docker Desktop 已完成启动，再运行 `docker compose up -d --wait postgres` |
| 3000 或 8000 端口被占用 | 若是本项目上次启动的进程，运行 `Stop-Local.ps1`；不要直接结束来源不明的进程 |
| 演示账号不存在 | 服务启动后重新运行 `python -m evals.seed_demo` |
| 页面登录后立即失效 | 全程统一使用 `127.0.0.1`，清理混用 `localhost` 产生的旧 Cookie |
| 文档没有可分析文字 | 打开材料预览确认；扫描件使用 OCR；损坏或不支持的文件要上传新版本 |
| ZIP 上传失败 | 保持 ZIP 不解压，确认小于 30MB、没有路径穿越、符号链接或超量文件 |
| 模型返回 429/超时 | 不连续重试；使用已保存报告或切换规则模式，报告仍应可生成 |
| 报告没有 AI 标记 | 检查是否启用外部调用、是否授权、是否有可引用证据、是否达到限额，并查看任务实际记录 |
| 模型输出引用不存在 | 后端应拒绝该输出并降级；不要手工修改报告冒充成功 |
| 停止脚本提示进程不匹配 | 不要强制删除记录或误杀进程，先核对端口和进程来源 |

日志位于 `backend/.tmp/local-run/`，该目录不会提交到 Git。

## 十一、停止系统

仅停止前后端，保留 PostgreSQL 运行：

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
.\Stop-Local.ps1
```

同时停止 PostgreSQL 容器，保留数据库卷和历史数据：

```powershell
.\Stop-Local.ps1 -Database
```

停止脚本只结束由本次启动脚本记录且身份一致的进程，不会主动删除数据库卷或上传材料。

## 十二、比赛录制顺序

建议正式视频按以下顺序操作：

1. 首页说明问题、用户和隐私边界；
2. `/demo` 展示合成账号、材料和支持范围；
3. 上传简历与项目并打开解析预览；
4. 选择岗位、展示发送范围并主动授权；
5. 展示 SSE 实际执行步骤；
6. 展示 DeepSeek 带引用解释和逐项证据评级；
7. 点击引用回到原始代码；
8. 展开一次受控 Function Calling 补检索；
9. 保存人工复核并刷新；
10. 展示模型失败仍可生成规则报告；
11. 展示 OCR 或移动端页面；
12. 最后说明限制：未执行上传代码、评级不是证书或录用结论、4/5 级尚未自动授予。

正式录制前先用已保存报告完整预演一次，再进行一次受控真实调用。这样可以降低临场限流、格式错误和重复 Token 消耗的风险。

## 十三、提交前最后检查

完成演示不等于可以直接提交。还需确认：

- 独立评审者完成语义复核任务单；
- 项目所有者处理 PyMuPDF 的 AGPL/商业许可并确定根许可证；
- 学校、团队、组别和负责人信息已填写；
- 另一位成员在干净环境完成安装和主链路；
- Git 远程仓库、默认分支和提交历史可访问；
- `.env`、Key、真实简历、上传目录和本地日志未被提交；
- 最终 PDF、MP4 的页数、时长、编码、大小和命名符合官方要求。

详细状态见《赛前验收清单》和《发布前检查记录》。
