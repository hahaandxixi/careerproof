| 方案 | 设计与目的 | 保留的产品边界 |
| --- | --- | --- |
| A 学生证据工作台（原型备选） | 中性浅底与深青绿；先呈现逐项材料状态、关键缺口和补证主按钮；来源证据渐进展开；右侧说明三步闭环，移动端重排 | 只显示材料支持状态计数，不加能力总分；AI建议需核对；原投递版本固定；新版报告逐项解释变化 |
| B 企业核验台 | 较紧凑的逐项矩阵和独立核验面板；文字与颜色共同编码；先读来源依据，再整理具名问题 | 不按材料总分排名；不把颜色当录用结论；不混候选人/岗位/快照；问题发送仍人工确认 |

实施顺序：先基础控件/导航与真实报告阅读层级，再补证工作区，最后企业矩阵。先以真实数据字段计算状态，不把原型示例数字写入产品。投递授权仍在真实投递操作前明确展示，不因减少提示而隐藏授权、撤回限制、第三方参考或模型降级状态。详情折叠需保留证据锚点与通知定位；焦点、请求代际、账号切换清理等行为不可随布局改写。

## 测试依据与项目目标

W3C WCAG 2.2 官方解释已在本轮核对：

- [1.4.3 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字至少 4.5:1，符合条件的大字至少 3:1；颜色与禁用控件等应按各自准则判断，不把一次配色计算当整站合规。
- [1.4.10 重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：按准则在等效 320 CSS px 宽度检查；二维内容有例外，但本项目关键操作与解释仍需可读。
- [2.5.8 点击目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：AA 基准 24×24 CSS px，存在间距等例外；本项目主要按钮采用更宽松的至少 44px 设计目标，不能说标准一律要求44。
- [2.4.11 焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)：聚焦控件不能完全被作者创建的内容遮挡；同时检查可见焦点、合理顺序、错误后焦点与键盘可操作性。

补充体验门槛：字号/行距可读，状态不只靠颜色，减少动态效果偏好有效；加载不提前显示成功，重试不自动重新分析/扣预算；读取失败说明已存内容与下一步。真实性、权限和竞态测试与外观测试并行，不用截图代替业务证据。

## 可复现的验收案例

以下保留 10 月 11 日设计阶段的验收表。网站后续结果按任务清单和对应证据更新，不沿用表内旧“待验”作为现行结论。

| ID | 场景与动作 | 应观察的结果 | 原型实测 / 网站状态 |
| --- | --- | --- | --- |
| UX-01 | 1280桌面、390/320窄屏打开两角色页面 | 核心文本/按钮可读，无主页面横向溢出；窄屏矩阵有文字含义 | 原型两端390/320通过，学生1280通过；网站待验 |
| UX-02 | 键盘Tab/Shift+Tab、Enter展开证据/重试 | 顺序合理、焦点可见，折叠真实展开；错误恢复后焦点有可理解落点 | 原型Enter展开/重试、恢复H1通过；完整Tab序列待验 |
| UX-03 | 200%文字放大、400%页面缩放 | 不截断操作/解释，不以320视口测试冒充缩放实测 | 待实际缩放验收 |
| UX-04 | 普通/辅助/警示/按钮文本对比度 | 逐场景测量；颜色之外有标签；热力图能由文字理解 | 原型5组色对6.24–15.30:1；网站逐元素待验 |
| UX-05 | 点击目标与窄屏折叠菜单 | 主要控件至少44px设计目标，菜单展开后可触达，不误触相邻按钮 | 原型320已渲染控件无低于44px项；展开菜单待验 |
| UX-06 | 加载、空列表、读取失败、重试 | 状态可辨；无假成功/假零用量；重试不产生新分析或投递 | 原型状态切换/重试通过；网站失败注入待验 |
| UX-07 | 读屏访问标题、状态、错误、图例与表单 | 语义与可访问名称正确、状态变化能感知、字段错误关联 | 原型status/polite语义已核对；实际读屏待验 |
| UX-08 | 浏览器后退、刷新、隐藏恢复，保存途中继续编辑 | 已保存内容能重读；未保存丢弃提示准确；旧回执不能覆盖新编辑 | 41既有真实页面验收范围，尚待服务就绪执行 |
| UX-09 | 双账号/不同岗位/不同候选人切换，旧响应晚到 | 不闪现他人信息，不混引用、快照或权限；页面外观不能削弱清理 | 真实页面/授权边界测试待验 |
| UX-10 | 证据折叠后从通知/引用锚点进入 | 打开正确要求与来源，键盘焦点与滚动定位可解释 | 真实页面待验 |
| UX-11 | 长岗位名、长路径、中文/英文、多引用/无引用 | 自然换行，布局稳定；不通过截断隐藏需核对的关键事实 | 原型有长说明与路径；正式极值夹具待验 |
| UX-12 | 发布前执行分析→补证→新版→比较→企业旧投递复核 | 状态文本与服务端一致；原快照/已发回复哈希不变；无外发 | 网站端到端/PG证据为准，原型不执行业务 |

## 实测证据与职责

[原型证据目录](../evidence/20261011-design-prototype/)保存四张桌面/390px截图、浏览器检查和配色计算。本轮使用真实浏览器驱动切换视图/筛选/状态、按Enter操作；不是仅HTML静态检查。最初把native summary按button定位失败，后以实际可见文本唯一定位成功；第一次目标尺寸仅看几何框误纳入已折叠details子项，最终排除未显示子项后通过。该记录不掩盖失败，也不声称完整无障碍认证。W3C阅读经agent-reach Jina渠道连接失败后，改由网页工具打开官方原文核对。
