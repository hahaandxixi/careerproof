# DeepSeek 两轮补检索验收（2026-09-25）

## 范围与口径

使用仓库 `demo/evidence-api/` 的公开合成代码，通过后端证据工作流调用本地配置的 DeepSeek 官方 API。岗位要求为 FastAPI 与 Python 两项，每项初始拥有 5 条有来源的候选。此验收没有经过浏览器、上传 API 或数据库；不代表真实简历上的检索质量。两轮规划的离线模拟测试另有覆盖。

第二次运行的三个引用 `R1-E1`、`R1-E2`、`R1-E3` 和另一项的两个引用 `R2-E1`、`R2-E2` 均可按保存的路径与行号与合成源文件逐字核对。报告没有降级，自动结构与引用校验通过。**引用内容是否足以支持每句解释，尚待独立人工语义复核。**

模型在第二轮选择停止，不能把这两次运行表述为“两次工具执行成功”；它们只证明再规划请求实际发生、模型可以停止、停止决定现在可追溯。离线模拟用例验证了两轮分别补到 `R1-E3` 与 `R2-E3` 的执行边界。账单金额未在项目内核验，不把 Token 数换算为已确认费用。

## 复现与下一步

在 `backend` 目录运行 `python -m evals.verify_deepseek_two_rounds` 可免费检查候选数；显式添加 `--live` 才发起真实调用并生成新的 JSON，不覆盖旧记录。运行代码与项目自动化测试均不会输出 API Key。

下一步应由独立评审者逐项标注解释支持度、过度推断和第二轮停止是否合理；若评测显示遗漏关键证据，再调整规划条件，而不是强制模型执行第二次工具调用。真实上传与浏览器链路的两轮展示仍待验收。
