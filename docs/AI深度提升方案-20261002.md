## 三、分项详述

### P1 真·语义 embedding 入 pgvector（已完成）

- 动机：pgvector 当前是哈希词袋投影，能力矩阵已如实声明"不是语义 embedding"。用仓库内已有 MiniLM ONNX 模型（fastembed 0.7.4，本地固定 revision + SHA-256，`app/tools/semantic_retrieval.py:19-75`）生成真语义向量，是提升 RAG 项性价比最高的一步，且零新增云依赖。
- 改动：
  - `app/services/retrieval.py`：新增 `embed_for_index()`（MiniLM 优先，模型缺失自动回退 384 维哈希）、`resolve_query_engine()`（读取用户 chunk 的 engine 元数据决定查询向量引擎，混合时取最新块引擎并在结果元数据标 `mixedEngines`）；`EMBEDDING_DIMENSIONS` 1024→384。
  - Alembic `0012_semantic_knowledge_embedding.py`：knowledge_chunks 为纯派生索引，迁移直接清空后把列改为 `vector(384)` 并重建 HNSW 索引；downgrade 还原 1024。
  - `app/scripts/reindex_knowledge.py`：迁移后重建；输出各 engine 计数。
  - engine 标识：`embeddingEngine` 取 `minilm-l12-v2-onnx` / `local-hash-v1-384`，进 chunk 元数据可审计。
- 验收：PG 专项测试覆盖"MiniLM 索引→语义查询命中→engine 元数据一致"；模型缺失回退路径单测；SQLite 全量与 Ruff 通过；`alembic upgrade head` + `alembic check` 通过。
- 回滚：`alembic downgrade -1` + 重跑 reindex（旧哈希引擎）；无业务数据损失。

### P2 检索重排阶段（草稿已备，按指示暂停未合入）

- 动机：无重排时多路候选直接按原始分合并，位置偏差明显。先实现零依赖融合重排（RRF，k=60，对固定检测/词法/语义三路名次融合），把"重排"作为显式阶段接入报告候选装配；ONNX 交叉编码器（bge-reranker-base 量化）作为可选增强，待固定 revision 评测后再决定是否引入（不引入则不宣称）。
- 改动：`app/tools/hybrid_retrieval.py` 增加 `reciprocal_rank_fusion()`；`evidence_context.py` 装配处接入；候选元数据记录 `fusionRank`。
- 验收：64 例冻结对照集重跑无回归（documentScope/分类指标持平或更好）；融合前后名次对比写入评测 JSON。
- **草稿状态（2026-10-02）**：实现已完成——`app/tools/rank_fusion.py`（RRF k=60）、matcher 融合接入、缓存键加入 `candidateFusion` 版本；15 项专项测试通过；64 例对照与 09-27 基线逐项一致（evals/retrieval-comparison-20261002-192109.json）。因用户指示暂停改动，完整草稿（含未跑完的最终全量回归）收纳于 git stash：`stash@{0}`，恢复命令 `git stash pop`。

### P3 语音输入（未开始）

- 动机：多模态从"图像-only"补齐为"图像+语音"，前端零后端成本。
- 改动：`jianli/src/components/VoiceInputButton.tsx`（Web Speech API 封装：浏览器不支持/无权限时优雅隐藏或提示，不写库不上传音频）；接入岗位描述输入（JobForm）与职业规划追问（CareerRecommendations）。
- 验收：TypeScript/测试/构建通过；不支持语音的浏览器（Firefox）按钮不出现，功能零回归。

### P4 职业规划 token 级流式（未开始）

- 动机：目前唯一面向"生成型文本"的端点是职业规划，逐字流式对"AI 思考可视化"观感提升最大；报告仍是结构化 JSON，保持一次性返回（合理取舍，答辩可讲清）。
- 改动：`POST /career-plans/stream`（SSE：`plan.delta` 逐段、`plan.completed` 落库结果、`plan.failed` 分类错误）；DeepSeek `stream=True`；增量文本同样过出站脱敏与凭据过滤；前端 EventSource 渲染 + 现有轮询降级兜底；用量在 completed 事件一次性写入 AiUsageLog。
- 验收：PG 专项 + 新增流式契约测试；脱敏单测覆盖增量片段（跨块凭据拼接场景）；前端 390px 验收。

### P5 DeepSeek 上下文缓存对齐（未开始）

- 动机：DeepSeek 对重复前缀自动缓存计费减半。当前系统提示词已较稳定，但策略文件与少样例插值混在前缀中段，可能打断缓存命中。
- 改动：组装出站消息时把稳定内容（系统提示 + evidence_policy 全文）置于最前、易变内容（用户材料片段）置后；`cache_hit_tokens` 已在用量结构中（provider.py:553），在报告元数据与用量页面暴露命中率。
- 验收：真实调用前后对比缓存命中 tokens（留档 evals JSON）；功能回归全过。

### P6 AI 评测自动化（未开始；64 例对照已复跑留档）

- 动机：项目已有 41 个评测脚本与冻结基线，但依赖手动执行；把"契约评测 + 输出漂移检查 + 64 例检索对照"串成一条本地命令，作为回归门禁。
- 改动：`backend/evals/run_all_offline.py`（零 API：契约期望、漂移重放、检索对照、语义检索小例），输出汇总 JSON；失败退出码非零。
- 验收：本地一键全绿；公开仓库后原样接入 GitHub Actions（当前私有阶段不启用云 CI）。

### P7 auth 测试与 mypy（已完成 auth 部分）

- auth：新增 `app/tests/test_auth.py`（注册/登录/refresh/错误口令/弱密钥拒绝），补上唯一测试盲区。
- mypy 暂缓理由：收益主要在长期维护，赛期改动集中在已强测试覆盖的路径；790 项回归 + Ruff 已兜底，避免赛期引入新工具链噪音。赛后清理迭代再启用。
