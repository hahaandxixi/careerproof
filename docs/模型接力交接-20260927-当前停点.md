## 4. 当前未提交项：MCP片段截断与脱敏边界

### 真实问题和实现

原`search_evidence`先把snippet切到1000字符再过滤，保留原始行范围和来源哈希，却没有截断标记。合成长函数通过官方SDK读取时，新增断言因缺少snippetTruncated以KeyError失败，明确证明协议结果缺字段。

现在内部选出的最多5条保存证据先完整脱敏，再把返回文字限制1000字符。新增：

- `snippetTruncated`：脱敏后的文字实际被截断；不按原文长度猜测。
- `snippetRedacted`：公共过滤是否改变snippet；false不能证明不存在所有隐私。
- `snippetReturnedChars`：返回字符数，最多1000，不是Tokens或字节数。
- `sourceRangeBasis=saved_original_excerpt`：原lineStart/lineEnd标记原始保存片段，不能认为返回文字完整覆盖。
- `contentHashBasis=original_source`：哈希仍是来源身份，不是返回片段的哈希。

`sanitize_tool_result`只为search补这些字段，仍复用公共脱敏；工具说明及boundary同步提醒。不会修改报告、原始行号/哈希、等级、授权/撤销/40次限额或审计规则。
