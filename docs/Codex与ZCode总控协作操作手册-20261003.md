# Codex 与 ZCode 总控协作操作手册

更新日期：2026-10-09。适用项目：`D:\jbcode\web ai\jianli`。

这份手册把“一个窗口负责拆任务、验结果、安排下一轮”的思路落到本项目的实际操作。截图中的评论是工作方法的启发，不是模型价格、能力或项目状态的权威来源。此处的“总控”指一条负责需求、集成和验收的 Codex 会话；ZCode 是执行边界清晰的协作客户端。**Git 工作区、现行代码、测试和页面实测才是结果依据**。长期目标见[持续迭代目标与执行闭环](持续迭代目标与执行闭环-20260930.md)，跨客户端基础约定见[多 AI 协作与 ZCode 接力](多AI协作与ZCode接力-20261002.md)。

## 一、谁负责什么

| 环节 | Codex 总控负责 | ZCode 负责 | 完成标志 |
| --- | --- | --- | --- |
| 选题与拆分 | 排优先级、定协议和红线；每轮只填[任务卡模板](templates/ZCode任务卡模板.md)，给出 2–3 个顺序小项 | 先核对嵌套仓库，再调查不明确的复现条件；交付末尾给出有证据的下一项建议 | 每项有责任文件、验收标准与停止条件 |
| 开发与首轮审查 | 主导跨前后端协议、授权/撤回、固定快照、AI 结论可信度；全文审查这些边界文件的最终 diff，裁决争议 | 在指定范围内实现和补回归测试；用现有 `review-agent` 做只读缺陷审查，自行修正或列明发现 | ZCode 交付 diff 与自审结论；安全边界由 Codex 终审 |
| 自动测试 | 审计证据包，独立复跑 1–2 个最高风险断言；缺证据、失败或不稳定时扩大复跑范围 | 执行适用的目标、受影响、阶段全量测试及 Ruff/类型/构建，把原始命令、脱敏后的完整输出、退出码写入[证据包](templates/ZCode证据包模板.md) | 不采信“已通过”一句话；原始执行证据可审计，关键项双跑 |
| 生产页面测试 | 审核截图、状态和可复现步骤；阶段集成时抽验授权、双端链路或 390px 中风险最高的 1–2 条 | 浏览器工具可用时，使用合成账号完成指定双端与 390px 首验，保存截图和页面状态；工具失败如实登记 | 程序、页面与真实 AI 语义各自有独立结论 |
| 文档与交接 | **终审和签字**：核对数字、限制及代码一致性，合并正式 Bug 清单与不超过 100 行的接力清单 | **默认起草**新验收记录、变更说明和证据包，按固定模板写范围、命令、结果、风险、未验证项 | 正式文档由 Codex 审计定稿，ZCode 不与其并写同一文件 |
| Git 集成与额度 | 持有提交范围、冲突和远端同步决策；直接使用 BigModel 个人计划，按难度选择 GLM-5.3 或 Flash；每周总消费最多70% | 不擅自 reset/clean、应用 stash、提交、推送或切换额度组；中断时列出已改文件和未完成事项 | 工作树可审查，额度组和模型选择有现场依据 |

**提交节奏：**每个经过目标测试、边界复核和 `git diff --cached --check` 的可独立验收任务，由 Codex 做一个本地 Git 提交；不要求每次保存文件都提交。不同问题分开提交，证据与文档可随对应任务或独立文档提交。远端推送、合并和发布另外核对范围与授权。2026-10-04 的 B-08、B-11 分别形成 `f51858b`、`a389f75` 两个本地提交，尚未推送；下轮仍要重查状态。

**ZCode 闲时任务：**截图中的“Git 站会摘要”“CI 失败与不稳定测试报告”“文档同步检查”可以作为只读巡检。建议只输出证据与待办，不允许闲时任务自动改业务代码、改数据库、提交或推送；修改须进入有任务卡和验收条件的正常队列。只有确实要定时运行时才配置频率与唤醒选项，避免重复任务占用额度或扰乱单写入者规则。

当前 B-11 是过渡例子：ZCode 用免费 GLM-5.3-Flash 修改下载服务并补 PostgreSQL 并发测试；Codex 审查锁释放和撤回后的授权重检，并独立复跑关键项。该任务下达时已约定 ZCode 不编辑文档，因此本轮手册由 Codex 持有；**从下一张任务卡开始**默认让 ZCode 在新文件中起草验收记录与证据包，Codex 只做终审。

### 个人计划与模型选择（现行规则）

2026-10-09 用户更新：**免费计划已过时，直接使用 BigModel · 个人，不再等待或优先消耗 Start Plan。** 简单修复、批量测试、证据整理与文档起草优先 GLM-5.3-Flash；复杂协议、授权、并发、预算事务及反复返工的问题使用 GLM-5.3。推理强度按难度调整，必要时可开最高，以完成耗时、返工和可验收结果判断效率。每轮核对并记录实际套餐、模型、推理档和余额；准备好的输入不能记作已发送。

2026-10-07传智杯19的观察经验：用户正在操作键鼠时，UI输入可能受保护，截图也可能捕获前台游戏，而原生应用树滞留在旧草稿。此时不盲点发送或误判任务停止。可用[只读观察脚本](evidence/20261007-OPS-01C-codex/observe_zcode.py)对明确编号、唯一且属于本项目的session查询本地模型/工具时间与状态；mode=ro/query_only，不读其他任务正文或密钥、不写ZCode数据库。现场已证实Start Plan免费Flash/最高持续Edit和测试。旧task-index running标志不单独证明活执行；须结合新调用、实际工具句柄和重复观察。只读观察不能替代交棒/停止确认，不能用直接写数据库排队消息、修改状态或删除任务来绕过UI保护。若需发送审查，恢复UI后走正常任务输入；未发送的审查文件明确记“对方尚未确认读取”。

个人额度沿用2026-10-06授权：**每个周额度周期，最多自主使用总额度的70%推进本项目，保留至少30%；当前周期已有消耗计入，不是在剩余额度之外再增加70%。** 以 BigModel 现场每周余额与重置时间控制，记录任务前后余额和结果。余额不明先核对；达到周上限或五小时限额时保存现场并等待恢复，不自动改回免费计划。无需逐任务重新申请已授权额度。

此规则替代此前“免费 GLM-5.3 → 免费 Flash → 个人 GLM-5.3”的顺序。Codex 按问题难度选择个人模型，无需等 Flash 多次失败才使用 GLM-5.3。可在同一清晰任务内顺序处理2–3项有界工作，每项独立留证；高风险项先由 Codex 签收再进入下一项。切换额度组或上下文混乱时新建任务，承接已有改动，不重复实现；单写入者和分级验收不变。

2026-10-04 进度：B-08、B-11 代码已分别本地提交；B-16 合成 Chromium 复现未发现问题，产品页面仍待验；P0 企业单投递与 390px 首验已做，双投递竞态未验。P0 任务中 ZCode 撤回了唯一有效的 DBA 合成演示投递，超出“只做可精确恢复夹具改动”的任务卡约束，详见[边界审计](evidence/20261004-P0-enterprise-page/codex-audit.md)。以后任务卡须把演示夹具是否可丢弃写成明确停止条件，不能仅凭“合成”判定可撤回。下一批用隔离夹具补双投递。每项是否开始仍以当时工作树、测试和工具状态为准，不能让两个任务同时改同一数据库或文件。

历史额度截图仅解释当时的同名模型分组，不再作为当前选模顺序。当前直接使用 BigModel 个人计划；ZCode 可用只读子智能体调查不同模块，但共享工作区仍只有一个写入者，数据库和构建目录不能并行污染。

模型按当前 ZCode 菜单中的 **BigModel · 个人** 组及实际余额选择，同名模型可能属于不同套餐。10月3日的 Start Plan、Lite 和 MCP 余额仅是历史快照，不代表今日额度。个人计划额度与网站 DeepSeek 官方 API 预算相互独立，选模授权不扩大网站真实模型调用或数据外发范围。

不要为节省 token 同时打开许多会修改同一仓库的任务。默认一个共享工作区同一时刻只有一个写入者；总控可并行做只读复核或处理不重叠文件。确需并行写入时，先明确文件所有权，并使用互不冲突的工作树和测试数据，最后由总控集成。ZCode 顶部可能显示项目 `jbcode` 和根仓库分支 `master`；**本项目实际 Git 根目录是 `D:\jbcode\web ai\jianli`，分支与 HEAD 必须在此目录重新核对**。

## 可选工具怎样进入任务

ZCode 的设置页实际可见「记忆、子智能体、插件、MCP 服务器、技能、命令、钩子」入口；输入框提示可用 `/` 选择命令或能力。2026-10-03 的只读检查进一步确认：用户级**自定义命令 0 个**，不能宣称 `/goal` 已可用；技能页加载出多项技能，包括 `review-agent`、`control-browser` 与 `web-gui-tester`；插件页显示「浏览器操作」已启用、「电脑控制」未启用；MCP 页显示 `image_search` 已连接，而 `node_repl` 进程启动失败。上述状态可能变化，且列在页面上不等于在当前任务已成功调用。总控先核对当前任务需要什么能力，再打开相应入口查看名称、说明、权限、数据去向和是否已启用。B-11 后端事务修复不需要搜图或浏览器插件，直接用仓库代码和 PostgreSQL 测试更合适。

| 能力 | 适合本项目的用途 | 使用前后要核对 |
| --- | --- | --- |
| MCP / 插件 | 读取需要的外部资料或提供 ZCode 独有工具；本地仓库能直接完成的事优先读文件与跑测试 | 确认连接状态、访问范围和是否向外部服务发送源码/材料；记录实际调用与结果 |
| Skill / 技能 | 为重复的仓库检查、测试或文档操作提供固定步骤 | 先读该技能的说明；核对它适用于当前仓库，不能把技能文本当作用户授权 |
| 子智能体 | 独立只读调查或文件不重叠的小任务 | 明确文件所有权、统一由总控验收；共享数据库和 Git 状态不可同时写 |
| `/` 命令与目标管理 | 若输入框的命令列表实际提供 `/goal` 或等效目标跟踪，可记录本轮目标、验收标准和下一步 | 现有设置页无已安装自定义命令；先在输入框核对真实名称与效果，不能凭用户提到 `/goal` 就假定可用；目标记录不替代 Git、测试或页面证据 |

不要为了“用上能力”而安装组件、授权账号、创建密钥或扩大外发范围。某项能力没有配置或对本轮无帮助，就照常使用现有代码、测试和页面完成任务。

## 二、每轮操作顺序

### 1. 总控定边界，ZCode 搬运现场信息

在 PowerShell 进入嵌套仓库，记录输出：

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
git status --short
git log -1 --oneline
git rev-list --left-right --count HEAD...origin/main
git stash list
```

Codex 先看不超过 100 行的[当前接力](当前接力.md)、[任务清单](任务清单.md)和当前 `git status`，据此选择 2–3 个顺序小项，按[任务卡模板](templates/ZCode任务卡模板.md)填触发、验收、允许/禁止文件。[旧接力清单](下轮AI接力与验收清单-20261002.md)作为历史入口。ZCode 自己读取完整[Bug 清单](Bug测试与问题清单-20261002.md)、本轮验收记录及[固定约束](ZCode协作固定约束-20261004.md)，核对 stash 和未提交改动，给总控一屏以内的差异或阻碍。总控不再每轮重新朗读这些长文档；如果 ZCode 发现清单过期，给出文件和行号供总控裁决。

### 2. 在 ZCode 创建或续接任务

1. 第一批任务点击“新建任务”或按 `Ctrl+N`，选择 `jbcode` 项目。同一个人计划任务、同一清晰上下文中的后续小项可顺序续接，减少重复读仓库；额度组切换或上下文混乱时必须新建任务。
2. 打开模型菜单，确认 **BigModel · 个人**，核对五小时、每周余额和重置时间。简单任务选择 Flash，复杂任务选择 GLM-5.3；推理档按难度选。每周总消费最多70%，包含已有消耗。额度面板与调用冲突时核对实际结果，保留已有成果，不重复发送任务。
3. 核对访问模式。只读调查使用只读指令；允许改代码的任务只开放本地所需范围。Codex 只发送固定开头与填好的 10 行以内任务卡，并让 ZCode 读取固定约束与交付模板；不要每轮手写长指令。
4. 发送后确认生成了新任务、选中的模型/额度组正确，并观察第一步是否进入了 `jianli` Git 仓库。记录任务标题和开始时 HEAD；ZCode 操作记录不能替代 Git 检查。
5. ZCode 在一项完成 L1 自检并落证据包后，低风险队列可按任务卡顺序继续；涉及授权、撤回、并发、固定快照、用量或 AI 事实归因的下一项须等 Codex 对前项完成 L2 签字。总控期间可审核已交付项，但不同时改 ZCode 正在编辑的文件，也不同时改变共享数据库夹具或 Git 状态。抽检失败时立即暂停队列并修正。

新任务的固定开头只需：

```text
项目根目录 D:\jbcode\web ai\jianli。请先读取 docs/ZCode协作固定约束-20261004.md、docs/templates/ZCode任务卡模板.md 和 docs/templates/ZCode证据包模板.md。
按下面填写的任务卡顺序执行；先核对嵌套仓库现场。每项完成后尝试用 review-agent 做只读缺陷审查，修正发现，保存脱敏后的完整测试输出和页面证据到新证据包；如技能不可用，写明原因并做人工自审。
回报限一屏：目标行为、文件范围、测试总数/失败数、证据路径、自审发现、风险、下一项建议。不要把长 diff 或完整日志粘贴进聊天。
[在此粘贴不超过 10 行的任务卡；可连续放 2–3 张]
```

当前任务收到额度不足提示时，核对 BigModel 五小时与周余额。五小时限额等待恢复；周剩余到30%时停止新增个人调用。复杂度升高时可切个人 GLM-5.3；上下文混乱或换额度组时另开任务，带上 git status、已有改动、未完成项和失败证据，先核对再继续，不清除旧成果。新任务开头可以追加：

```text
这是额度切换后的新任务。上个任务已留下 [文件/测试/当前状态]，请先只读核对 diff，再从未完成处继续；不要 reset、clean、覆盖或重复提交。当前任务使用 ZCode 菜单中已确认的 BigModel 个人 额度组和 [具体模型]。
```

### 3. 分级验收与证据包审计

ZCode 先交[证据包](templates/ZCode证据包模板.md)：原始命令、脱敏后的完整输出、退出码、Git 文件列表、`review-agent` 发现及处理、页面截图/状态、未验证项和下一项建议。可在 `docs/evidence/YYYYMMDD-任务号/` 下放 `summary.md`、`tests.log`、`review.md` 和仅含合成数据的截图；日志不得含密码、密钥或真实简历。聊天回报限一屏。没有实际运行的技能、测试或页面步骤必须标记未验证。

Codex 默认只看 `summary.md` 的关键段、`git status --short`、`git diff --check` 和 `git diff --stat`：

```powershell
git status --short
git diff --check
git diff --stat
# 审查边界时，把下列示例路径换成该任务卡涉及的实际文件
git diff -- backend/app/services/applications.py backend/app/tests/test_applications_api.py
```

验收分层：L1 由 ZCode 及工具检查全部文件范围、目标/受影响/阶段全量测试、Ruff、类型、构建和页面首验；`review-agent` 可用时做第一轮只读缺陷审查。L2 由 Codex 对安全边界文件看完整 diff，对其他文件按 `--stat` 抽查，并独立复跑 1–2 个最能证伪的并发、故障注入或授权断言；阶段集成时抽验 1–2 条关键页面路径。缺原始输出、测试改成跳过、diff 越界、抽检失败或页面证据不一致时，Codex 扩大审查与复跑范围，必要时重跑全量。共用 Next 构建目录的构建和类型检查由 ZCode 顺序执行。

验收记录要区分：**代码和自动测试通过**、**生产页面实测通过**、**真实模型调用完成**、**AI 语义由独立人员复核**。这些是不同结论。ZCode 默认在新文件起草验收记录；Codex 核对证据、定稿 Bug 状态和接力清单。接力清单保持 100 行以内；阶段完成后由新 Codex 会话读取清单接手，详细日志留在证据包，不随对话反复搬运。

## 三、当前项目的实战例子与风险处理

2026-10-03 的 B-07/B-09/B-10/B-12/B-13/B-14/B-15 修复使用了“ZCode 做有界修复、Codex 独立审查并补边界”的方式。原免费任务返回额度不足后，B-15 在**新的 ZCode 任务**使用个人计划的 GLM-5.3-Flash 继续；这是该次实际选择，**不是以后个人计划的首选模型**，也不能证明所有免费额度都已用完。总控随后修正了 B-10 的 PostgreSQL 测试注入和 B-15 的旧 DOM 授权边界。该轮记录载明后端 PostgreSQL 全量 839 通过、前端 123 通过，并完成 Ruff、类型检查、生产构建；具体证据见[B-07 至 B-15 修复验收](archive/验收记录/B07-B15修复验收-20261003.md)。这些数字仅代表当时快照，每轮都要重新运行。企业筛选和双投递竞态的生产页面验收仍应按最新清单核对。

这轮操控 ZCode 的经验可直接复用：

1. **先看组别，再看模型名和余额。** 同名 Flash 可以出现在不同额度条目中；一条失败或显示 0%，不能推断其他条目也没有余额。
2. **新任务必须带上当前现场。** 开始时先核对嵌套仓库的 `git status`、HEAD、原任务已改文件；额度切换时明确“继续已有改动”，避免重复实现或覆盖。
3. **把简单修复与复杂边界拆开。** ZCode 适合处理局部、可测试的修改；总控仍需检查真实授权、旧页面节点、数据库故障注入和生产页面行为。本轮 B-10/B-15 的后续修正说明自动测试结果不能替代这一步。
4. **只报告实际覆盖范围。** 合成学生页面通过不等于企业筛选或双投递竞态已验；真实 AI 语义也不能由代码测试代签。

2026-10-04 的 B-08 是额度切换实例：先在 **Start Plan 免费 GLM-5.3** 任务留下红灯测试和部分实现；该模型返回额度用完后，另开 **Start Plan 免费 GLM-5.3-Flash** 任务，只读核对已有 diff 再续做，个人计划未使用。ZCode 完成迁移、两库专项、全量回归、证据包与自审，Codex 补强无效 token 判定和取消入账测试，见 [B-08 总控复核](evidence/20261004-B08-implementation/codex-audit.md)。这轮也暴露了迁移验证的操作风险：运行 Alembic 前必须先核对项目实际读取的环境变量名和目标数据库；首次误用变量名使迁移落到本机 compose 库，已如实记录。数据库专项须使用夹具创建的隔离 schema，不用默认业务库做故障注入。

出现问题时按以下规则恢复：

| 情况 | 处理 |
| --- | --- |
| 模型菜单组别不清或调用提示额度不足 | 核对 BigModel 个人套餐、五小时/周余额与实际调用结果；保存成果，达到限额时等待恢复，不默认切免费组 |
| ZCode 宣称完成却无目标 diff，或只给测试结论 | 以 Git diff 和本地实跑为准；把缺口写回同一任务或新任务 |
| 两个客户端改到同一文件或测试数据相互污染 | 停止并行写入，保留所有改动；先查看状态和差异，再由总控整合，不做破坏性清理 |
| 测试绿了但页面/授权边界仍错 | 补能复现真实行为的测试，修正后重跑相关检查和页面路径 |
| 推送、外发或付费调用受到授权/自动审批阻挡 | 保存本地可审查成果，说明具体被挡动作及原因；取得针对该动作的明确许可后再执行，不换通道绕过 |

每次只让一个小项实际写入共享工作区；完成并验收后，同一个人计划任务可接着处理队列中的下一项。由总控根据实测结果调整队列，比让许多任务窗口同时写入更容易保证固定快照、授权边界和 AI 解释质量。

## 四、不可下放的护栏与文件所有权

Codex 保留授权/撤回、并发事务、固定投递快照、用量入账、AI 事实归因与对外发送的最终裁决；这些路径的最终 diff 必须全文审查，最高风险断言仍须独立复跑。ZCode 完成首轮测试、页面操作或自审，不能代替这一签字。真实模型调用、真实材料外发、向人发送消息及远端推送分别需要任务范围内的明确授权；模型套餐余额不构成这些授权。若测试证据不完整、边界冲突或页面与接口结果矛盾，先停止后续队列并扩大核验。

| 文件或资源 | 默认写入者 | 另一方可做什么 |
| --- | --- | --- |
| 本项源码、回归测试、隔离测试数据 | ZCode，按任务卡顺序独占 | Codex 只读审查；如需补边界，先等 ZCode 交棒 |
| `docs/evidence/YYYYMMDD-任务号/` 新目录及验收草稿 | ZCode | Codex 审计、签字和必要更正 |
| 正式 Bug 清单、接力清单、优先级与任务卡 | Codex | ZCode 提供有定位证据的更新建议 |
| 当前手册、固定约束和模板 | Codex | ZCode 可指出过期或执行困难之处 |
| 共享 PostgreSQL 夹具、Next 构建目录、Git 索引和 stash | 当前执行者临时独占 | 另一方等候或只读；涉及破坏性操作先由 Codex 裁决 |

## 五、用结果衡量节省的成本

每个证据包记录 ZCode 实际跑过的检查、首轮审查发现、页面首验覆盖和未验证项；Codex 只在终审写所复跑的断言、扩大审查的触发原因及最终结论。阶段回顾时比较 Codex 阅读的 diff 行数、重复跑测试次数、从零撰写的文档量，以及返工、漏检和边界缺陷数。目标是让重复搬运下降，同时保持关键断言双跑、页面可复现和边界裁决，不以消耗额度或减少抽检次数本身作为成果。
