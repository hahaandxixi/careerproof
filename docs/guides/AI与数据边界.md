## 配置边界

产品外部生成使用 DeepSeek 官方 API；开发协作的 ZCode / DeepSeek Harness 见[协作规则](../协作规则.md)。历史适配器和旧供应商配置不作为产品操作入口。

外部调用配置示例，仅在本机被忽略的 `backend/.env` 填写，不能把真实 Key 写入文档：

```env
AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=true
DEEPSEEK_API_KEY=只在本机填写
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_TIMEOUT_SECONDS=90
DEEPSEEK_MAX_ATTEMPTS=2
```

适配器限定官方地址与受支持型号，文字生成使用当前受控请求配置。普通启动会核验产品配置；隔离合成验收由 Start-E2E 选择 Mock 并关闭外发，不能靠修改普通环境冒充真实模型成功。具体环境选择见[启动指南](使用与启动.md)。

产品可调用外部模型，不等于用户已授权每次外发。学生生成匹配/补证报告时可以不勾选外部发送同意，仍可生成规则报告；外部生成需同时通过配置、授权、材料/角色检查与预算闸门。图片观察另行确认原图像素外发，文字脱敏不能保护图片像素。没有调用、调用失败、复用和降级必须分别标记。

只读配置检查：在 `backend` 下，用启动核验通过的 Python 执行 `-m app.scripts.check_deepseek`，不加 `--live`。真实连通/质量评测须另定具体合成输入、请求数与费用范围；开发客户端权限不替代产品外发授权。

## 预算与用量

以下是 `app/core/config.py` 的代码默认值，不是本机余额或保证可调用次数；实际配置与账目以当前运行环境为准。

| 配置 | 默认值 |
| --- | ---: |
| `AI_PER_REPORT_INPUT_TOKEN_LIMIT` | 12,000 保守预检单位 |
| `AI_PER_REPORT_OUTPUT_TOKEN_LIMIT` | 4,000 Tokens |
| `AI_DAILY_REPORT_LIMIT` | 20 |
| `AI_DAILY_INPUT_TOKEN_LIMIT` | 200,000 Tokens |
| `AI_DAILY_OUTPUT_TOKEN_LIMIT` | 40,000 Tokens |

保守输入预检不是供应商精确 Token 统计。规划、分析、修正与物理重试需要按所属链的实际账目计量；模型已经产生用量后，输出不合法或报告保存失败不能据此抹去用量。可信收据与账目、在途预留、未知结果分别显示；没有可信收据不能把 unknown 计为零。核验与主匹配的持久账目/共用预算签收见任务清单，不能推及所有其他 AI 链。

有可用缓存时按本人、岗位快照、材料版本、提示与规则版本复用；无证据、未授权、限额或模型失败时按该链规则降级。预留最终分析输入、有限补检索和一次定向修正也受硬限额约束。API 定价与账户套餐会变化，不从历史余额、请求数或缓存输入倒推当前费用。

## 数据、授权与快照

系统保存账号、材料原文件/解析片段/版本/哈希、岗位、任务、报告、站内事件和复核记录。原文件在配置的存储目录，结构化数据在数据库；本地 OCR 与语义检索在本机处理，不执行上传代码。

外部文字请求只发送所需岗位要求、规则判据、声明与必要证据上下文；不主动加入账号身份字段或完整材料。常见联系方式、带标签姓名、凭据赋值、Token 和私钥形状会过滤，但不能保证识别全部隐私。发送副本脱敏，本地来源与哈希保持原样。学生须只选择必要材料，演示只使用合成数据。

- 学生只能读本人材料、任务与报告。企业无自动读取学生库权限。
- 确认投递仅向岗位所属企业授权当次固定报告、引用与该次简历下载；新版报告不会覆盖旧投递。
- 撤回后企业查看、下载、回复与旧通知目标拒绝；已下载副本无法追回。重新投递形成新的授权记录，旧回复保留在旧记录。
- 查看/下载是平台事件，不能解释为已充分阅读、通过筛选或录用。站内回复不等于邮件发送。
- 材料归档可恢复，不等于永久删除或撤回投递。人工核对不改原文、不自动提级。

## 尚未完成的上线要求

10/15安全头已同时由前端与API返回层提供：DENY、nosniff与strict-origin-when-cross-origin；本机生产构建仍走HTTP，不默认启用HSTS。仅实际HTTPS生产部署显式设置前端`CAREERPROOF_HTTPS=true`时输出HSTS，不能把设置此标志当作已配置TLS。

认证风险仍开放：专属PG两独立会话已复现同一refresh并发签出两条有效后继，修复须覆盖原子轮换、跨标签和网络重试恢复；尚未实现持久登录失败限流或完整重放链识别。不得给演示邮箱永久豁免，不信任任意转发IP，不因竞争失败直接撤销用户全部会话。退出撤销refresh，但已签发access仍可能在配置有效期内使用；默认30分钟，不能声称即时撤销全部访问凭证。

用户自助永久删除/保存期限、完整导出、存储与备份保护、管理员最小权限以及供应商数据处理政策仍需上线前逐项核对；不能用局部权限测试宣称全面隐私合规。真实材料公开部署与外发需对应授权。密钥、Cookie、凭据、真实简历和运行临时目录不得入库。
