# 使用与启动

更新：2026-10-12。本文是当前用户操作入口；开发状态见[当前接力](../当前接力.md)，AI/预算/隐私见[AI与数据边界](AI与数据边界.md)。旧版本日志不作为当前使用说明。

## 先找到登录账号

**本机凭据文件：[打开演示账号与密码](../../backend/.tmp/demo-credentials.json)。** 文件不进入 Git；换机器或评审打包后，这个链接可能不存在。

| 文件字段 | 用途 |
| --- | --- |
| `studentEmail` | 学生登录邮箱 |
| `enterpriseEmail` | 企业登录邮箱 |
| `password` | 两个演示账号共用的本机密码 |

登录地址：<http://127.0.0.1:3000/login>。复制对应邮箱和 `password` 的值，**不要复制 JSON 引号**。2026-10-12 已只读核对：两账号存在且有效，凭据密码匹配数据库；不在文档中复制实际密码。

`Start-Local.ps1` 只启动服务，不创建演示账号。首次演示请用 `Start-Demo.cmd` 或 `Start-Demo.ps1` 初始化账号和合成样例。如果文件不存在，先确认演示初始化成功。环境变量 `DEMO_STUDENT_EMAIL`、`DEMO_ENTERPRISE_EMAIL`、`DEMO_PASSWORD` 同时设置时优先于文件；不要混用两套凭据。

### 凭据检查与更换边界

修改 JSON 不会重置数据库已有账号的密码，也不会撤销旧会话。登录失败先确认使用 3000 的日常环境，而非 3001 的隔离测试账号；再核对文件或显式配置，不要反复重播种或修改密码猜测。需要换凭据时使用明确的新合成身份，保留原数据。网页 `/demo` 提供查找路径，不公开密码。可离线检查文件格式：

```powershell
Set-Location backend
.\.venv-dependency23\Scripts\python.exe -m evals.demo_credentials
```

## 三个启动入口

先双击桌面的 Docker Desktop，等待引擎就绪。在 `D:\jbcode\web ai\jianli` 操作：

| 入口 | 用途 | 端口与数据 |
| --- | --- | --- |
| `Start-Local.ps1` | 日常本地使用 | 3000/8000，普通数据库；不初始化演示账号 |
| `Start-Demo.cmd` / `Start-Demo.ps1` | 比赛/课堂演示 | 复用 Local，同端口；另外初始化合成账号、岗位和材料 |
| `scripts/Start-E2E.ps1` | 开发隔离验收 | 3001/8001，专属 `cp_e2e_*` 数据库、存储与构建；强制合成模型 |

Local 和 Demo 不要并行抢占同一端口。E2E 可与日常环境并存，但账号和材料不互通；按任务卡指定 RunId，不复制旧 run 重新播种。

```powershell
# 只读预检
.\Start-Local.ps1 -CheckOnly
# 日常启动
.\Start-Local.ps1
# 需要演示初始化时运行
.\Start-Demo.ps1 -NoBrowser
# 强制重建 / 只构建不启动
.\Start-Local.ps1 -Rebuild
.\Start-Local.ps1 -BuildOnly
# 默认只停网站，保留数据库容器与数据卷
.\Stop-Local.ps1
```

启动脚本自动选择合格的已安装依赖环境，显示实际路径；不自动安装或改 `.env`。未变的源码复用生产构建；改动后重建。启动会检查数据库迁移并更新 schema。重复启动只复用身份、代码与配置都一致的自有服务。

当前可用依赖示例为 `.venv-dependency23` 与 `dep-frontend-20261010`，以预检输出为准。可显式指定：

```powershell
.\Start-Local.ps1 -BackendVenv .venv-dependency23 -FrontendStage dep-frontend-20261010 -CheckOnly
```

停止演示可双击 `Stop-Demo.cmd`。确认没有其他验收服务使用数据库后，才使用 `Stop-Local.ps1 -Database` 停止数据库容器；数据卷保留。

## 首次安装与当前模型配置

安装依赖按[后端说明](../../backend/README.md)和[前端说明](../../jianli/README.md)执行，版本以当前锁文件/生产 pin 为准，旧手册版本号不作为安装依据。

网站外部生成只配置 **DeepSeek 官方 API**，文字与图片观察共用本机 Key；模型名以当前 `backend/.env` 为准。配置字段如下，示例不是实际密钥：

```dotenv
AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=true
DEEPSEEK_API_KEY=填入本机Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

启动和登录不调用模型。主动发起分析、职业规划或视觉观察可能产生费用，各自按页面同意及预算执行；模型失败会明确保存被动兜底结果。隔离合成验收不消耗真实 API 额度。本地 OCR/ONNX 检索不属于外部生成。ZCode 开发模型额度与网站 DeepSeek 额度分开。

## 学生使用顺序

1. 用 `studentEmail` 登录。打开 `/demo`，选一套同编号简历和项目材料；不要混选不同职业编号。
2. 在“我的材料”上传简历和项目 ZIP，等待解析完成。源码、文档与图片按各自边界展示，不执行上传代码。
3. 从“岗位发现”选择岗位，或从“职业推荐”查看方向建议；选择本次材料版本。
4. 阅读 AI 发送范围、确认后主动发起分析。在任务页等待结果，遇到断线按页面轮询/重试提示处理，不反复创建分析。
5. 打开“我的匹配报告”，核对逐项状态、引用原文、缺口、模型降级与人工复核说明。
6. 从下方补证工作台进入一条缺口，上传新版、保存材料选择，再生成新报告并比较。
7. 如需投递，单独阅读报告页的分享范围并确认授权。新版材料不会自动替换原投递快照。

## 企业使用顺序

1. 用 `enterpriseEmail` 登录，在“发布岗位”创建或选择自己的企业组织。
2. 填写岗位信息和逐条要求，核对 AI 提取的草稿后再发布。发布岗位不会获得学生私有报告访问权。
3. 从自己的岗位进入已授权投递列表，比较对应岗位要求和固定报告来源；不按能力总分排名。
4. 查看或下载授权范围内的材料，必要时从要求出发提问/回复。发送是主动操作，不由 AI 建议自动完成。
5. 学生撤回后，平台报告和旧通知访问按授权检查失效；已下载副本无法追回。学生私人草稿与补证报告不自动共享给企业。

## 缺口补证工作台使用说明（2026-10-12）

### 从哪里进入

以学生账号登录，从顶部“我的匹配报告”打开一份自己的报告，在报告摘要下找到“我的缺口补证工作台”。沿用原站靛蓝、白色卡片与原导航，不新增独立账号或另一套报告。企业端仍按授权查看固定投递快照，不显示学生私人工作台。

`http://127.0.0.1:8124/evidence-workspace.html` 是设计原型，按钮不保存或发送。真正使用应进入已启动网站的 `/reports/<报告ID>`：普通本地通常为 3000 端口，独立合成验收为 3001。端口与服务是否在线以当前启动输出为准。

### 一条缺口的操作顺序

1. **看当前状态。** “有证据支持”“部分支持”“待补材料”“未覆盖或需复核”统计本报告已保存的要求状态，不是能力分数或录用结论。已驳回/修正、规则未覆盖与未知状态单列，不算有证据支持。
2. **核对来源。** “优先补齐的证据”按岗位权重降序展示最多 3 项，权重相同时保留报告顺序。点击“核对来源与逐项解释”，查看对应要求、引用原文和信息缺口；其余要求仍在下方“逐项证据”。
3. **打开补证任务。** 点击“从这条缺口开始补证”定位到同一要求的补证入口并展开。系统读取已有任务；已有任务时点击“打开这条缺口已有补证任务”，沿用固定基准，不重复创建。没有任务时，填写缺口类型、具体交付物、执行步骤和核验条件，再点击“保存并进入补证”。点击工作台链接本身不会保存任务。
4. **核对 AI 草稿。** 如果当前报告有合格的 AI 建议，可以补入空白项，再自己修改。已有手写内容不会被替换。没有合格建议、建议过期或任务草稿被警告时，手动填写即可；程序校验不代表人工认可。
5. **补证并上传新版。** 按任务约定准备实现、运行记录或本人贡献说明，使用任务中的上传/材料入口新增版本。回到任务，选择新版简历与项目，再点击“保存本次材料选择”。单纯上传或改选不会自动改变已保存的分析材料；改选目标岗位也需要重新保存。
6. **主动生成并等待新报告。** 在任务中按页面提示发起分析、确认发送范围，等待处理完成。首次打开工作台、查任务和查历史对比都不会触发模型；主动分析是否调用真实模型取决于运行配置、发送同意及预算。失败时以任务页错误与重试提示为准。
7. **逐项核对变化。** 任务完成后查看新报告及任务中的基准对比；报告页“查看版本变化”定位到“证据变化与补证进度”，再点“与上一份报告对比”读取已有结果。这个报告页对比对象是同岗位最近一份更早报告，未必等于某任务的固定基准；要核对任务本身的闭环，请使用任务中的对比。

### 数据边界与常见疑问

| 情况 | 应如何理解或处理 |
| --- | --- |
| 上传新版后报告没变 | 旧报告固定；保存新版材料选择后主动生成新报告 |
| 显示有证据支持 | 表示当前材料状态，不证明运行成功、测试质量或独立贡献 |
| 工作台没有优先缺口 | 不等于全部能力已认证；继续核对未覆盖/需复核项和来源 |
| 已有补证任务 | 打开原任务；需要新一轮补证时从新报告开始 |
| 读取任务失败 | 在对应入口重试读取，不反复点击创建或重复提交 |
| 没有更早报告 | 报告页不能展示历史差异；先完成一次补证并生成新报告 |
| 企业是否会收到新版 | 不会自动收到。原投递快照保持固定；任何新的分享或回复仍需主动操作 |
| 是否覆盖原简历 | 新增材料版本；旧报告引用的版本与原投递快照不被工作台替换 |

投递授权说明、撤回限制、第三方参考与模型降级提示继续保留。投递操作必须另行确认授权；已下载副本不能通过平台撤回追回。工作台不自动发站内回复、邮件或创建投递。

### 当前验收与下一轮优化

2026-10-11 已完成：前端 213 项自动测试、类型检查、升级依赖目录生产构建；隔离合成运行真实报告页显示工作台，状态 0/0/1/0 与原报告一致并留截图。排序测试曾发现同权重顺序问题，已改为保留原报告顺序。原型的 390px 配色检查不能替代这个新增实际组件的手机验收。

本页更新时 3001/8001 未监听。新组件的 320/390px 实际页面、点击后展开/键盘焦点、账号切换仍需服务恢复后补验；未把这些写成已通过。本批未新建任务、上传材料、生成报告或发送消息，也未调用真实 DeepSeek。已有全链路证据只能说明旧链路曾通过，不能替代本次新入口的全部验收。

优先优化顺序：① 补齐实际手机与键盘验收；② 合并工作台与“下一步补证计划”的重复入口，保留完整 AI 行动建议与引用；③ 明确区分“任务固定基准对比”和“上一报告对比”，避免用户比较错对象。继续沿用原站配色，不引入第二套主题设置。生产页面验收与来源证据保留在 `docs/evidence/20261011-design-color-comparison/`。

## 常见启动与登录问题

| 现象 | 处理 |
| --- | --- |
| Docker Engine is unavailable | 双击 Docker Desktop，等引擎就绪后重新执行启动；失败脚本不会自动续跑 |
| 找不到账号 | 打开本页顶部凭据链接；首次使用需 Demo 初始化，Local 不创建账号 |
| 密码不对 | 核对端口、邮箱字段及环境变量来源；修改 JSON 不是重置密码 |
| 页面看不到新功能 | 确认源码已同步到实际 frontend stage，并重新构建；旧服务需按身份停止后启动 |
| 端口被占用 | 按自有运行记录停止原服务，不按端口任意结束进程 |
| 已上传新版但报告没变 | 报告固定；保存新版选择后主动分析生成新报告 |
| AI 超时或限额 | 查看任务记录和降级标记，不把规则兜底误当真实 AI 成功 |

本机始终使用 `127.0.0.1`，不要与 `localhost` 混用会话。日常日志和进程清单位于 `backend/.tmp/local-run/`；凭据、API Key、真实简历与上传目录不提交 Git。
