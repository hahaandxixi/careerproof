# CareerProof 使用与启动

更新：2026-10-19。本页从日常启动开始，适合第一次体验学生端和企业端。按步骤讲解网站另见[功能演示](功能演示.md)；开发进度与未验范围见任务清单（开发仓库内部记录，未随评审包分发）。

## 启动网站

**日常只记住两个文件：`Start-Local.cmd` 启动，`Stop-Local.cmd` 停止。**

1. 双击桌面的 **Docker Desktop**，等待引擎启动完成。仅看到窗口打开，不一定代表引擎已就绪。
2. 打开项目根目录（源码ZIP解压后包含 `Start-Local.cmd` 的项目根目录），双击 **`Start-Local.cmd`**。等待检查完成；需要构建时会多等一会，不要连续打开多个启动窗口。
3. 出现 `CareerProof is ready at http://127.0.0.1:3000` 后，在浏览器打开 **[网站首页](http://127.0.0.1:3000)**。普通启动不会自动打开浏览器。

启动成功后应能看到首页；登录入口是 [3000/login](http://127.0.0.1:3000/login)。重复启动会检查并复用同一套健康服务，再次显示网址、环境和账号入口。失败时按窗口中的错误处理，见[常见问题](#常见问题)，不要先删除账号或重建数据库。

新电脑首次安装需要先准备依赖和本地配置，见[首次安装与高级操作](#首次安装与高级操作)。启动脚本不会自动安装依赖或填写 API Key。

### 先选日常使用还是首次准备演示

| 你现在要做什么 | 选择哪个入口 | 会做什么 |
| --- | --- | --- |
| 继续昨天的操作、登录已有账号 | **`Start-Local.cmd`** | 启动网站，保留账号、材料、报告和投递；不创建账号 |
| 首次准备合成演示账号、岗位和材料 | `Start-Demo.cmd` | 复用同一正常网站，再初始化合成演示数据并打开演示页 |
| 只想先看热力图效果 | 普通启动后打开[热力图示例](http://127.0.0.1:3000/demo/heatmap) | 无需登录；不生成报告、不调用模型、不创建真实投递 |

**已有演示数据就用 Local 继续操作。** 登录失败或恢复网站，不需要重新初始化演示，更不要使用 `-Reseed` 猜测修复。

## 先找到登录账号

日常统一使用 **`http://127.0.0.1:3000`**，不要和 `localhost` 或旧测试地址混用。

**想立刻拿测试账号**：在项目根目录执行下面一行，直接打印本机演示账号（学生、企业两个 `@example.com` 邮箱共用一个密码）：

```powershell
Get-Content backend\.tmp\demo-credentials.json
```

这两个是**合成演示账号**，只存在于本机、不进 Git，也不等于真实注册用户清单。文件不存在时先运行一次 `Start-Demo.cmd`。

| 账号来源 | 邮箱和密码在哪里 |
| --- | --- |
| 自己注册 | 使用注册时自行设置的邮箱和密码；演示凭据文件不会记录你的账号 |
| 本机演示学生 | 本机 `backend/.tmp/demo-credentials.json`（首次演示初始化生成，不随包分发）中的 `studentEmail` 和 `password` |
| 本机演示企业 | 同一文件中的 `enterpriseEmail` 和 `password` |

复制 JSON 字段的**值**，不要带两边引号。凭据文件只在本机保存，不进入 Git，也不保证换机器后存在。启动提示里的文件路径仅帮助查找，不代表已验证账号可登录。

文件不存在且需要首次演示时，运行 `Start-Demo.cmd`，等待初始化成功；已有自己的账号则直接登录，或到[注册页](http://127.0.0.1:3000/register)注册。修改凭据文件**不会重置数据库里的密码**，也不会撤销已有会话。若开发者显式设置了 `DEMO_STUDENT_EMAIL`、`DEMO_ENTERPRISE_EMAIL`、`DEMO_PASSWORD`，三项必须成套使用，不能与文件混搭。

**昨天在3001注册的账号，要回原3001测试环境查看。** 3000与3001的数据库不同，账号、投递、通知不互通；普通启动不会启动3001。需要恢复旧测试运行时，请保留原运行编号，按文末隔离验收说明处理，不重新注册或播种来“找回”记录。

## 学生：先走通这五步

### 1. 登录并选择一套合成材料

以学生身份登录，在 **岗位发现** 选择 Python 后端、React 前端或接口测试开发这三套精选体验岗位之一。卡片标有“体验样例 · 虚构企业”，不是真实招聘。

在岗位详情的 **“用这套材料体验匹配”** 下载对应虚构简历TXT和项目ZIP，再从顶部 **学生账户 → 个人材料** 分别上传。ZIP无需解压或执行；不要把不同场景的简历和项目混用。旧的 CP 编号材料仍在演示页保留，适合复看历史报告，不再作为首次体验的默认路线。

### 2. 回到该岗位，选择材料版本

等待材料解析完成后，回到刚才的岗位详情。在“用我的材料分析岗位匹配”中，选中这套场景刚上传的简历与项目版本。

若没有精选体验岗位，需先通过 `Start-Demo.cmd` 准备演示数据；普通 `Start-Local.cmd` 只恢复网站，不自动创建或隐藏岗位。旧测试岗位从发现页收起后，原报告、投递和岗位ID仍保留；不会通过关闭岗位切断原有补证链。热力图预览不是可投递岗位。

岗位页若提示已有投递，可先查看记录；状态读取失败可重试，不妨碍选择材料或生成报告。生成新报告不会替换原投递。

### 3. 生成报告

先体验本站规则报告：**不勾选外部AI同意**，点击 **“生成我的匹配报告”**，等待任务完成。此路径不把材料发送给外部模型，也可以继续查看证据和明确投递。

需要AI解释时，先阅读页面中的发送范围与费用说明，再明确同意并生成。任务页会显示真实处理阶段；完成后按页面入口打开报告。未调用模型、模型降级和真实AI参与是不同状态，以这次任务记录为准。

### 4. 看结论，需要时再展开证据

先看报告摘要与待补材料，再选择一项要求查看解释、来源文件和行号。来源片段与“本人核对记录（可选）”按需展开。

本人核对不是投递前置条件，不需要为每条证据填写意见。材料支持度不等于能力、运行成功或录用结论；不必补齐所有证据才能投递。

### 5. 明确投递，查看结果

在报告页找到投递确认区：**阅读分享范围 → 勾选同意 → 确认投递**。生成报告不会自动投递。

完成后从 **学生账户 → 个人投递** 查看记录，从 **学生账户 → 通知** 查看企业回应。企业看到的是这次投递固定的报告快照，不会自动看到你后续生成的新报告。

首次体验的完成信号是：材料已解析、报告可打开、至少一处来源能定位、个人投递中能找到刚确认的记录。这里是操作指引，不表示首次独立用户验收已通过。

## 企业：查看学生的这份投递

1. 退出学生账号，使用**同一环境、目标岗位所属企业**的账号登录。演示企业邮箱取自上面的凭据文件。
2. 进入 **我的岗位**，选择该岗位，再进入已授权投递与匹配对照列表。
3. 选择候选人，从岗位要求查看固定报告、联动证据与授权材料；按需要展开详情。
4. 在投递详情填写并发送站内回复。学生回到自己的账户，在“通知”中定位对应投递并查看正文。

学生账号不能进入企业页面；新注册的任意企业账号也不能查看其他企业的岗位投递。若企业列表为空，先确认学生确实向**这个岗位**确认投递，且尚未撤回。

学生与企业同时展示时，使用两个浏览器或独立浏览器配置。普通标签页共用登录会话，3000/3001端口也不能隔离Cookie；在同一浏览器切换角色时，先退出再登录。

## 补证、生成新版与撤回

**补一条缺口：** 打开学生自己的报告 → 选择待补要求 → 从该缺口进入或创建补证任务 → 准备材料并上传到原项目的新版本 → 回任务选择版本并“保存本次材料选择” → 主动分析生成新报告 → 查看逐项变化。原简历可继续使用，旧报告与原投递快照不会被替换。详细按钮与演示步骤见[功能演示](功能演示.md)。

工作台的分组数量与列表来自报告要求；有建议时附带建议，没有建议时仍可查看缺口和来源。点击补证入口本身不保存任务；有已有任务时优先打开原任务，不重复创建。AI草稿可选，已有手写内容不应被替换。

注意两种对比：**补证任务以任务固定基准为起点**；报告页“与上一份报告对比”使用同岗位最近一份更早报告，二者不一定相同。没有更早报告时不能展示历史差异。

**撤回授权：** 从个人投递中按页面提示撤回。撤回后旧授权不能再查看报告；已下载副本无法追回。需要重新分享时，回到相应完整报告页重新阅读范围、明确授权投递，不是恢复旧链接。新版材料、补证任务和私人草稿不会自动分享给企业。

## 停止网站与下次继续

- 双击 **`Stop-Local.cmd`**，停止这套入口记录的网站进程；默认保留数据库运行和所有已保存数据。`Stop-Demo.cmd`调用相同停止逻辑，日常不必另记。
- 下次先确认Docker已就绪，再双击 **`Start-Local.cmd`**，打开3000并登录原账号即可。不要为恢复而重新导入材料或初始化演示。

确实不再有其他服务使用数据库时，可在项目目录运行 `Stop-Local.ps1 -Database` 停止数据库容器，数据卷仍保留。不要删除数据卷、材料目录或进程记录来代替正常停止。

## 常见问题

| 现象 | 先这样处理 |
| --- | --- |
| `Docker Engine is unavailable` | 双击Docker Desktop，等引擎就绪后重新启动网站；原失败脚本不会自动续跑 |
| 仍打开3106验证页或8124原型页 | 回到[3000首页](http://127.0.0.1:3000)。临时验证页不是日常网站，也不用于保存正式操作 |
| 邮箱或密码错误、昨天的记录找不到 | 先确认昨天使用3000还是3001，再核对账号来源；不要改凭据JSON或重播种来重置密码 |
| 登录尝试过于频繁 | 按页面提示的秒数等待再试；校园网可能共享来源额度，不要连续点击登录 |
| 提示依赖或源码不匹配 | 保留错误中的路径和原因，按前后端安装说明检查；启动器不会自动安装或降级依赖 |
| 端口被占用、旧进程身份不明 | 保留运行记录与日志，核对所属服务；不要仅按端口结束进程或删除记录 |
| 看不到新功能 | 确认实际运行的源码副本与构建已更新，再正常停止、启动；只刷新旧构建不会加载新源码 |
| 上传超时，不确定是否成功 | 先保留页面与上传任务，按页面重试或查看解析结果，不反复新建项目或上传副本 |
| 扫描PDF提示页面像素过大（4026） | 缩放到常规纸张尺寸或换可提取文字的PDF；此限制按OCR渲染单页像素计算，独立于10MB文件上限，压缩文件或拆页未必解决 |
| 新版已上传，但报告没变 | 回补证任务保存新版选择，再主动生成新报告；已有报告固定不变 |
| AI超时或限额 | 查看任务状态和降级标记；规则兜底不代表真实AI成功 |
| 企业找不到投递 | 核对同一环境、岗位所属企业、学生是否确认投递及是否撤回；列表有分页，企业筛选只针对当前页 |

个人投递、企业候选人、报告、补证任务每页默认20条；通知可选20或50条。补证页提示部分记录暂时无法读取时可重试，计入总数不代表记录被删除。

日志与运行记录在 `backend/.tmp/local-run/`。反馈问题时提供页面地址、操作步骤和错误提示即可；不要发送API Key、密码、完整数据库连接串或真实简历。

## 首次安装与高级操作

这部分用于新机器安装或开发排障；已有可用网站时无需逐条执行。

### 安装与模型配置

按[后端说明](../../backend/README.md)和[前端说明](../../jianli/README.md)安装依赖，以当前锁文件为准，在本机准备 `backend/.env`。当前正常启动要求配置DeepSeek官方API，示例不是密钥：

```dotenv
AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=true
DEEPSEEK_API_KEY=填入本机Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

配置存在不代表外部模型已连通。启动、登录、导入合成材料不调用模型；主动分析、职业规划或视觉观察是否外发、收费，以各自的同意与预算提示为准。未同意匹配外发仍可生成本地规则报告。开发客户端额度与网站API费用分开。

### 命令行检查、构建与停止

从项目根目录运行；日常直接双击CMD即可，CMD只是调用对应PS1脚本：

```powershell
.\Start-Local.ps1 -CheckOnly  # 只核验依赖与源码；不检查Docker或模型连通性
.\Start-Local.ps1             # 启动或复用健康服务
.\Start-Local.ps1 -Rebuild    # 强制重建后启动；已有运行需先正常停止
.\Start-Local.ps1 -BuildOnly  # 只准备构建，不启动Docker、迁移或服务
.\Stop-Local.ps1              # 停网站，保留数据库运行
.\Stop-Local.ps1 -Database    # 停网站及数据库容器，保留数据卷
```

启动自动选择已安装且版本、源码匹配的环境，输出实际路径；无需记住某个带日期的临时依赖目录。需要手动指定时，`-BackendVenv`接收backend下的环境目录名，`-FrontendStage`接收backend/.tmp下的目录名，以本次预检为准。首次启动会执行数据库迁移；依赖和源码未变时复用已有生产构建。`-CheckOnly`不是“网站与数据已可用”的完整验收。

### 隔离验收与旧3001账号

`scripts/Start-E2E.ps1`、`scripts/Stop-E2E.ps1`供开发验收，使用3001/8001、专属`cp_e2e_<RunId>`数据库与独立存储，强制合成模型；不与日常库合并。启动需要明确RunId及`-SyntheticVerification`，连接限定本机5432；已有运行按原编号恢复，不复制旧编号重新播种。完整准备与恢复见[功能演示的开发者说明](功能演示.md)。

隔离企业账号在 `backend/.tmp/e2e/<RunId>.json` 的 `accounts.enterprise` 中；HTTP演示学生凭据在 `backend/.tmp/release-smoke/<RunId>.credentials.json`。自行注册账号仍使用自行设置的密码。保留这些本机文件，勿发到仓库或公开视频。
