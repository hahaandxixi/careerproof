## 缺口补证工作台使用说明（2026-10-12）

### 从哪里进入

以学生账号登录，从顶部“我的匹配报告”打开一份自己的报告，在报告摘要下找到“我的缺口补证工作台”。沿用原站靛蓝、白色卡片与原导航，不新增独立账号或另一套报告。企业端仍按授权查看固定投递快照，不显示学生私人工作台。

`http://127.0.0.1:8124/evidence-workspace.html` 是设计原型，按钮不保存或发送。真正使用应进入已启动网站的 `/reports/<报告ID>`：普通本地通常为 3000 端口，独立合成验收为 3001。端口与服务是否在线以当前启动输出为准。

### 一条缺口的操作顺序

1. **看当前状态。** “有证据支持”“部分支持”“待补材料”“未覆盖或需复核”统计本报告已保存的要求状态，不是能力分数或录用结论。已驳回/修正、规则未覆盖与未知状态单列，不算有证据支持。
2. **核对来源。** “优先补齐的证据”按岗位权重降序展示最多 3 项，权重相同时保留报告顺序。点击“核对来源与逐项解释”，查看对应要求、引用原文和信息缺口；其余要求仍在下方“逐项证据”。
3. **打开补证任务。** 点击“从这条缺口开始补证”定位到同一要求的补证入口并展开。系统读取已有任务；已有任务时点击“打开这条缺口已有补证任务”，沿用固定基准，不重复创建。没有任务时，填写缺口类型、具体交付物、执行步骤和核验条件，再点击“保存并进入补证”。点击工作台链接本身不会保存任务。
4. **核对 AI 草稿。** 如果当前报告有合格的 AI 建议，可以补入空白项，再自己修改。已有手写内容不会被替换。没有合格建议、建议过期或任务草稿被警告时，手动填写即可；程序校验不代表人工认可。
5. **补证并上传新版。** 按任务约定准备实现、运行记录或本人贡献说明，使用任务中的上传/材料入口新增版本。回到任务，选择新版简历与项目，再点击“保存本次材料选择”。单纯上传或改选不会自动改变已保存的分析材料；改选目标岗位也需要重新保存。
6. **主动生成并等待新报告。** 在任务中按页面提示发起分析、确认发送范围，等待处理完成。首次打开工作台、查任务和查历史对比都不会触发模型；主动分析是否调用真实模型取决于运行配置、发送同意及预算。失败时以任务页错误与重试提示为准。
7. **逐项核对变化。** 任务完成后查看新报告及任务中的基准对比；报告页“查看版本变化”定位到“证据变化与补证进度”，再点“与上一份报告对比”读取已有结果。这个报告页对比对象是同岗位最近一份更早报告，未必等于某任务的固定基准；要核对任务本身的闭环，请使用任务中的对比。

### 数据边界与常见疑问

| 情况 | 应如何理解或处理 |
| --- | --- |
| 上传新版后报告没变 | 旧报告固定；保存新版材料选择后主动生成新报告 |
| 显示有证据支持 | 表示当前材料状态，不证明运行成功、测试质量或独立贡献 |
| 工作台没有优先缺口 | 不等于全部能力已认证；继续核对未覆盖/需复核项和来源 |
| 已有补证任务 | 打开原任务；需要新一轮补证时从新报告开始 |
| 读取任务失败 | 在对应入口重试读取，不反复点击创建或重复提交 |
| 没有更早报告 | 报告页不能展示历史差异；先完成一次补证并生成新报告 |
| 企业是否会收到新版 | 不会自动收到。原投递快照保持固定；任何新的分享或回复仍需主动操作 |
| 是否覆盖原简历 | 新增材料版本；旧报告引用的版本与原投递快照不被工作台替换 |

投递授权说明、撤回限制、第三方参考与模型降级提示继续保留。投递操作必须另行确认授权；已下载副本不能通过平台撤回追回。工作台不自动发站内回复、邮件或创建投递。

## 当前启动入口（2026-10-10）

先启动Docker Desktop。普通本地服务使用 `Start-Local.ps1`，演示仅由 `Start-Demo.ps1` 复用它，独立合成验收使用 `scripts/Start-E2E.ps1`；三个入口不要同时占用同一端口。

```powershell
# 自动选择通过版本与源码核验的已安装环境；只读检查
.\Start-Local.ps1 -CheckOnly
# 若使用本轮已经升级的独立依赖目录
.\Start-Local.ps1 -BackendVenv .venv-dependency23 -FrontendStage dep-frontend-20261010 -CheckOnly
# 普通启动：不变的源码/资源/锁文件复用生产构建
.\Start-Local.ps1
# 强制重建；或只准备构建、不运行Docker/迁移/服务
.\Start-Local.ps1 -Rebuild
.\Start-Local.ps1 -BuildOnly
# 停止只结束本入口记录的进程，数据卷保留
.\Stop-Local.ps1
```

启动前校验后端生产pin、前端lock/版本及源文件。默认先检查常规目录，不符合时查找本地已存在的升级解释器/dep-frontend目录，最终选择会明确显示；显式指定环境时只检查指定目录，不静默切换。无合格环境就报安装指引，不自动安装或改.env。

生产构建以源码、public资源、锁文件、配置、BUILD_ID和完整产物共同校验，未变时复用；`-Rebuild`强制重建，`-SkipBuild`只接受已有可信且一致的构建记录。重复启动仅复用进程归属、代码/配置与端口均一致的自有健康服务，变更时提示先停止；启停锁阻止重复启动。双击Stop-Demo默认保留共用PostgreSQL，确实不再需要时 `Stop-Demo.cmd -Database`。

主服务8000/3000，合成E2E8001/3001；进程记录/存储/数据库分开。以下历史来源章节的“每次构建/直接复用HTTP200/默认停止数据库”以本节的新启动行为为准。

独立核验预算测试需 `-SyntheticVerification -ActivateSyntheticBudget`，在新run迁移后、任何同意分析前执行真实空库存审计。旧run无完整物理账目时应拒绝，不改旧任务来开闸。当前运行ID以[当前接力](../当前接力.md)为准，切勿复制历史run重播。

以下为归类后的安装与使用参考，旧版本号、历史计数及套餐余额不作为当前状态。只阅读与你操作对应的章节。

## 本地生产模式复现

适用Windows PowerShell。需要Python 3.12、Node.js、npm、已启动的Docker Desktop和可用的DeepSeek官方API Key。仓库脚本不购买服务、不写入Key，也不提供主动规则模式。

```powershell
Set-Location backend

Set-Location ..\jianli

Set-Location ..
```

编辑 `backend/.env`：

```dotenv
AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=true
DEEPSEEK_API_KEY=仅保存在本机的Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

```powershell

```

脚本会等待PostgreSQL、迁移到最新schema、构建Next.js、启动两个服务、验证健康状态，并初始化演示账号和九个合成岗位。默认只监听 `127.0.0.1`。缺少DeepSeek配置时启动会失败，不会静默改为规则模式。

### 被动规则兜底

产品始终按AI链路发起分析。DeepSeek网络失败、限流、超时、鉴权错误、非法JSON、引用越界、评级越界或一次修正后仍未通过校验时，系统自动保存本地兜底报告。无可发送证据或达到每日用量上限时同样跳过外部请求并保存本地结果。

SSE连接中断只会让前端改用轮询，不等于模型断链。是否发生AI降级以任务步骤和报告标记为准。

## CareerProof 完整使用手册

本文覆盖系统管理员、企业用户和学生用户的完整操作流程，并作为比赛演示的统一操作依据。

只想人工点一遍网站、不需要安装或读代码时，使用 [网站人工测试手册](使用与启动.md)。

如果准备课堂汇报或指导老师检查，优先使用 [教师展示运行手册](使用与启动.md)，其中提供约7分钟的点击顺序、讲解口径和现场异常处理。

### 1. 产品运行原则

CareerProof 只提供一种面向用户的分析方式：**AI证据分析**。

正常流程为：

```text
上传材料
  → 本地解析与OCR
  → 按岗位要求检索候选证据
  → 本地规则确定引用范围和评级上限
  → DeepSeek解释证据并完成1–3级初评
  → 必要时最多两轮受控补检索规划
  → 后端校验引用、评级和表达边界
  → 保存报告
```

规则引擎不是用户可选择的独立模式。它只承担三个职责：

1. 在模型调用前确定候选证据、引用白名单和评级上限；
2. 在模型返回后校验引用、评级和过度结论；
3. 在模型断链、限流、超时、鉴权失败或输出不合格时自动保存兜底报告。

如果材料完全没有可发送的证据，或账号达到每日AI用量上限，系统也会被动保存本地结果。用户未勾选外部AI授权时，前端不允许创建分析任务。

### 2. 角色与功能边界

| 角色 | 当前可以使用的功能 | 当前没有开放的功能 |
| --- | --- | --- |
| 学生 | 上传与归档恢复材料、AI匹配与复核、历史报告、逐份投递授权、回应时间线与撤回 | 在线面试、自动录用推断 |
| 企业 | 创建企业组织、发布岗位、设置要求和权重、编辑/关闭/重新发布岗位、管理本企业岗位 | 查看学生私有报告、候选人列表、AI候选人排序、面试邀请 |
| 管理员 | 具备受保护页面的管理访问能力 | 当前没有单独的后台运营控制台 |

学生报告默认只属于学生本人。企业发布岗位并不自动获得学生简历、项目或报告的读取权限。

### 5. 一键启动与停止

#### 5.1 启动

直接双击项目根目录的 `Start-Demo.cmd`，或者运行：

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
.\Start-Demo.ps1
```

脚本会依次：

1. 检查DeepSeek配置；
2. 启动PostgreSQL；
3. 执行数据库迁移；
4. 构建并启动FastAPI和Next.js；
5. 检查前后端健康状态；
6. 初始化演示账号、企业组织和九个合成岗位；
7. 打开演示指南页面。

入口地址：

- 首页：<http://127.0.0.1:3000>
- 演示指南：<http://127.0.0.1:3000/demo>
- API健康检查：<http://127.0.0.1:8000/api/v1/health>
- API文档：<http://127.0.0.1:8000/docs>

全程使用 `127.0.0.1`，不要与 `localhost` 混用，以免登录Cookie不一致。

#### 5.2 停止

可以直接双击项目根目录的 `Stop-Demo.cmd`。也可以在PowerShell中停止前后端并同时停止PostgreSQL容器：

```powershell
Set-Location 'D:\jbcode\web ai\jianli'
.\Stop-Local.ps1 -Database
```

数据库卷和历史数据会保留。脚本不会删除上传文件。

| 工作类型 | 实习 |
| 岗位状态 | 公开发布 |
| 岗位描述 | 使用FastAPI开发接口，维护PostgreSQL数据并编写自动化测试 |

然后添加岗位要求。每条要求需要填写：

- 要求原文；
- 技能名称；
- 重要程度1–5；
- 必要要求或加分项。

推荐演示要求：Python、FastAPI、PostgreSQL、pytest、Redis。点击“发布岗位”后，应能在公开岗位列表中找到它。

#### 6.4 管理岗位

进入 <http://127.0.0.1:3000/jobs/mine>：

- 使用关键词、方向、城市和类型筛选岗位；
- 查看草稿、已发布和已关闭状态；
- 编辑岗位基本信息；
- 关闭正在招聘的岗位；
- 将草稿或关闭岗位重新发布。

岗位已经产生匹配任务或报告后，能力要求会锁定。需要修改要求时应新建岗位，避免历史报告引用被改变。

#### 6.5 企业端当前边界

企业在岗位详情点“查看本岗位已授权投递与匹配对照”，可按关键词或岗位要求分数维度对照学生主动投递的固定报告：

- 未投递或已撤回的学生不可见，其他学生私有报告与项目接口不开放；
- 点击候选人或热力格子后查看固定报告及引用，雷达图只展示已有分数；
- 下载只交付本次明确授权的简历，平台事件不证明对方阅读；
- 企业可确认发送站内回复，学生在“我的投递”查看并撤回授权；
- 企业单独 AI 评估、通知中心、邮件发送与完整项目预览尚待实现。

比赛讲解时可描述为“岗位定义与授权报告对照”，不能描述成完整ATS招聘系统。操作验收步骤见 [网站人工测试手册](使用与启动.md)。

### 7. 学生端完整流程

#### 7.1 登录学生账号

1. 退出企业账号；
2. 打开登录页；
3. 使用学生演示账号登录；
4. 顶部导航应显示“岗位发现”“我的材料”“职业推荐”和“我的匹配报告”。

#### 7.2 下载演示材料

打开 <http://127.0.0.1:3000/demo>，先下载：

- CP01 卡片对应的简历 TXT；
- CP01 对应项目 ZIP 与人工测试步骤 TXT。其他职业下载同编号的对应文件。

ZIP无需解压。所有演示数据均为合成内容。

#### 7.3 上传简历

进入“我的材料”，在简历区域填写：

```text
简历名称：CP01｜Python 后端｜测试简历-本轮日期
文件：CP01-Python 后端-简历-v1.txt
```

点击“上传并解析简历”，等待进度达到100%和状态变成解析完成。打开预览，确认提取文本与原文件一致。

简历支持PDF、DOCX、TXT、PNG、JPG/JPEG、WEBP和BMP，最大10MB。扫描PDF和图片使用本地OCR，OCR文本必须对照原图复核。

#### 7.4 上传项目或作品

在项目区域填写：

```text
项目名称：CP01｜任务管理 API｜测试项目-本轮日期
项目说明：合成测试项目，包含 Python、FastAPI、PostgreSQL 和 pytest 片段，用于测试证据匹配。运行情况和作者贡献未经核验。
文件：CP01-Python 后端-任务管理 API-v1.zip
```

点击“创建项目并开始扫描”。ZIP最大30MB，无需解压；打包前应移除 `node_modules` 等依赖目录。系统只做静态分析，不执行上传代码。

解析完成后打开项目预览，检查文件列表、原文行号和内容。上传新版本不会覆盖旧报告引用的历史版本。

#### 7.5 获取职业与岗位推荐

1. 点击顶部“职业推荐”；
2. 选择一份已完成解析的简历；
3. 勾选要参与检索的项目版本，最多10项；
4. 核对所选版本，阅读外发范围并勾选同意；
5. 点击“生成 AI 职业规划”；
6. 查看“本次生成的规划”。默认显示 AI 实际比较的重点岗位；模型降级时显示前几个规则候选，其他候选按需展开；
7. 选择一个岗位，点击“查看岗位并生成完整 AI 报告”。

规则预筛在本地读取已解析材料并比较已发布岗位；按钮随后调用 DeepSeek 生成比较、缺口和补证任务，会产生 API 用量。推荐顺序是材料与岗位要求的证据贴合度，不是能力认证、跨人排名或录用概率。没有项目证据时，页面会把结果标记为“探索方向”，不能描述成强推荐。通过推荐入口进入岗位页时，页面会沿用该规划保存的简历和项目；后端仍会在创建任务时检查材料归属和状态。

进入或刷新职业推荐页不会自动显示旧规划。要读取已有结果，点击“查看上次保存的规划”；此操作不调用模型，也不会替换当前材料选择，页面明确标为“历史结果”。更换简历或项目版本后会收起当前展示，请重新生成，避免把旧结论当成新材料的分析。保存的完整候选不删除；“展开其余规则候选”只改变展示，不产生额外调用。

#### 7.6 选择岗位

1. 从职业推荐进入岗位，或在“岗位发现”搜索并打开目标岗位；
2. 阅读岗位描述和要求；
3. 核对简历版本；从职业推荐进入时会自动沿用刚才选择的版本；
4. 核对要参与分析的项目版本，最多10项，也可以手动调整。

#### 7.7 确认AI发送范围

页面会展示：

- 本次选择的材料；
- 岗位要求数量；
- 每项最多发送的必要证据片段；
- 邮箱、手机号、身份证号和标签姓名的自动脱敏范围；
- 不主动发送的账号身份、原始文件、完整简历和原始图片。

阅读后勾选：

```text
我已查看上述发送范围，同意将脱敏后的必要片段发送给外部AI生成带引用解释。
```

未勾选时不能创建任务。自由文本中的地址、别名或非标准个人信息不保证全部识别，因此真实使用时只选择完成分析必需的材料。

#### 7.8 创建并观察分析任务

点击“生成我的匹配报告”。任务页通过SSE展示实时进度，连接中断时自动改用轮询获取任务状态。

正常记录应包括：

1. 核对材料版本；
2. 检索候选证据；
3. 计算证据边界；
4. 模型判断是否需要补检索；
5. DeepSeek证据分析；
6. 校验模型引用；
7. 保存可追溯报告。

SSE断开只影响页面实时更新，不等于DeepSeek断链。页面会改用轮询，不会因此把分析改成规则兜底。

#### 7.9 阅读报告

报告顶部应显示真实处理结果：

- “AI证据初评 + 规则校验”：模型输出已经通过后端校验；
- “规则报告 · 模型已降级”：模型连接或输出失败，已被动保存本地结果。

AI成功时还应显示实际模型、耗时、输入Token和输出Token。逐项报告包括：

- 岗位要求和技能；
- 材料证据等级；
- AI对相关性、实质操作和完整任务的判断；
- 引用编号；
- 文件名、行号和原文；
- 信息缺口和补充建议。

评级含义：

| 等级 | 含义 |
| --- | --- |
| 1级 | 基础线索 |
| 2级 | 局部操作 |
| 3级 | 任务实现 |
| 4级 | 验证闭环 |
| 5级 | 工程验证 |

当前自动初评最高为3级。4、5级需要可审计的运行验证和独立复核，尚未开放自动授予。评级描述材料支持度，不是证书、个人能力认证或录用概率。

#### 7.10 核对引用

展开“查看来源证据”，检查：

- 引用编号与AI解释一致；
- 文件路径和原始行号存在；
- 代码或文档片段确实支持当前结论；
- 依赖声明没有被说成完整实现；
- 代码片段没有被说成已经运行成功；
- 报告没有推断本人贡献。

#### 7.11 人工复核

每条有来源的要求都可以：

- 采纳证据；
- 驳回证据；
- 标记已修正；
- 填写复核理由；
- 恢复待复核状态。

保存后刷新页面，状态、备注和时间应继续存在。该操作只代表当前用户复核，不等于独立考官认证。

#### 7.12 查看历史报告

进入“我的匹配报告”，可以重新打开已完成报告。报告固定当次岗位要求和材料版本；后续上传新材料不会偷偷改写旧报告。

### 8. Function Calling专项演示

普通演示优先打开已有专项报告。内部验收岗位已关闭，不能再从公开列表选择。需要付费复验时，由负责人在 `backend` 运行 `.venv\Scripts\python.exe -m evals.verify_deepseek_tool_report`；脚本准备合成材料并临时启用专用岗位，结束时关闭岗位，保留报告。

1. 负责人提供本次或已保存的专项报告地址；
2. 学生账号打开报告；
3. 核对固定的合成项目版本；
4. 不重新生成即可查看保存的模型调用；
5. 确认报告为有效 AI 结果；
6. 展开“受控补检索规划”记录；
7. 确认检索范围为“当前上传材料”；
8. 点击新增引用 `R1-E3`；
9. 确认定位到 `create_item` 的实际代码；
10. 确认报告仍保留运行结果、测试和本人贡献未核验的边界。

模型最多规划两轮，每轮至多申请一次白名单补检索；也可以判断无需继续。工具不能访问任意文件、网络或其他用户数据。

### 9. OCR专项演示

1. 准备不含真实个人信息的PNG/JPG图片或扫描PDF；
2. 从简历入口上传；
3. 等待本地OCR完成；
4. 打开预览；
5. 核对页码、识别文本、平均置信度和人工复核提示；
6. 对照原图确认关键内容后再用于岗位分析。

仅做本地 OCR 时不发送图片；主动启用“视觉观察”时，会在单独授权后发送所选合成图片给 DeepSeek。两种流程和费用需分开记录。

### 10. AI断链与被动规则兜底

以下情况会触发被动兜底：

- DeepSeek网络连接失败；
- 请求超时；
- 429限流或服务繁忙；
- Key无效或鉴权失败；
- 模型输出不是可校验JSON；
- 引用不存在或跨要求引用；
- AI评级超过规则上限；
- 输出包含受保护的过度结论；
- 一次定向修正后仍未通过校验；
- 材料没有可发送证据；
- 达到账号每日用量上限。

兜底时系统不会伪造AI结果。报告会标明模型已降级，保留本地检索证据、材料缺口和可追溯来源；模型解释、AI评级和Token显示为空或按实际已发生调用记录。

用户不能从页面主动切换到规则模式。项目启动脚本也不再提供 `RulesOnly` 参数。

### 11. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 启动提示缺少DeepSeek配置 | 检查本机 `.env` 中启用开关、Provider和Key；脚本不会自动改成规则模式 |
| Docker数据库未就绪 | 等待Docker Desktop完成启动，再重新运行启动脚本 |
| 提示存在旧的local run record | 一键脚本会在前后端均离线时自动安全清理；仍失败时双击 `Stop-Demo.cmd` 再重试 |
| 3000或8000端口占用 | 如果是本项目上次启动，先运行 `Stop-Local.ps1`；不要误杀来源不明的进程 |
| 演示账号不存在 | 服务启动后运行 `backend/.venv/Scripts/python.exe -m evals.seed_demo` |
| 登录后立即失效 | 统一使用 `127.0.0.1`，清理混用 `localhost` 产生的旧Cookie |
| 文档没有可分析文字 | 打开材料预览；扫描文件使用OCR；损坏文件需要上传新版本 |
| ZIP上传失败 | 确认小于30MB、没有路径穿越、符号链接、依赖目录或过量文件 |
| 页面显示连接中断 | 这是SSE断开，页面会自动轮询；查看任务步骤判断模型是否真正降级 |
| 报告显示模型降级 | 查看任务实际记录中的失败原因，不要连续重试消耗额度 |
| 企业看不到学生报告 | 请确认学生已逐份授权投递到该企业的岗位且未撤回；私有报告原地址仍拒绝企业访问 |

日志位于 `backend/.tmp/local-run/`，该目录被Git忽略。

- 企业新增AI综合评估、通知中心、SMTP邮件与完整项目文件预览仍待完成；
- 自动评级最高3级；
- OCR是本地图像转文字，不是通用视觉大模型；
- 当前是单工具、最多两轮的受控Function Calling，不是通用多Agent；
- 检索链路应称为可追溯的混合候选检索增强；固定检测器、有界词法排序与可选本地语义文档候选共同工作，数据库哈希向量不等于语义embedding，不宣称通用向量RAG；
- 在线部署为可选加分项，本地演示仍需保证可复现。

## CareerProof 教师展示运行手册

适用场景：课堂汇报、指导老师检查、比赛预演和录制前走查。本文按“准备—启动—企业端—学生端—AI亮点—异常说明—结束”排列，照顺序操作即可。

### 1. 展示目标

建议用一句话介绍项目：

> CareerProof是一款面向高校学生求职准备的AI岗位证据分析Web应用。它把岗位要求、简历声明和项目原文连接起来，让DeepSeek解释材料支持了什么、还缺什么，并允许用户点击引用和人工复核。

本次展示需要让老师看到五点：

1. 企业端能够创建组织、发布和管理岗位；
2. 学生端能够上传简历与项目并查看解析结果；

4. 每个AI结论都能回到文件、行号和原文；
5. AI断链或输出不合格时，系统自动保存本地兜底报告。

2026-09-26 模型统一：上述学生与企业功能、截图内容观察均使用同一DeepSeek官方Key，无需智谱或百炼。可另外上传 `demo/synthetic-vision-panel.png`，在预览页单独授权原图外发后生成描述，点击估计区域、记录本人核对并刷新。图片按用量计费，不证明真实运行、不自动提高等级；OCR仍在本机处理。演示前先读[视觉验收边界](../archive/验收记录/视觉证据验收-20260926.md)。

### 2. 展示前准备

#### 2.1 电脑环境

启动后打开 <http://127.0.0.1:3000/demo>，可以直接下载：

| 现象 | 现场处理 |

### 6. 老师常见问题与回答

#### 6.1 这是不是简单调用大模型API？

不是。系统在模型前完成材料解析、证据检索、引用编号和评级上限；模型可进行至多两轮受控补检索规划；模型后还要经过JSON结构、要求编号、引用白名单、评级和过度结论校验。失败时不会直接展示未经验证的回答。

#### 6.2 规则和AI是什么关系？

AI负责证据解释、缺口建议和1–3级初评；规则负责检索候选证据、限制模型边界和故障兜底。产品没有供用户主动选择的规则模式。

#### 6.3 这是RAG吗？

当前准确表述是“可追溯的混合候选检索增强生成闭环”。系统先运行固定技能检测器，再以本地多语言 ONNX 模型检索项目文档、用有界词法排序补充代码及文本候选，随后核对文件哈希、行号和原文再交给 DeepSeek。两种补充候选都不能自动提高规则分数。语义模型需要事先安装；缺失或失败时只保留词法检索。四个固定检索小例与一次隔离进程来源核对已通过，但尚未证明真实材料上的通用向量 RAG 质量。

#### 6.4 这是Agent吗？

当前是单工具、最多两轮的受控AI工作流。DeepSeek可以参考上一轮结果决定继续补检索或停止，但不是开放式通用Agent或多Agent系统。

#### 6.5 为什么企业不能直接看学生报告？

这是隐私边界。学生报告包含私有材料，企业只有在学生逐份确认投递授权后，才能从本岗位投递入口查看固定快照；企业发布岗位本身不会开放学生数据。撤回后平台拒绝企业后续访问，已下载副本无法追回。

#### 6.6 分数能证明学生能力吗？

不能。当前已经改为逐项实践证据等级，表示本次材料对岗位要求的支持程度。代码没有被执行，测试结果、作者身份和本人贡献仍需核验。

#### 6.7 为什么最高只自动评到3级？

1–3级可根据静态材料判断线索、局部操作和任务实现；4–5级需要运行结果、测试闭环、工程质量和独立复核，现阶段不自动授予，避免过度评价。

### 7. 讲解中不要使用的表述

不要说：

- “系统能准确判断一个人是否胜任岗位”；
- “AI评分就是候选人的能力分”；
- “所有岗位和职业都已经完整支持”；
- “这是通用Agent、通用RAG或MCP平台”；
- “OCR能理解图片中的业务逻辑”；
- “企业已经可以查看和排名全部候选人”；
- “DeepSeek API永久免费”；
- “代码已经运行通过”或“测试全部通过”，除非展示了真实运行记录。

建议说：

- “评级描述材料支持度”；
- “缺少证据不等于缺少能力”；
- “引用编号和原文已经校验，语义结论仍需人工复核”；
- “当前聚焦软件开发岗位的完整链路，其他方向用于覆盖边界展示”。

### 企业流程：确认后才发布

先退出学生账号，再用企业演示账号登录。只管理本次新建的合成测试岗位，不改其他人的岗位。

1. 进入“我的岗位”，点发布岗位入口。选择已有演示企业；没有企业时请负责人初始化，或创建名称为 `人工测试企业-日期` 的合成企业。
2. 岗位名称填 `人工测试后端实习生-日期`，方向选软件开发，城市填深圳，工作类型选实习，状态先选“保存草稿”。岗位描述可以复制：

   > 合成测试岗位，不是真实招聘。需要使用 Python 和 FastAPI 编写接口，包含输入校验与错误响应；能使用 PostgreSQL 做参数化查询。pytest 接口测试是加分项。请提供相应源码与可核对材料，不要求证明生产运行经历。

3. 允许本轮模型调用时，阅读并勾选岗位描述发送授权，点一次“从描述生成 AI 草稿”。未授权时按钮不能执行生成。

5. 点“确认选中要求并填入表单”。检查要求表单，必要时修改文字或权重。草稿生成和确认都不应该自动发布岗位。

MCP 客户端配置由负责人准备，普通测试人员按下节操作，不要求自己安装或写代码。本手册不能替代独立语义审核：若老师愿意审核，可逐条注明“结论是否被引用支持、是否过度推断、哪里还缺材料”，保留审核者、日期与理由。

### MCP 人工专项：有人带着也能完成

MCP 是让你选择的客户端只读查询选定报告，不是另一种网站聊天功能。请负责人按 [受控 MCP 使用与验收](工具与接入.md) 先配好本机可信客户端；工具调用若由模型自主规划可能产生客户端模型费用。测试只用合成报告。

1. **H01 授权**：学生打开自己的合成报告，展开“外部工具只读访问（可选）”。不勾敏感信息确认时“生成十分钟只读授权”应禁用。勾确认，按需要勾“同时授权上一份同岗位报告”，生成一次。没有上一份报告时应提示，不扩大到其他岗位。
2. **H02 只读查询**：请负责人把临时凭证放到本机客户端，勿发聊天或截图。让客户端分别检索本报告证据、读取摘要；已同时授权两份报告时再做比较。三个工具为 `search_evidence`、`get_report_summary`、`compare_reports`。返回内容应只来自选定报告，脱敏/截断标记与原始定位明确；不能上传、修改或复核材料。让负责人用一条未授权的合成报告 ID 验证拒绝，不能试探真实报告。
3. **H03 撤销**：在离开或刷新授权页面前点“立即撤销”，看到撤销提示后让同一个客户端再读取，应失败。此前已读到的内容不会从客户端自动删除，不能将撤销描述成召回旧数据。
4. **H04 过期**：另发一份合成短期授权，保持页面开着，不需要等待中反复调用；到页面显示的有效期后让客户端查询，应拒绝。最多 40 次调用的边界可由负责人既有专项记录核对；普通测试不为测限额制造 41 次模型问答。

刷新只会隐藏网页里的临时凭证，不等于撤销；所以测试完必须先撤销再离开。未配客户端只能记“网页授权/撤销通过、客户端未测”。输出截图必须遮住临时凭证；商业客户端界面、回答是否受证据支持另写结果。

### 哪些功能目前没有（不要误报“找不到”）

目前未开放：企业读取未投递学生的私有材料、企业单独AI综合评估、通知中心、SMTP邮件、在线聊天/面试、账号自助重置密码、独立专家认证、高等级自动授予、永久文件删除和管理员运营后台。学生明确投递、企业授权报告对照与站内回复已开放；归档可以恢复。旧的候选人/匹配演示地址不作为新增业务入口。公网部署、录制视频、PDF、团队资料由负责人另行验收。

### 遇到问题怎么处理

| 现象 | 先做什么 |
| --- | --- |
| 网站打不开 | 确认运行项目的是这台电脑、地址正确、负责人已启动项目。Docker 启动并不会自动启动前后端。服务恢复后刷新原错误页。 |
| 点击没反应 | 等一次加载完成；仍无反应时记录按钮名，尝试 Tab 聚焦后按 Enter（复选框按空格）。键盘成功只能记录为键盘通过，鼠标问题仍记下。不要同时重复提交。 |
| 文件不受支持/无可分析文字 | 先用演示 TXT/ZIP 排除文件因素。扫描 PDF/图片核对 OCR；项目 ZIP 与简历上传入口别用反。不要把所有失败都归为 AI 失败。 |
| 任务失败 | 记录任务页地址和错误。如果文件问题，上传修正的新版本；“重试此任务”复用原版本，不能修复文件内容。 |
| 模型已降级/限额/超时 | 报告可继续看，记“兜底通过，AI 未通过”。不要立即多次重新生成；交负责人查模型、配置或预算。 |
| 引用不支持解释 | 记录要求、引用号、片段及问题句，驳回或恢复待复核。不为拿高等级改写测试预期。 |
| 登录失败 | 核对角色账号及原密码，请负责人处理。不要改本机凭据文件试图重置账号。 |

截图不要包含密码、Key、完整敏感简历或授权令牌。异常报告提供：哪一步、哪个按钮、页面地址、预期、实际结果和脱敏截图。
