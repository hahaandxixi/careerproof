# 使用与启动

更新：2026-10-14。本文是当前用户操作入口；开发状态见[当前接力](../当前接力.md)，AI/预算/隐私见[AI与数据边界](AI与数据边界.md)。旧版本日志不作为当前使用说明。

按步骤展示网站，请使用[功能演示文档](功能演示.md)：热力图预览、学生报告、企业回复与通知、缺口补证、撤回后重新投递。

## 第一次使用：先完成一条路线

1. 在同一网站地址注册或登录**学生账号**；日常使用3000，已有3001测试账号仍用3001，不切换环境。
2. 打开 `/demo`，先选CP01“Python后端”。下载同编号简历TXT、项目ZIP和测试步骤；项目ZIP不解压、不执行。也可点“导入这套材料到我的账号”，只上传合成材料，不生成AI报告；随后点“查看个人材料与解析进度”，等简历和项目都解析完成。
3. 选择手动上传的，从“学生账户 → 个人材料”分别上传简历和项目；已导入且解析完成的，无需重复上传。点击该示例“查找对应岗位”，在岗位页选择刚才的同编号版本；没有对应岗位时需企业先准备，不能把热力图预览当真实岗位。
4. 先生成规则报告时，不勾选外部AI同意即可继续，不外发材料。需要AI解释时，阅读发送范围及费用说明，明确同意后再生成。先看概括与下一步补证计划，证据按需展开；本人核对备注可选。页面明确区分AI结果与本地降级，公共热力图只是预设示例。
5. 决定投递时，在报告页阅读分享范围、勾选同意、确认投递。随后从“学生账户 → 个人投递/通知”查看；企业只可查看其岗位的已授权固定快照。

首次独立用户还需实际完成上述路线并反馈卡点；本文不是该验收已经通过的证明。更换版本、补证和撤回重投见功能演示。

## 先找到登录账号

**先看地址栏：昨天在3001注册的账号，今天仍到3001登录。** 3000与3001使用不同数据库，账号、投递、通知不互通；“邮箱或密码错误”也可能是当前库中没有该账号，并不证明密码错误或数据丢失。日常使用固定选择3000，已有隔离测试记录沿原运行恢复，不靠重新注册或播种找回。

| 使用场景 | 登录入口 | 凭据位置 |
| --- | --- | --- |
| 日常使用，自己注册的账号 | `http://127.0.0.1:3000/login` | 注册时自行设置的邮箱、密码 |
| 日常演示账号 | `http://127.0.0.1:3000/login` | `backend/.tmp/demo-credentials.json`，字段见下表 |
| 隔离环境，自己注册的账号 | `http://127.0.0.1:3001/login` | 注册时自行设置的邮箱、密码；不写入演示凭据文件 |
| 隔离运行的企业账号 | `http://127.0.0.1:3001/login` | `backend/.tmp/e2e/<RunId>.json` 内 `accounts.enterprise.email/password` |
| HTTP演示准备的独立学生 | `http://127.0.0.1:3001/login` | `backend/.tmp/release-smoke/<RunId>.credentials.json` |

本机当前恢复的隔离运行是 `release-owner-20261012`；企业凭据可在[该运行账号文件](../../backend/.tmp/e2e/release-owner-20261012.json)中查找。路径只在这台机器有效，不是所有新运行的默认账号。

**本机凭据文件：[打开演示账号与密码](../../backend/.tmp/demo-credentials.json)。** 文件不进入 Git；换机器或评审打包后，这个链接可能不存在。

| 文件字段 | 用途 |
| --- | --- |
| `studentEmail` | 学生登录邮箱 |
| `enterpriseEmail` | 企业登录邮箱 |
| `password` | 两个演示账号共用的本机密码 |

登录地址：<http://127.0.0.1:3000/login>。复制对应邮箱和 `password` 的值，**不要复制 JSON 引号**。2026-10-12 已只读核对：两账号存在且有效，凭据密码匹配数据库；不在文档中复制实际密码。

`Start-Local.ps1` 只启动服务，不创建演示账号。首次演示请用 `Start-Demo.cmd` 或 `Start-Demo.ps1` 初始化账号和合成样例。如果文件不存在，先确认演示初始化成功。环境变量 `DEMO_STUDENT_EMAIL`、`DEMO_ENTERPRISE_EMAIL`、`DEMO_PASSWORD` 同时设置时优先于文件；不要混用两套凭据。

### 凭据检查与更换边界

修改 JSON 不会重置数据库已有账号的密码，也不会撤销旧会话。登录失败先确认与注册时相同的端口和运行，再核对文件或显式配置，不要反复重播种或修改密码猜测。需要换凭据时使用明确的新合成身份，保留原数据。网页 `/demo` 提供查找路径，不公开密码。可离线检查日常演示文件格式：

```powershell
Set-Location backend
.\.venv-dependency23\Scripts\python.exe -m evals.demo_credentials
```

### 查看自己的投递，以及切换企业查看

学生登录后点击顶部“学生账户”，选择“个人投递”或“通知”。例如在3001测试，就打开 `http://127.0.0.1:3001/applications` 或 `/notifications`；不要将链接换成3000。

查看企业侧时，退出学生后用**同一环境、目标岗位所属企业**的账号登录，进入“我的岗位”，选择该岗位的授权投递列表。学生账号不能进入企业页；任意新注册的企业账号也不会自动获得其他企业岗位权限。企业看到的是投递时固定报告；撤回后不能继续查看旧授权。

学生与企业同时操作，请用两个浏览器或独立浏览器配置。普通标签页共用登录Cookie；同一主机的3000/3001也不能靠端口隔离Cookie，跨环境登录可能覆盖现有会话。切换后如身份不符，回到正确环境重新登录，不改数据库。

## 三个启动入口

先双击桌面的 Docker Desktop，等待引擎就绪。在 `D:\jbcode\web ai\jianli` 操作：

| 入口 | 用途 | 端口与数据 |
| --- | --- | --- |
| `Start-Local.ps1` | 日常本地使用 | 3000/8000，普通数据库；不初始化演示账号 |
| `Start-Demo.cmd` / `Start-Demo.ps1` | 比赛/课堂演示 | 复用 Local，同端口；另外初始化合成账号、岗位和材料 |
| `scripts/Start-E2E.ps1` | 开发隔离验收 | 3001/8001，专属 `cp_e2e_*` 数据库、存储与构建；强制合成模型 |

Local 和 Demo 不要并行抢占同一端口。E2E 可与日常环境并存，但账号和材料不互通；按任务卡指定 RunId，不复制旧 run 重新播种。

```powershell
# 只读预检
.\Start-Local.ps1 -CheckOnly
# 日常启动
.\Start-Local.ps1
# 需要演示初始化时运行
.\Start-Demo.ps1 -NoBrowser
# 强制重建 / 只构建不启动
.\Start-Local.ps1 -Rebuild
.\Start-Local.ps1 -BuildOnly
# 默认只停网站，保留数据库容器与数据卷
.\Stop-Local.ps1
```

启动脚本自动选择合格的已安装依赖环境，显示实际路径；不自动安装或改 `.env`。未变的源码复用生产构建；改动后重建。启动会检查数据库迁移并更新 schema。重复启动只复用身份、代码与配置都一致的自有服务。

当前可用依赖示例为后端目录下的 `backend/.venv-dependency23` 与 `backend/.tmp/dep-frontend-20261010`，以预检输出为准。以下参数接收目录名，由脚本在后端目录定位；命令仍从项目根运行：

```powershell
.\Start-Local.ps1 -BackendVenv .venv-dependency23 -FrontendStage dep-frontend-20261010 -CheckOnly
```

停止演示可双击 `Stop-Demo.cmd`。确认没有其他验收服务使用数据库后，才使用 `Stop-Local.ps1 -Database` 停止数据库容器；数据卷保留。

## 首次安装与当前模型配置

安装依赖按[后端说明](../../backend/README.md)和[前端说明](../../jianli/README.md)执行，版本以当前锁文件/生产 pin 为准，旧手册版本号不作为安装依据。

网站外部生成只配置 **DeepSeek 官方 API**，文字与图片观察共用本机 Key；模型名以当前 `backend/.env` 为准。配置字段如下，示例不是实际密钥：

```dotenv
AI_PROVIDER=deepseek
AI_EXTERNAL_ENABLED=true
DEEPSEEK_API_KEY=填入本机Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

启动和登录不调用模型。主动发起分析、职业规划或视觉观察可能产生费用，各自按页面同意及预算执行；模型失败会明确保存被动兜底结果。隔离合成验收不消耗真实 API 额度。本地 OCR/ONNX 检索不属于外部生成。ZCode 开发模型额度与网站 DeepSeek 额度分开。

## 无需账号的热力图演示

打开 [企业热力图交互示例](http://127.0.0.1:3000/demo/heatmap)，或在 `/demo` 点击“打开热力图交互演示”。3 位虚构候选人、4 项要求，可按关键词/要求/状态筛选、点选候选人查看雷达和来源说明。状态与分数为预设合成数据，不生成报告、不调用模型、不创建投递；真实企业列表为空时也提供这个入口，不能把示例当真实授权记录。

## 学生账户菜单

登录后点击顶部“学生账户 · 姓名”，在下拉栏查看“个人材料”“个人投递”“通知”或退出登录。三个私人入口不再平铺于主导航，主导航保留岗位发现、职业推荐和匹配报告。账户入口显示未读通知提示，菜单中保留未读计数；读取失败不会冒充零未读。点击页面外部、导航或按 Esc 收起菜单；Esc 返回账户入口焦点。支持 Enter/Space 打开和 Tab 选择链接。

## 学生使用顺序

1. 用 `studentEmail` 登录。打开 `/demo`，选一套同编号简历和项目材料；不要混选不同职业编号。
2. 点击顶部“学生账户”→“个人材料”，上传简历和项目 ZIP，等待解析完成。源码、文档与图片按各自边界展示，不执行上传代码。
3. 从“岗位发现”选择岗位，或从“职业推荐”查看方向建议；选择本次材料版本。
4. 阅读 AI 发送范围、确认后主动发起分析。在任务页等待结果，遇到断线按页面轮询/重试提示处理，不反复创建分析。
5. 打开“我的匹配报告”，核对逐项状态、引用原文、缺口、模型降级与人工复核说明。
6. 从下方补证工作台进入一条缺口，上传新版、保存材料选择，再生成新报告并比较。
7. 如需投递，单独阅读报告页的分享范围并确认授权。新版材料不会自动替换原投递快照。撤回后可在“个人投递”点击“重新确认授权并投递”，在报告页重新勾选分享授权；也可选择新版报告投递。每次重新投递创建新记录，旧记录、回复和快照保留，企业旧链接与旧通知不会重新开放。同岗位同时只允许一份有效投递；撤回后重新投递也计入24小时20次上限。

## 企业使用顺序

1. 用 `enterpriseEmail` 登录，在“发布岗位”创建或选择自己的企业组织。
2. 填写岗位信息和逐条要求，核对 AI 提取的草稿后再发布。发布岗位不会获得学生私有报告访问权。
3. 从自己的岗位进入已授权投递列表，比较对应岗位要求和固定报告来源；不按能力总分排名。
4. 查看或下载授权范围内的材料，必要时从要求出发提问/回复。发送是主动操作，不由 AI 建议自动完成。
5. 学生撤回后，平台报告和旧通知访问按授权检查失效；已下载副本无法追回。学生私人草稿与补证报告不自动共享给企业。

## 缺口补证工作台使用说明（2026-10-12）

### 从哪里进入

以学生账号登录，从顶部“我的匹配报告”打开一份自己的报告，在报告摘要下找到“我的缺口补证工作台”。沿用原站靛蓝、白色卡片与原导航，不新增独立账号或另一套报告。企业端仍按授权查看固定投递快照，不显示学生私人工作台。

[证据工作台设计原型](../prototypes/evidence-workspace.html) 可作为本地HTML打开，按钮不保存或发送；启动脚本不提供8124端口的原型服务。真正使用应进入已启动网站的 `/reports/<报告ID>`：普通本地通常为 3000 端口，独立合成验收为 3001。端口与服务是否在线以当前启动输出为准。

### 一条缺口的操作顺序

1. **看当前状态。** “有证据支持”“部分支持”“待补材料”“未覆盖或需复核”统计本报告已保存的要求状态，不是能力分数或录用结论。已驳回/修正、规则未覆盖与未知状态单列，不算有证据支持。
2. **核对来源。** “优先补齐的证据”按岗位权重降序展示最多 3 项，权重相同时保留报告顺序。点击“核对来源与逐项解释”，查看对应要求、引用原文和信息缺口；其余要求仍在下方“逐项证据”。
3. **打开补证任务。** 点击“从这条缺口开始补证”定位到同一要求的补证入口并展开。系统读取已有任务；已有任务时点击“打开这条缺口已有补证任务”，沿用固定基准，不重复创建。没有任务时，填写缺口类型、具体交付物、执行步骤和核验条件，再点击“保存并进入补证”。点击工作台链接本身不会保存任务。
4. **核对 AI 草稿。** 如果当前报告有合格的 AI 建议，可以补入空白项，再自己修改。已有手写内容不会被替换。没有合格建议、建议过期或任务草稿被警告时，手动填写即可；程序校验不代表人工认可。
5. **补证并上传新版。** 按任务约定准备实现、运行记录或本人贡献说明，使用任务中的上传/材料入口新增版本。回到任务，选择新版简历与项目，再点击“保存本次材料选择”。单纯上传或改选不会自动改变已保存的分析材料；改选目标岗位也需要重新保存。
6. **主动生成并等待新报告。** 在任务中按页面提示发起分析、确认发送范围，等待处理完成。首次打开工作台、查任务和查历史对比都不会触发模型；主动分析是否调用真实模型取决于运行配置、发送同意及预算。失败时以任务页错误与重试提示为准。
7. **逐项核对变化。** 任务完成后查看新报告及任务中的基准对比；报告页“查看版本变化”定位到“证据变化与补证进度”，再点“与上一份报告对比”读取已有结果。这个报告页对比对象是同岗位最近一份更早报告，未必等于某任务的固定基准；要核对任务本身的闭环，请使用任务中的对比。

### 逐项证据现在如何查看

默认展示要求状态、简短解释与缺口。“查看判断依据与 AI 解释”“查看来源证据”“本人核对记录（可选）”默认收起，需要时再展开；点击引用会自动打开对应来源。本人核对是对 AI/规则证据的意见记录，不是独立认证，不操作也能继续补证；驳回或修正可能暂停此报告当前等级，原投递快照不变。

### 数据边界与常见疑问

| 情况 | 应如何理解或处理 |
| --- | --- |
| 上传新版后报告没变 | 旧报告固定；保存新版材料选择后主动生成新报告 |
| 显示有证据支持 | 表示当前材料状态，不证明运行成功、测试质量或独立贡献 |
| 工作台没有优先缺口 | 不等于全部能力已认证；继续核对未覆盖/需复核项和来源 |
| 已有补证任务 | 打开原任务；需要新一轮补证时从新报告开始 |
| 读取任务失败 | 在对应入口重试读取，不反复点击创建或重复提交 |
| 没有更早报告 | 报告页不能展示历史差异；先完成一次补证并生成新报告 |
| 企业是否会收到新版 | 不会自动收到。原投递快照保持固定；任何新的分享或回复仍需主动操作 |
| 是否覆盖原简历 | 新增材料版本；旧报告引用的版本与原投递快照不被工作台替换 |

投递授权说明、撤回限制、第三方参考与模型降级提示继续保留。投递操作必须另行确认授权；已下载副本不能通过平台撤回追回。工作台不自动发站内回复、邮件或创建投递。

### 当前验收与下一轮优化

2026-10-12已补验学生报告的逐项默认折叠、点击引用展开来源及390px布局；账户菜单的桌面、390px/320px、键盘打开与Esc关闭，以及撤回后重新投递已有对应实测。证据见[展示验收](../evidence/20261012-demo-disclosure/README.md)、[账户菜单验收](../evidence/20261012-student-account-menu/README.md)、[重新投递验收](../evidence/20261012-application-resubmission/README.md)。这些不代替新增补证任务全链路的320px或键盘复验，也不代表独立语义认证。

后续优先合并工作台与“下一步补证计划”的重复入口，并明确区分“任务固定基准对比”和“上一报告对比”。沿用原站配色，不引入第二套主题设置。演示步骤使用[功能演示文档](功能演示.md)，原型及长日志按对应证据查阅。

## 常见启动与登录问题

| 现象 | 处理 |
| --- | --- |
| Docker Engine is unavailable | 双击 Docker Desktop，等引擎就绪后重新执行启动；失败脚本不会自动续跑 |
| 找不到账号 | 自己注册的账号使用自行设置的密码；演示账号按本页环境表找文件，Local 不创建账号 |
| 登录尝试过于频繁 | 升级0020并启用新版后，同一邮箱＋来源默认5次/5分钟；成功登录清除该组合计数。同一来源另有120次/分钟总上限（成功请求也计入）。按页面秒数等待，不反复点击；不会修改账号停用状态。校园网共享出口可能共用来源额度 |
| 邮箱或密码错误 | 先确认注册时的端口和运行；账号可能在另一个库。再核对邮箱、密码和凭据来源，修改 JSON 不是重置密码 |
| 页面看不到新功能 | 确认源码已同步到实际 frontend stage，并重新构建；旧服务需按身份停止后启动 |
| 端口被占用 | 按自有运行记录停止原服务，不按端口任意结束进程 |
| 记录父进程已退出，但可能仍有子进程 | 脚本保留运行记录并拒绝猜测停止；保留日志，核对残留进程身份后再恢复。不要删除记录或仅凭旧父PID强杀 |
| 已上传新版但报告没变 | 报告固定；保存新版选择后主动分析生成新报告 |
| AI 超时或限额 | 查看任务记录和降级标记，不把规则兜底误当真实 AI 成功 |

本机始终使用 `127.0.0.1`，不要与 `localhost` 混用会话。日常日志和进程清单位于 `backend/.tmp/local-run/`；凭据、API Key、真实简历与上传目录不提交 Git。
