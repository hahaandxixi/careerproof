## 确定缺陷（本次改动引入：task_boundaries.py）

按 review-agent 格式（P0 缺失，无发布级阻断）：

**[P1] 「能否」未列入 _UNCERTAIN，核验计划被误拒 — task_boundaries.py:14**
最小对：既有允许例「核对小组报告**是否**证明本人负责模块」通过；「核对小组报告**能否**证明本人负责模块」被拒（unsupported_attribution=True → "substitutes group or reference material"）。两词在本句型中语义等价，属遗漏非取舍。

**[P1] 本人具名小组仓库提交记录被当作群体产物误拒 — task_boundaries.py:7-13**
前次审计明示「不拦'小组项目中本人具名提交记录'」。实测：「列出**小组项目中**本人具名的提交记录」放行；「补充**小组仓库中**本人具名的提交记录作为个人贡献证明」被拒。来源枚举 `(?:小组|团队)(?:项目)?(?:报告|成果|产物|作品|仓库)` 使 小组仓库 命中而 小组项目 不命中，同一合法证据类别仅因词形不同结果相反。

**[P1] 本人旧日志/版本演进被误当冲突 — task_boundaries.py:44-56（冲突检查无时间/版本豁免）**
- 「FastAPI**未实现的部分已由本人补全**，含过期分支。」与「FastAPI已实现，支持过期与并发。」→ 判冲突。行首最左解析只取 未实现，丢弃 同句 已由本人补全，单人演进成两人矛盾，普通验收计划被拒（C1b）。
- 「导出功能尚未实现，**2025年1月旧记录**。」与「导出功能已实现，支持CSV。」→ 判冲突并拒计划（C2）。`旧版|历史|此前|曾经` 跳过仅存在于 contracts 的旧日志守卫，冲突检查内无任何对应豁免；直接违反边界卡约束2「不同版本或已明确解释的演进不得误当冲突」。

**[P2] 句号拆句使「声称+拒绝采纳」豁免失效 — task_boundaries.py:36-39**
最小对：「声称小组报告可证明本人贡献**，**此声明待核验，不作为事实」通过（既有允许例）；把逗号换成句号——「声称小组报告可证明本人贡献**。**此声明不作为事实，仅保留待核验。」被拒。拒绝采纳声明存在，只因落在下一句。

**[P2] 否定词距动词超 25 字窗口即失效 — task_boundaries.py:31-33**
「写明小组项目成果**不能**在缺少本人具名提交记录、模块分工表、时间戳与代码评审意见的验收流程中证明本人负责后端模块」被拒（否定词距 证明 36 字、无逗号重置窗口）。明确保留边界的合法否定计划。
