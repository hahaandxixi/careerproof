## 结构与行为

之前：`ReportDetail` 中逐项阅读区和 `ReportActionLayer` 各生成一套要求入口、统计和补证导航；下一步容易被来源明细淹没。

现在：匹配概览 → 同源状态筛选 → 一套要求列表 → 所选要求的缺口与保存建议 → 来源核对 → 明确创建或打开补证任务。`ReportEvidenceWorkspace` 复用 `ReportRequirementReader` 管理筛选与选择，`RequirementActionPanel` 读取同一份 `report.items`、`report.actionPlan` 与已校验建议，不重新生成建议。

- 本次真实报告五项要求，四项支持、一项Redis待补；默认选中Redis。状态统计沿用 `evidenceWorkspace`，零数量仍明确显示；支持项存在上下文提示时保持支持，提示直接可见。
- 支持项先显示保存结论和证据核对入口；待补/部分支持项直接显示保存建议与主要补证按钮；未覆盖或本人驳回/修正项保持独立的核对语义；缺少计划时不补造步骤。
- 所有要求面板持续挂载，切换仅改变阅读界面。原要求、引用、规则来源、补证锚点均保留；技术原文完整保留在来源区域，UUID/文件路径不进入扫描摘要，不改写原始片段或存储身份。
- 仅有效且未整体降级的AI内容可作建议或判据解释。无效AI、旧上下文和本人驳回/修正均有保护；整体降级提示继续直接显示。
- 复用 `GrowthTaskStart` 原有已有任务查找、明确保存和重入保护；本轮只调整入口文案及层级。补证、上传新版与生成新报告不覆盖旧报告或企业固定快照；投递确认入口保留。
- 后端、评分、API、数据库、授权、提示词及Agent流程未修改；独立副本复用既有依赖，没有安装或升级依赖。
