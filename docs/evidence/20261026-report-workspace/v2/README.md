## 数据来源和优先级

- 当前缺口使用已校验 AI 缺口或保存的 evidenceLevelGap/actionPlan 缺口；无数据才用保存结论，不据未检索到引用认定未实现。
- 行动步骤优先级：用户打开入口并成功读到的 `GrowthTask.plan` → `validatedGrowthAdvice` 接受的结构化 AI 计划 → 明确标注的通用核对步骤。已有任务计划由同一次 API 回执传回行动区，启动器不再重复展示一份。
- 结构化计划保留交付物、步骤和核验条件；前四步直接显示，其余按需展开。人工已保存计划不被当作系统执行结果。计划待复核、上下文不完整、AI未采用等警告直接可见。
- `actionPlan` 的原始建议、缺口与 rules/review/ai_suggestion 来源仍在“查看报告原始建议”，不改写历史输出。AI 计划仍受原有效性、上下文和整体降级保护。
- 通用提示不推断文件名、代码是否存在、测试是否运行，也不自动填表或保存任务。**后端规则行动计划仍可能笼统**；这属于后续任务 A 的建议质量问题，本轮没有改 Prompt、Agent、RAG 或评级。

## 已有任务、编辑与身份边界

- 无任务：先成功查得 null 才显示新建表单；明确提交才创建。重复提交仍受原锁保护。
- 已有任务：展示原保存计划，继续原任务；完成并生成新版时提供结果入口。旧报告、材料版本及投递快照保持原样。
- 读取被拒绝/暂时失败：显示原错误与重试，不把失败当作无任务开放新建。
- 迟到回执：旧 report/requirement 的结果不覆盖新目标，也不回传旧计划给行动区。页面仍复用 AccessGate 的 user.id 重挂载边界，未改权限或私人草稿逻辑。
- 所有要求面板继续挂载；切换筛选和展开来源不触发模型或保存。未保存内容不承诺跨刷新恢复，本轮未增加浏览器长期缓存。

以上任务分支由生产组件的受控 hooks/event handlers 和 API promises 验证；**不是新的一轮真实数据库权限或浏览器端到端验收**。
