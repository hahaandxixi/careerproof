## 原问题与新流程

原先“开始补证”打开查找/创建任务后，仍要求填写类型、交付物、步骤和核验条件；最突出入口仍引导用户管理一份计划。

现在：查看要求与缺口 → 读保存建议及标明来源的通用指导 → **复制补证建议 / 完成后上传新版材料** → 在自己的开发环境改进 → 材料中心上传 → 到原岗位明确选版本并主动分析 → 在新报告读取真实变化。

不保存任务也能获得指导、复制和上传。支持项的操作仍放在“材料有更新？”次级入口。规则未覆盖、本人驳回等状态不改写成需要补代码。原单一要求列表、来源主入口、六类状态、固定版本和历史评级保留。

## 指导与复制的真实来源

- `report-follow-up.ts`统一页面通用步骤与复制内容；它们是操作提示，不是新AI建议生成器。
- 复制文本含岗位要求、保存缺口/待核对、有效来源的原始行动建议、保存计划的步骤/交付物/条件（确有可靠数据时），以及版本、未独立执行和本人贡献提醒。拒绝、降级或过时上下文的AI建议继续由原校验排除。
- 无具体计划时不编造文件名、Redis实现、测试成功或交付物。页面给出条件式通用材料类型：相关工程文件、测试/已有执行记录、必要说明；复制时不将这些类型冒充保存的具体交付物。
- 复制只调用剪贴板，不调用API或保存任务；成功回执后才显示已复制。失败时提供只读文本手动复制。旧要求的迟到回执不能更新新要求状态；账号切换沿用原有身份卸载边界。

Redis仍保留原报告的泛化建议，并补充“检查已有实现—已有实现先定位材料—尚未实现再在自己的环境完善—有新增才上传并主动分析”。没有认定Redis不存在或已经实现。保存规则建议偏泛仍是后续任务A的内容质量问题；本轮未改Prompt、Agent、RAG或评分。

## 上传与接续

- 上传链接只携带UUID格式限制的sourceReport/sourceRequirement提示，没有自动选择、保存或分析指令。
- 材料页`ReportUploadReturn`使用原有受权限限制的getReport读取原报告，确认要求存在后才显示返回原要求、到原岗位选版的入口。读取失败/拒绝/要求不存在时不提供业务跳转；支持重试，旧回执不能覆盖新上下文。
- 不从版本ID猜项目ID、不自动关联新版。用户明确选择自己的原项目上传新版，或按实际需要新增材料。上传处理、白名单、大小、幂等、配额和关联逻辑沿用原实现。
- “本次上传已保存”不表示解析完成。提示先核对处理状态，再到原岗位明确选版并主动分析，不把新版放入自动选择参数。
- 新报告复用“同岗位最近更早一份报告对比”，不假称固定比较当前来源报告；期间有其他报告时须核对基准。需要固定基准者仍可选原补证记录。
- 原growthTask返回路径优先保持原协议，不额外请求报告接续。未增加API或更改旧任务状态流转。

## 可选记录与历史兼容

“已有记录与自定义计划（可选）”降为次要入口。展开并点击后才查已有任务；有记录则查看原计划/原ID，有新版则查看结果，不创建第二条。

无记录时，有完整有效AI计划可明确点击“确认记录这条建议”，按原合法GrowthPlan保存相同要求、类型、交付物、步骤和条件，无需重填三个文本框。明确点击才写入，不标记完成、不调用模型；重复点击仍受共享锁保护。

只有泛化建议时不填造必填字段。用户可直接跳过；旧完整表单保留在默认收起的“自定义补证计划（高级，可跳过）”，供确实需要固定基准/自定义计划的人使用。读取失败不当作无记录，保存失败错误显示在收起区之外并可重试。

旧`#growth-*`目标移到可选折叠内部，ID不变，原锚点恢复逻辑仍能展开祖先。原要求/引用锚点、任务URL、材料版本、企业快照均保留。折叠不卸载编辑表单，不新增长期浏览器缓存。
