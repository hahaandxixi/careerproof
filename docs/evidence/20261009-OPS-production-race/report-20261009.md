## 编排关键点（对照卡片与 Codex 风险修正）

- 屏障设在 `AttemptService.prepare_for_send` 进入原函数之前：两链入口预检事务（claim/读）此时已 commit，无 User/Task 行锁；不在 `_live_identity` 事务内设双方屏障（会人为死锁）。原事务/锁保持原样，未 commit/跳过任何原调用，未 mock 预算准入结果，未顺序跑两链。
- `_live_identity` 包装：两方各自先登记 PostgreSQL backend pid，双方登记齐（有界等待、此时不持行锁）后才进原锁调用；先取得 owner User 行锁的一方以 `pg_blocking_pids` 证实另一方 session 已真实等待在该锁上，才继续原 reserve/commit——胜方 commit 前两个原 prepare 均已创建独立 session，且从未"等胜方 prepared 后才放行败方"。
- 模型信号量：按 Codex 修正改为 `settings.ai_model_concurrency=2` 并复位 `_MODEL_SEMAPHORE/_MODEL_SEMAPHORE_SIZE` 交由生产惰性重建，断言重建容量为 2（原"直接替换 Semaphore 对象"做法会被配置不匹配重建回 1，已废弃）。
- Task 行探针按 Codex 修正改为严格单发 NOWAIT：未知锁一律失败，不再设"heartbeat 豁免重试"（NOWAIT 失败后事务已结束，pg_blocking_pids 快照仅尽力取证，不作放行依据）。
- 事件时间线与两 session backend pid 以 `RACE-EVIDENCE` 打印留档；竞争重叠证据来自 `pg_blocking_pids`，非 sleep 推断。所有等待有界，finally 释放事件并收回自有协程，不杀服务。
