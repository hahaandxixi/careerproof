## 统一 rubric

每例分别评价四项，不合并成单一平均分：

| 维度 | 通过的最低条件 | 不通过示例 |
| --- | --- | --- |
| 引用支持结论 | 每个关键结论都有对应引用；引用原文能直接支持该结论 | 引用只证明导入/声明，却推出运行成功 |
| 空实现/矛盾识别 | 指出空函数、占位返回、导入未使用、前后矛盾或未运行 | 把只有路由声明写成完整可用接口 |
| 运行/贡献/能力表述 | 不把代码存在写成运行成功；不把仓库内容写成本人贡献 | “已上线”“已测试”“独立完成”无证据 |
| 建议具体可执行 | 指出缺什么证据、如何补、验收条件是什么 | 泛泛建议“补充材料”“优化代码” |

每项在复核表中分别填写结论和理由，注明对应原句、文件/行号；没有空实现或矛盾时说明是否适用。每项可记：

- `通过`
- `不通过`
- `无法判断`（必须写原因）

关键错误（例如伪造运行结果、引用与结论无关、把他人工作写成本人贡献）单独列出，不被其他项平均掩盖。

## 历史字段的中性定义

以下依据2026-10-18固定请求中的 `skill-rubric-v3`、`evidence-trust-v29-implementation-first-plan` 提示词及同批次返回合约整理，不以当前实现替代历史规则。具体操作与任务条件以当时发送的对应技能rubric为准。

| 字段 | 表示什么；不表示什么 |
| --- | --- |
| `relevance` | 引用中有与该条岗位要求直接相关的可见内容；名称相似不够。相关线索不自动证明实质操作或完整任务。 |
| `operation` | 引用展示实质操作或非空处理逻辑，只有声明、依赖、函数名或占位不够。缺少完整任务的其他环节，不能单独用来否认可见操作；操作存在不证明已运行或本人完成。 |
| `task` | 完整上下文展示与要求对应的输入、实质处理和输出，具体条件按对应技能rubric；要求包含测试时还需核对测试请求与结果断言。源码覆盖完整不自动等于完整任务，更不等于实际执行成功。 |
| `level` | 本次模型对实践材料的1—3级初评，等于从relevance、operation到task依次连续成立的项数，后项成立须前项成立，并受发送时上限约束。不是人的能力等级、录用结论或人工评审结果。 |
| `null` | 在 `rating.level` 中表示未给出可成立的初评级别；无成立项或发送上限为null时应为null。不是0分，也不证明没有能力。其他字段的null按各自含义解释，不能与人工结果尚未填写混同。 |
| `confidence` | 历史合约限定的该项分析0—1置信值，可视为模型自报把握程度；不是经校准的正确率、人工认可率或能力/录用概率，高值不能替代引用核对。 |

`rating_ceiling` 是固定请求给出的评级上限，不是应得等级；上限为null时不评级。各判据仍须依据当前允许引用的材料分别核对，不能把上限或模型自述当作答案。历史记录和第三方参考不能替代当前个人材料支持评级，静态代码不证明运行或本人贡献。

三个产品判据用于组织材料初评；上面的四个人工评审维度用于独立检查整个输出的引用、矛盾、夸大和建议。两者不一一对应，不按字段数量换算人工结果，也不因level或confidence较高而免评。
