# 受控 Function Calling 补检索

## 目标

模型在正式证据分析前可判断是否需要补充一条证据。该能力只用于弥补上下文不足，不改变规则分数，也不允许模型访问网络、运行代码或读取任意文件。

## 执行边界

1. 初始上下文为每项要求最多两条证据。
2. 模型只能调用一次 `retrieve_more_evidence`，参数只有 `requirement_id` 和 `query`。
3. 服务端校验要求编号必须属于当前报告。
4. 执行器只在当前上传版本已索引的候选片段中检索，最多返回一条新证据。
5. 新证据继续经过路径、行号、原文和评级上限校验。
6. 非法工具名、多个调用、未知要求或非法 JSON 会被拒绝，报告继续使用已有证据生成。
7. 网络错误、鉴权错误和服务过载仍触发规则降级，避免模型调用拖垮主链路。

## 可追溯记录

报告元数据的 `modelToolCalls` 记录工具名、要求编号、查询、结果数量、作用域和新增引用编号。作用域固定为 `current-upload-index`。SSE 会显示规划、执行、拒绝和降级阶段。

## 能力声明

这是一次服务端白名单工具调用，不是可自由行动的通用 Agent。它证明系统能让模型提出有限检索请求，并由本地代码在明确边界内执行和校验。
