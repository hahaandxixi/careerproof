# 本地生产模式复现

适用 Windows PowerShell。需要 Python 3.12、Node.js、npm 与已启动的 Docker Desktop。下列路径按实际解压位置调整。仓库脚本不自动购买服务或写入 API Key。

## 首次安装

在项目根目录（含本文件上一级 README 的目录）执行：

```powershell
Set-Location backend
if (!(Test-Path .env)) { Copy-Item .env.example .env }
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Set-Location ..\jianli
npm ci
Set-Location ..
.\Start-Local.ps1 -CheckOnly
.\Start-Local.ps1 -RulesOnly
```

脚本会等待 PostgreSQL、迁移到最新 schema、构建 Next.js、后台启动两个服务并验证健康检查。默认仅监听 `127.0.0.1`。脚本中任一步失败都不报告启动成功；已有服务占端口时先处理原服务，不自动杀掉未知进程。

默认端口：前端 3000、后端 8000，数据库端口见 `backend/docker-compose.yml`。启动前按 `backend/.env.example` 配置数据库。若首次迁移报连接错误，检查 Docker 就绪与 DATABASE_URL，不要输出包含密码的完整配置。

## 演示流程

1. 访问 `http://127.0.0.1:3000`，按 `demo/README.md` 使用合成材料。创建企业账户、组织及含 Python/FastAPI/PostgreSQL/pytest/Redis 的岗位并发布。
2. 学生账号上传合成简历和项目 ZIP，等待解析完成，先在预览中核对原文件。
3. 选择这两个材料版本，生成报告。在任务页观察进度和最终七步记录。
4. 报告展开 FastAPI、PostgreSQL、pytest 来源，检查函数返回值、参数化查询和断言。依赖声明与局部上下文的限制应清晰可见。
5. 保存人工复核备注，刷新确认分数、版本和备注保留。
6. 停止：`.\Stop-Local.ps1 -Database`。只停止本脚本记录且进程身份匹配的本地进程；数据库数据卷保留。单用 `Stop-Local.ps1` 保留数据库运行。

## 启用千问及验收

按后端 README 在本地 `.env` 配置已有千问服务；不要把 Key 写进命令、截图或提交资料。去掉 `-RulesOnly` 重新启动。`-RulesOnly` 仅临时覆盖进程环境，不修改 `.env`。

用户已确认当前无百炼免费 token，先保持 `-RulesOnly`。仅在核验可用免费额度或获得费用授权后，才启用模型及真实评测；不能为了处理 `Arrearage` 默认让用户充值。“服务可启动”不能替代“模型语义验收”。

## 验证范围

本轮在现有依赖环境完成生产构建与脚本真实启动、健康检查和浏览器验收；另以随机隔离 PostgreSQL schema 验证 12 项集成测试。未在一台全新电脑重装全部依赖，不能把这些检查称为新机器复现已通过。最终提交前应由另一位成员按本页首次安装流程执行并保存日志。

日志与进程记录在 `backend/.tmp/local-run/`，该目录被 Git 忽略。端口被占用、Docker 未就绪、依赖缺失都应先处理明确错误。不要为了复现删除既有上传材料或数据库卷。

本轮停止脚本的时间类型比对问题已修复，但重测被自动审批额度限制挡住，服务尚未确认停止。请手动执行停止命令后检查 3000/8000 端口；不要将其记为停止验收已通过。
