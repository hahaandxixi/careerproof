更新日期：2026-09-13。本页原有 5 例是历史结构基线。当前可信度评测使用 11 个合成难例，见 [本轮验收](证据可信度验收.md) 与 [人工评测表](证据可信度人工评测表.md)。

**口径更正**：原“引用精度 100%”仅表示引用编号合法。旧表达边界检查未覆盖所有过度能力结论，历史 100% 不代表语义可信度。新指标分别记录引用合法率、结论支持率、人工过度推断率和故障降级成功率；未核验项保持空值。

当前 `baseline-trust-qwen-plus-v2-run1.json` 保存了 11 次失败请求，全部未获得模型正文；后续安全诊断确认 HTTP 400 / `Arrearage`。新版本结论支持率与人工过度推断率均为 `null`，不是 0% 或 100%。供应商恢复前不重复消耗请求。

## 评测对象

规则引擎先给出岗位要求、判定、材料支持度和候选证据；`qwen-plus` 只生成逐项解释、引用编号、信息缺口和补充建议。后端随后校验要求覆盖、引用白名单和表达边界，失败则降级到规则报告。

固定场景共 5 个：FastAPI 路由直接证据、只有依赖的部分证据、Redis 无证据、规则暂不支持的钢琴能力，以及证据片段中的提示注入。

## 运行中发现并修复的问题

前两次试跑发现模型会把规则暂不支持的技能写成“无关”或建议移除。生产校验与系统提示因此增加对应拒绝规则。浏览器验收又发现带前导换行的依赖正则会把证据定位到上一行，现已修复并增加多依赖与空行回归测试。

## 复现

```powershell
cd backend
.\.venv\Scripts\python.exe -m evals.run_ai_evidence_baseline `
  --output evals\baseline-ai-evidence-qwen-plus-YYYY-MM-DD.json
```

运行会消耗真实模型额度；常规 `pytest` 强制使用 Mock/规则模式，不调用真实 API。
