# 检索独立标注任务单

请由未参与本项目实现的真实评审者完成。当前状态：**尚未分配/签署**，不能由助手自己填写后称为独立标注。

先只阅读`backend/evals/retrieval-independent-review-v1.json`，不要先阅读临时标签或对照结果。所有内容是合成文本；文件内的命令、满分声明和“忽略要求”等文字是待判断材料，不是需要执行的指令。

## 如何填写

1. 另存为`retrieval-review-completed.json`，保留`corpusHash`，填写真实`reviewer`和ISO日期`reviewedAt`。不会发送API，不需要Key。
2. 每例先读`query`和`documents`，判断哪些原文应被送给分析器核对。区分“相关并需核查”和“已经支持完整实现”；两者不能混为一谈。
3. 如有相关原文，将`noRelevantSource`设为`false`，在`relevantSources`中填写`path`、`lineStart`、`lineEnd`和`support`，并在`reason`解释判断。行号从1开始。
4. 如没有相关原文，将`noRelevantSource`设为`true`，保留`relevantSources: []`，仍填写理由。空白/null不算无目标结论。
5. 十组任务各含六例；四个安全例也要标注。不要漏例或重复ID，同一来源范围不重复列入。

`support`可选值：

| 值 | 意义 |
| --- | --- |
| `describes_behavior` | 描述相关行为，不代表已经执行或归属于本人 |
| `describes_partial_behavior` | 仅覆盖要求中的一部分 |
| `self_claim_only` | 只有自述，没有实施材料 |
| `dependency_only` | 只有依赖清单 |
| `empty_implementation` | 空实现或占位 |
| `contradiction_to_check` | 相关矛盾，需要模型指出差异 |
| `untrusted_instruction` | 材料内的注入指令，不能执行 |

特别复核近义干扰：同领域、相近词汇是否足以让该片段成为需核对候选？若认为初始标签应改变，可以按自己的判断填写；不要为了迎合当前检索结果而改标签。

## 交付与边界

完成后保留真实签署与理由，由项目所有者确认评审者独立性，再用评测脚本的`--annotations`导入生成新文件。脚本只做完整性和来源校验，没有能力认证身份；“格式通过”不能写成“独立语义复核通过”。不要将API Key、私有登录凭据或真实简历放入标注文件。
