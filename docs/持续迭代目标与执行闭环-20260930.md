# CareerProof 持续迭代目标与执行闭环

更新日期：2026-10-02。用途：指导后续每次运行实际测试、修复和改进本项目。本文记录执行目标与验收方法；外发、付费调用、发布及推送权限仍以用户在会话中的实际授权为准。

## 持续目标

持续完善 `D:\jbcode\web ai\jianli`，使学生能从具体岗位要求出发，核对证据与缺口，采用可编辑的 AI 补证计划，完成具名材料补充、生成固定版本的新报告，并逐项解释证据变化及职业规划变化；使企业能基于有效投递快照查看证据、形成有引用的核验问题、与学生沟通，并通过通知回到正确对象。每轮以可复现问题和真实操作阻碍确定工作，完成发现、修复、回归、页面复验、记录和接力。

AI 深度通过对用户任务的帮助衡量：建议是否具体、引用是否支持结论、草稿是否可执行、变化解释是否准确、失败时能否继续完成工作。每个新增 AI 能力都应接入明确操作、保存来源和版本、允许用户编辑或复核，并有可重复的质量评测。

## 每轮执行顺序

1. **确认当前状态。** 读取本文、文档导航及与当前任务有关的最新验收记录；检查 Git 差异，保留已有改动与未跟踪材料。核实数据库、前后端健康和当前构建。服务失联时先诊断运行状态，用现有安全脚本恢复，随后判断页面功能。旧文档中的版本、进程和测试数量只是历史证据。
2. **选择一条完整用户流程。** 先处理权限或数据错误、流程断点，再处理 AI 建议质量和操作效率。选定目标后写明起点、账号角色、材料版本、操作步骤、预期结果和失败表现。使用独立合成账号及具名合成材料。
3. **复现并修复。** 从页面和 API 核实故障，查明前端、后端、任务、缓存或模型输出中的原因。修复受影响链路；涉及状态或权限时补充能重现原故障的回归用例。普通样式改动以渲染检查为主。
4. **验证用户结果。** 先跑相关测试，再按改动运行类型、Ruff、数据库专项或生产构建。修改跨服务流程、报告契约或授权时运行相应完整回归。用当前生产页面复验受影响流程，检查刷新、返回、重试、空态、重复操作及390px布局。检查已经持久化的结果，确保后续步骤能继续使用它；对旧报告、旧任务和缓存快照至少做一次“重新读取”核验，确保新校验不会只保护生成瞬间。
5. **记录并接力。** 将实际变化、复现步骤、测试命令与结果、页面证据、失败和未验证项写入验收记录，更新导航和下轮优先级。每项使用“已实现／已程序验证／已页面验证／待真实模型验证／待独立语义复核”中的准确状态。只有覆盖了整个流程才能声称该流程通过。

## 用户流程与必查边界

| 流程 | 每次推进必须证明的结果 | 需要抽查的异常 |
| --- | --- | --- |
| 学生材料到报告 | 明确选择简历及作品版本；解析、预算预览、任务状态、报告、同项引用与本人复核一致 | 未选择材料、解析失败、模型不可用、过期会话、重复提交、刷新与中断恢复 |
| 缺口到补证 | AI 建议与缺口、引用一致；可编辑任务记录固定基准；补充材料与任务关联；新版报告逐项对比可解释 | 同项已有任务、尚无实现却只要求日志、重复提交已展示源码、无内容变化、旧建议后来被驳回 |
| 补证到职业规划 | 带入明确新版材料；解释材料变化与岗位变化，呈现新增支持、未解决缺口和不确定性 | 跨岗位误比、旧材料混入、岗位变更、把档位变化直接归因为能力提升 |
| 企业筛选与核验 | 只读取有效投递授权的固定报告和来源；核验问题有同项引用；沟通内容定位到正确投递 | 他人企业访问、撤回、过期快照、空引用、重复生成、旧响应覆盖当前投递 |
| 通知与沟通 | 通知计数、筛选、分页、已读、对象跳转与业务状态一致 | 最后一页变空、未读并发变化、旧通知、对象已撤回或删除、会话切换 |

企业原投递快照必须保持固定。新版材料、新报告、任务计划和本人复核变化均不能悄悄替换企业已经获授权的旧快照；撤回后所有企业读取入口均须重新核验权限。

## AI 深度的推进顺序

| 优先级 | 具体成果 | 验收方式 |
| --- | --- | --- |
| P0 | 修复错误引用、错误授权、旧状态污染、无法继续的任务和误导性补证建议 | 故障先复现；同用例修复后通过；相关权限、版本与并发反例通过 |
| P1 | 验证当前逐项结构化任务草稿（v28继续保留v27能力），改进交付物、步骤、核验条件及缺口类型 | 合成样例覆盖无实现、部分实现、运行缺证、贡献缺证、矛盾材料；人工逐项判断能否执行、能否核验、是否重复已有材料；离线契约探针必须全通过 |
| P1 | 完成“缺口→任务→新版材料→新报告→逐项解释→规划变化”的生产页面复验 | 固定两版合成材料，记录任务、两份报告与对比；企业旧投递快照和撤回边界另行检查 |
| P2 | 加深企业核验问题与学生补证结果的关联 | 问题明确指出需核实的内容和来源；学生能定位回答所需材料；人工沟通与 AI 草稿可区分 |
| P2 | 建立任务草稿和变化解释的固定质量评测 | 保留成功和失败样例、提示版本、用量及判定理由；覆盖多个职业方向；程序校验和独立语义复核分别记录 |
| P3 | 优化高频操作的搜索、筛选、可访问性、移动布局及等待提示 | 以实际步骤数量、错误恢复成功和页面可读性确认改善 |

新增模型功能优先复用当前报告、引用、版本与受控工具。统一使用当前 DeepSeek 路线与既有预算、脱敏、缓存和失败降级流程。程序引用合法只证明来源约束通过，模型结论与任务质量需要语义评测。真实 API 调用按现有授权的材料、目的地、次数和预算执行；一次合成调用授权不能扩展成持续消费权限。
