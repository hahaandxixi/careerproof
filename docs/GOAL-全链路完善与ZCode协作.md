## 目标和本轮完成条件

使学生可以从一条真实可定位的证据缺口或企业核验问题出发，创建补证任务、上传新版、生成新报告，并逐项解释变化；企业原投递快照保持不变。企业能够筛选、查看、下载、人工回复和处理撤回；通知正确连接两端，过期响应和旧入口不能恢复失效授权。AI建议必须有来源、可执行、可核验，失败时有明确降级和恢复路径。

本轮必须交付下列四项，并修复验收中发现的阻断缺陷：

| 阶段 | 可观察的完成结果 | 必需证据 |
| --- | --- | --- |
| E2E-01 隔离环境 | 同一产品可在独立数据库、存储、端口和构建目录重复运行，强制Mock；不写业务库；重跑不重复投递/通知 | 目标拒绝测试、幂等测试、运行清单、实际启动与隔离审计 |
| E2E-02 企业闭环 | 慢响应不覆盖当前报告；通知筛选可定位；失败回复保留可编辑草稿且不自动重发；下载确实落盘；撤回A后A不可访问、B仍有效 | 可控延迟/失败注入、请求与状态顺序、下载哈希、快照哈希、桌面/390px页面证据 |
| E2E-03 学生闭环 | 问题/缺口→任务→补证上传→新版报告→逐项变化解释可走通；刷新可重读；旧投递不被新版覆盖 | 合成材料前后版本、原要求/引用/任务关联、两端操作步骤、旧快照前后哈希 |
| AI-01 离线质量 | 覆盖无实现、部分实现、缺运行证据、缺贡献证据、矛盾材料、第三方参考；拒绝无引用和错误归因，建议不是重复上传已有源码 | 可复跑样例与契约、正反例、失败与降级测试、已验/未验分类 |

完成判定：四项均有签收证据，阻断问题已修复复测；适用的阶段全量测试/静态检查/生产构建通过；有界成果已由Codex本地提交，任务清单与当前接力一致。真实模型质量另列“未验证”，不得把离线完成写成真实模型通过。任一必需项受阻时，本目标仍未完成；交接报告须准确保留阻碍。

## 谁负责什么

| 工作 | ZCode负责 | Codex负责 |
| --- | --- | --- |
| 选题与设计 | 只读调查、最小复现、依赖和下一项建议 | 定优先级、协议、不变量、任务卡和文件所有权 |
| 开发完善 | 简单bug、局部UI、回归、测试脚本、合成夹具；按批准范围顺序实现 | 授权/并发/固定快照/用量/AI事实归因的设计与最终裁决 |
| 自动测试 | 目标、受影响模块、阶段全量、Ruff、类型、构建；保存脱敏原始输出及退出码 | 审计证据，独立复跑1–2项最高风险断言；失败或缺证时扩大验证 |
| 页面测试 | 隔离合成账号跑完整首验、故障注入、桌面/390px及截图 | 抽验关键链路，复核撤回、下载与旧快照；裁决工具或证据缺口 |
| AI融合 | 实现具名引用、人工采纳、结构化步骤/交付物/核验条件与离线样例 | 审核可信度和变化归因；核对新增真实模型调用的单独授权 |
| 文档与Git | 新证据包、验收草稿、自审结论；一屏回报 | 正式状态终审、一项签收一个本地提交、集成及交接；不自动推送 |

Codex不可用时，ZCode仍可完成批准范围的实现、测试和证据，但不能冒充Codex独立签收。简单工作应优先交ZCode，不为消耗额度制造无用任务，也不因节省Codex额度省略高风险独立检查。

## 每轮执行协议

1. 先读[当前接力](当前接力.md)、[任务清单](任务清单.md)、[固定约束](ZCode协作固定约束-20261004.md)。核对嵌套仓库的status、HEAD、分支、stash和实际服务；保留已有未提交成果。旧文档仅作线索，按当前代码/命令/页面证据修正状态。
2. 确认当前任务是否仍在写文件。共享文件与数据库一次一个写入者；已有E2E-01任务须先核对交付和所有权，不能另开任务重写同一文件。Codex同时只读复核或维护其独占文档。
3. 每次选一个验收目标，可一次准备2–3个顺序小项。读[任务卡模板](templates/ZCode任务卡模板.md)，明确触发、预期、允许/禁止文件、测试与停止条件。前项失败先修；高风险下一项等Codex签收。
4. Bug先复现并补有意义的回归，再最小修复；功能先写清用户结果与数据/授权协议。禁止只修改测试期望来掩盖错误。低风险文案修改无需机械增加测试。
5. ZCode顺序运行适用检查并自审。已安装且适用的MCP、插件、技能、review-agent、web-gui-tester可使用；先读取其说明、核对权限与目的地。不可假设工具存在，不自动安装，不把工具失败记成业务通过。
6. 页面故障测试必须真的控制请求延迟/失败并记录顺序。若busy禁止同页切换，就测试用户允许的导航/刷新路径，不调用组件内部方法冒充真实操作。下载要证明文件落盘及哈希，不只看成功提示。
7. 按[证据包模板](templates/ZCode证据包模板.md)写新目录：命令、脱敏完整输出、退出码、文件范围、自审发现/处理、页面步骤/截图/哈希、未验项和下一项建议。回报限一屏，日志不在聊天反复搬运。
8. Codex读关键证据、全文审查安全边界diff并独立抽检。抽检失败扩大验证、退回修正。签收后由Codex检查提交范围、排除凭据和无关成果，形成可回滚的本地提交；不每次保存就提交，不提交未验修复。
9. 更新任务清单及不超过100行的当前接力。阶段集成时由ZCode跑必要全量，Codex审计；同一Next构建目录的构建/类型检查顺序执行。没有新改动或失败时不无意义重复全量。
10. 阶段结束或上下文约80–100k的经验阈值时，准备短交接：HEAD/未提交文件/活动任务与所有权/测试与证据/服务与隔离运行ID/阻碍/下一步。无精确计数时按里程碑交接，不伪造上下文数字；新会话先读当前接力，不重做已验项。

## 额度与运行护栏

- 模型默认优先级：**Start Plan 免费 GLM-5.3 → Start Plan 免费 GLM-5.3-Flash → BigModel 个人 GLM-5.3**。现场核对所属组和对应余额；一个模型报错不代表免费组耗尽。用户2026-10-04追加授权：复杂隔离/授权/并发/跨端协议或免费模型反复修复仍未收敛时，Codex可说明具体难点并提前升级有额度的个人GLM-5.3，无需等免费额度全部耗尽；简单任务继续优先免费。切额度组时按用户要求新建任务，先读已有diff续做，保留部分成果。
- 测试只用明确可丢弃的合成夹具。使用`cp_e2e_*`独立回环数据库、8001/3001和独立存储/构建，强制`AI_EXTERNAL_ENABLED=false`、`AI_PROVIDER=mock`；不改.env或产品DeepSeek默认。数据库创建/迁移/启动先由Codex审查E2E-01目标校验与环境覆盖，再执行。
- 固定约束中的“精确恢复夹具”不表示可恢复撤回：可丢弃隔离夹具撤回后保持真实状态，复跑新run ID；禁止SQL改回状态或删除事件伪造恢复。不得再撤回现有演示投递，不读/复制真实业务材料作夹具。
- Docker或服务缺失时核对项目脚本与目标，按工具实际权限启动本地所需服务，保留数据卷；端口被占用不能杀无关进程。停止脚本只处理自有PID及开始时间匹配的进程。
- 无新增真实DeepSeek调用、真实简历/联系方式、真实收件人消息、远端推送、部署、密钥创建或组件安装授权。隔离合成账号之间的本地站内回复可用于本目标测试；不得扩大到真实人员或外部渠道。用户已有套餐许可不是上述操作的许可。
- P2 RRF stash继续暂停，不应用、不丢弃；保留所有用户和其他任务改动。禁止破坏性reset/clean、删除业务表/数据卷或覆盖式恢复。
- 工具受用户输入、审批、权限或额度阻碍时保存成果并报告具体动作/原因，不绕过限制。可继续不依赖阻碍的只读调查、离线测试或独占文档；不得靠换通道绕过审批。
