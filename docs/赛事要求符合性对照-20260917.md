# 全国高校 AI Web 开发挑战赛要求符合性对照

更新日期：2026-09-17。

本对照只依据用户提供的赛事文字与当前本地仓库核验结果。附件没有官方网页地址，且奖项比例存在互相冲突的版本，因此报名组别、截止时间和最终提交格式仍须在赛事个人中心复核。

## 结论

CareerProof 的选题、Web 形态和主要前端技术栈符合参赛范围，证据约束的求职材料分析也具有真实场景价值。当前属于“可运行作品、尚未达到完整提交状态”：AI 安全与可解释性较强，LLM、工作流和检索增强部分符合；多模态、MCP/Function Calling、完整 Git 历史及正式提交材料尚不符合。

## 当前最优整改顺序

1. **先解决资格与仓库硬门槛**：确认团队、学校和组别；创建独立 GitHub/Gitee 仓库，补团队信息与许可证说明，开始保留真实提交。
2. **补齐 AI 评分主线**：完成固定难例的真实模型语义评测，给出规则、无检索和有检索对照；让模型在受控范围内触发一次补检索工具，形成可证明的 Function Calling/Agent 闭环。
3. **补一个小而真实的多模态点**：优先做简历图片/扫描 PDF 的 OCR 与版面证据定位，避免扩展语音面试等大功能；必须由图像/OCR模型参与，不把普通文件解析称为多模态。
4. **完成浏览器验收与性能证据**：上传→分析→SSE→引用→人工复核→刷新恢复；记录移动端/桌面端截图、Lighthouse 或等价指标和模型不可用降级。
5. **制作正式交付物**：一份不超过 30 页的 PDF、5–8 分钟 1080p 视频、评审演示账号和最终提交清单。在线部署按可选加分项决定。
