# ZCode 协作固定约束

此文件供每张任务卡引用；当前事实仍以 Git、代码和实测为准。任务卡可收窄范围，不能放宽这里的授权和数据边界。

1. Git 根目录是 `D:\jbcode\web ai\jianli`。ZCode 界面的 `jbcode · master` 属于上层项目；先在嵌套仓库核对 `git status --short`、HEAD、分支和 stash。
2. 保留所有已有未提交和未跟踪成果。暂停的 P2 RRF stash 不应用、不删除；不运行破坏性的 `reset`、`clean` 或覆盖式还原。只改任务卡列出的文件。共享工作区一次只有一个写入者。
3. 企业收到的是**原投递固定报告快照**。学生补证、上传新版、生成新报告和变化解释不得改写旧投递。撤回后企业的报告、下载、旧通知和核验路径都必须拒绝新访问；已经交付的本地副本不能声称收回。
4. 授权、撤回、并发、用量入账、AI 引用与事实归因都是高风险边界。复现要覆盖失败路径，不能只测成功返回或复制实现逻辑；ZCode 先自审，Codex 终审。
5. 自动测试只用合成数据和隔离夹具。PostgreSQL 集成测试只在随机 `cp_test_*` schema 中运行；不清理 `public` 或开发业务数据。页面测试使用合成账号，先记录夹具，结束后精确恢复。
6. 不调用真实 DeepSeek、不使用真实简历或联系方式、不向外部人发送消息、不创建密钥、不安装新组件、不提交或推送 Git，除非任务卡明确列出相应授权。ZCode 个人计划额度许可不等于网站模型调用或远端发布授权。
7. 每个小项交[证据包模板](templates/ZCode证据包模板.md)规定的原始命令、完整输出、退出码、diff 文件列表、自审结论、页面证据和未验证项。日志与截图不得含密钥、密码、真实用户材料；缺项就标记“未验证”，不能用口头“通过”补齐。
8. 回报限一屏，长日志、完整 diff 和截图放仓库证据目录。每项末尾提供“下一项建议 + 可定位证据”，由 Codex 决定排序和是否续做。模型选择顺序是 **Start Plan 免费 GLM-5.3 → Start Plan 免费 GLM-5.3-Flash → BigModel 个人 GLM-5.3**；前一档确实不可用才切下一档。额度组切换时必须新建 ZCode 任务并带上已有现场。
