# E2E-02-R1：回复故障后的可编辑草稿

状态：已由隔离生产页面实际复现。证据：`docs/evidence/20261004-E2E-enterprise/reply-failure-2026-10-05T04-26-18-917Z/`，两个故障变体均保留草稿但只读且阻止输入；每变体仅一次POST，响应丢失后服务器确已收到。待修复和复测，不代表已验收。

1. 触发：企业在隔离A/B/A2有效投递报告输入回复、人工确认；注入请求失败或服务器已接收但响应丢失。
2. 现行线索：`ApplicationBoard.tsx`的“未确认发送的回复草稿”使用`readOnly`；会话失败清空列表和旧报告，草稿仍在组件状态。必须实际验证页面，不能仅以源码代替复现。
3. 结果：失败草稿可在当前页面编辑、复制，长度仍限2000字；编辑必须清除发送确认。不得自动重发，不得显示已送达；授权尚未复核时不得显示可发送按钮或旧报告。
4. 送达未知：保留“先核对状态”的提示。响应丢失场景核对服务端实际回复事件数；刷新后已送达的投递不得允许第二次发送。保留原刷新/离窗清理授权和草稿的既有规则，勿擅自持久化草稿或跨投递复用引用。
5. 允许范围：`jianli/src/components/ApplicationBoard.tsx`及最小有意义的相关回归；新的本任务证据目录。会话/后端协议如需改变，先交Codex设计；不扩大到业务数据库、E2E-01脚本或AI评测文件。
6. 测试：能证明故障后真实文本框可输入、发送入口缺失、无自动重试；分别覆盖请求失败和响应丢失。保留既有会话竞态/授权回归。新增测试不得只匹配源码字符串冒充可编辑行为。
7. 页面：E2E-02运行器在同一隔离环境复测桌面与390px；记录编辑前后文本、请求次数、服务端事件数、刷新授权后的状态和快照哈希。
8. 交棒：ZCode实现、目标/受影响测试、自审及证据；Codex独立复核授权边界并抽验后本地提交。代码与纯前端测试可在独占组件范围内并行；当前企业任务仍独占数据库、浏览器和生产运行器，不得重建或重启其服务。页面复测等企业任务交棒后执行，不同时启动两个页面写入者。
