# E2E-01：可重复的隔离全链路测试环境

1. 责任：ZCode 实现隔离夹具/启动脚本/安全回归/证据包；Codex 审查隔离边界后才实际启动浏览器环境。先核对嵌套仓库 HEAD、工作树和 P2 stash，读固定约束与最新接力快照。
2. 目标：用独立 `cp_e2e_*` PostgreSQL 数据库、独立存储目录、8001/3001 端口、独立 Next 构建目录运行同一网站。仅测试进程强制 `AI_EXTERNAL_ENABLED=false`/`AI_PROVIDER=mock`，不改 `.env` 或产品默认 DeepSeek。禁止把现有 careerproof 库当测试库。
3. 文件所有权：仅新增 `backend/evals/seed_e2e.py`、`backend/app/tests/test_e2e_fixture_safety.py`、`scripts/Start-E2E.ps1`、`scripts/Stop-E2E.ps1`、新证据包 `docs/evidence/20261004-E2E-environment/`；允许最小修改 `jianli/next.config.mjs` 支持环境变量选择独立 distDir。正式接力/任务清单由 Codex 持有。
4. 隔离护栏：所有迁移/播种之前拒绝非 loopback、非 cp_e2e_ 前缀数据库；不读取业务简历，不复制现有应用数据。数据库口令从环境读且不打印。新库创建与迁移只能在审查后执行。脚本保留已有进程/端口、只启动和停止自有 PID+开始时间，不删数据卷/业务表。
5. 夹具：创建独立合成企业与学生，两个不同岗位 A/B、固定本地简历/项目材料、具名固定报告及同项引用，通过产品投递服务/API创建有效授权及通知。记录 ID/规范化快照哈希，合成账号凭据只写 ignored 的本地测试状态，不入日志。可借鉴 test_applications_api.py，但不导入测试模块作为运行依赖。
6. 重跑：同一个隔离运行 ID 重跑不得重复新增账号/投递/通知，已有已撤回夹具不得偷偷恢复状态；显式要求新 run ID 创建新夹具。实现最小有意义回归验证目标拒绝、幂等播种和两条快照/通知正确，不用真实模型。
7. 执行范围：本任务先写实现并跑隔离/模拟安全测试与 Ruff/脚本静态检查；**不得实际 CREATE DATABASE、Alembic 或启动新后端，等 Codex 审查后再执行**。不动现有 8000/3000 服务与 careerproof 库，不撤回现有演示投递。
8. 交付：证据包写原始命令/脱敏完整输出/退出码、使用方式、已验与未验、独立端口和目录，review-agent 可用则做只读自审。聊天回报限一屏。发现实现需要扩大允许文件时停下说明具体依赖。
9. 禁止：真实 DeepSeek、真实数据、外部回复、Git 提交/推送、reset/clean、P2 stash；不要创建或修改 ZCode 其他用户任务涉及的文件。
10. 下一阶段（本卡不执行）：Codex 签收后在隔离库启动环境，再用可延迟/失败注入的浏览器测试双投递、通知筛选、撤回、回复失败、下载、学生补证新版报告与变化解释；发现产品缺陷再下独立修复卡。
