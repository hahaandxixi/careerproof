# AI评测协议：引用、补证建议和变化解释

2026-10-09，Codex设计；尚未委派实现，不授权改P2 stash。现基线evals/run_task_plan_quality.py为14个合成样例/23个契约探针，13有来源且片段精确、1无来源，semanticQualityPassRate=null。不能把契约命中率当真实模型质量分。

## 要评测的真实产品行为

1. 引用：每个requirement/citation来自当前冻结材料，path/hash/line/snippet能回溯；旧报告引用、他人/其他岗位/未来报告、第三方参考不得提升本人实践评级。无来源合法降级单列，不计引用精确成功。
2. 建议：六类缺口分别应产出具名交付物、可执行步骤与可观察核验条件，指向当前缺口；不能重复索取已有源码，不能把运行前提写为已运行，不能用小组材料证明本人贡献，也不能把参考样例当本人补证。接受与拒绝都要有独立正反例。
3. 新版变化：调用生产比较逻辑/历史上下文与最终建议管道，按稳定要求ID比对；只换岗位要求应解释评价基准改变，不声称学生能力提高；只加材料应说明具体文件/行及仍缺运行或贡献证据；材料和岗位同变分别归因；无变化不得制造进步；引用ID在两报告局部重用时须按版本/来源区分。

## 样例与指标

固定合成输入、冻结基线结果及预先写定期望，再实现runner；生成器与评审标签分离。保留14旧样例并新增变化组：无变化、仅材料、仅岗位、二者同变、删除证据、来源角色变化、同名文件hash不同、旧引用越界。加入正常建议/恶意解释、无引用、未来完成条件、重复交付物及关键词正确但语义错误的holdout反例。

指标逐维输出分子/分母、case ID和失败原因：sourceExact/noSource/mismatch；有效与越界引用接受/拒绝的precision/recall（明确黄金标签来源）；交付物/步骤/验收条件可操作性分项；变化类型/正确归因/遗留缺口识别准确率。不要将author-written draft计成真实模型输出，不以字段非空或关键词出现就判语义优质。

离线runner不创建provider、不联网、不执行上传源码、不访问业务库；可回放明确标为合成的已保存输出。结构/词法守卫指标与模型/人工语义评价分栏，缺少真实或独立语义评审时保持null/未验证；如用ZCode作盲评，单列AI reviewer及rubric，不冒充人工。独立重复运行除timestamp外结果稳定，支持按case筛选和原输出不覆盖。

目标/受影响回归、原红灯与绿灯、自审、源码/fixture哈希完整交付。Codex用未见holdout反例和变化边界抽验；错误应修产品路径，不只修评测期望。下一阶段依据结果决定P2保持暂停/建议恢复或其他链预算方案，有具体差异证据与验收标准；本协议不允许直接应用stash。
