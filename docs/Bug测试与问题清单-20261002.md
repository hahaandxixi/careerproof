## 二、原始问题记录（按严重级排序，状态见上表）

严重级依据：高＝主流程在可预期场景不可用或大面积故障；中＝特定但现实的场景下功能受损或资源被占；低＝边界场景、体验或账目问题。

### B-01【高·后端】SSE 进度端点占用连接池，演示并发下可拖垮全部接口
- 位置：`backend/app/api/v1/analysis.py:131-176`（`task_events`）
- 现象：流开始前 `get_task` 在请求级会话上开启事务；application_verification 分支特意 `commit()` 释放（135-137 行），但 job_match / resume_parse / project_scan 分支没有——事务（idle in transaction）保持到 SSE 流结束。
- 触发：约 15 个学生同时打开分析进度页（引擎默认池 5+10，`app/core/database.py:13-19`），后续所有 API 等待 `pool_timeout`（30 秒）后报错。评审同时打开页面即可能触发。
- 影响：演示现场大面积请求超时；长事务阻碍 autovacuum。
- 修复方向：为其余分支补与 verification 相同的 `await session.commit()`（或流前用独立只读会话）。

### B-02【高·前端】过期通知锚点命中已撤回投递时，对照板清空且刷新死循环
- 位置：`jianli/src/components/ApplicationBoard.tsx:35`；`jianli/src/lib/notification-session.ts:19-26`；`jianli/src/lib/application-board-session.ts:55-56`
- 现象：URL hash `#application-{uuid}` 指向已撤回投递时，后端 `_access` 返回 404（`applications.py:176-179`），异常导致 `run()` 把整板 `items` 清空报错；"刷新授权投递"会再次执行同一失败查找，且全前端无清除 hash 的逻辑——死循环，只能手改 URL。
- 触发：企业从旧通知进入投递对照，而学生事后撤回；或浏览期间学生撤回后 visibility 触发刷新。
- 影响：主流程页面在撤回场景不可用且错误文案误导用户反复重试。
- 修复方向：锚点 detail 查询失败时降级为"忽略该锚点并清除 hash"，不清空列表。

### B-03【中·后端】心跳协程无异常容忍，一次瞬时 DB 错误导致任务被误标失败、模型结果丢弃
- 位置：`backend/app/services/task_lifecycle.py:96-111`
- 触发：模型调用进行中（可达 180 秒）心跳提交遇到连接抖动 → 心跳协程静默死亡 → 120 秒租约超时后 `recover_interrupted_tasks` 标 FAILED → worker 完成时 token 不匹配，结果作废。
- 影响：真实花费了模型 token 却得到"任务中断"；且此时用量不入 `AiUsageLog`（与 B-08 叠加），日预算账目偏低。
- 修复方向：心跳循环体加 try/except + 连续失败计数，超过阈值才放弃。

### B-04【中·后端】核验 worker 持用户行锁横跨整个模型调用，同用户其他操作最长挂起 180 秒
- 位置：`backend/app/services/application_verification.py:483`（`_daily_ai_budget` 内 `users` 行锁）→ 598 行才 commit
- 触发：HR 发起核验（运行数十秒）期间，同一用户创建补证材料、发起分析、职业规划等全部阻塞在行锁上（对比 `execute_match_task` 在模型调用前就 commit 释放）。
- 影响：单用户自阻塞、前端超时观感"卡死"；不会死锁（锁序一致）。
- 修复方向：预算校验独立事务或校验后立即 commit；执行期仿照主链路用进度回调分段提交。

### B-05【中·前端】岗位要求标题含全角方括号【】时，回复引用定位双端静默失效
- 位置：后端 `backend/app/services/applications.py:36`（`_REPLY_MARKER` 的 `[^【】]+`）、71-81、137 行；前端 `jianli/src/lib/verification-reply-draft.ts:14-17,42`（同一正则模式）
- 触发：企业发布的要求标题含【或】（岗位原文自由文本，完全可能）→ 生成标记 `【第N项：【核心】Java后端】` 无法被 `[^【】]+` 正则匹配 → 企业端"加入回复草稿"后定位列表不出现该条、发送的 references 为空；历史数据则导致学生端企业回复恒为 None 或引用校验 422。
- 影响：正文声称"报告引用编号：R1-E1…"但保存的定位为空，破坏"引用可核验"这一核心卖点的一致性。两个独立审查交叉确认了同根因。
- 修复方向：marker 改用不含用户文本的结构（如 `【第N项】`＋编号），或对标题做转义/占位替换。

### B-06【中·前端】visibilitychange + focus + pageshow 事件叠加造成重复请求与列表闪空
- 位置：`ApplicationBoard.tsx:57-70`、`ApplicationList.tsx:22-29`、`NotificationLink.tsx:22-25`
- 触发：返回标签页时多事件同时触发 `refresh`；Board 每次 run 都重置为空态再全量拉取（首屏即 2 次请求；bfcache 恢复 2-3 次）。
- 影响：请求翻倍（放大 B-01 的连接占用）、列表反复闪空、已打开报告被重复收起。数据不串（generation 守卫完备）。
- 修复方向：refresh 加时间窗去抖（如 3 秒内合并）。

### B-07【中·待确认·后端】补证任务 view 的防御性异常位于列表循环内，单行坏数据使该用户全部任务不可见
- 位置：`backend/app/services/evidence_growth.py:188-229`（`view` 内 model_validate / StopIteration / 主动 raise 409 均无兜底），`list()`（123-131）逐行调用
- 待确认原因：当前写入路径保证数据自洽，正常操作触发不了；依赖历史数据残留或 schema 演进（如 `material_role` Literal 扩展）才会触发。
- 影响：一旦触发，该用户 GET /growth-tasks 整体 500/409，无自愈手段。
- 修复方向：view 失败时降级为"该行标记为不可读"而非中断整列表。

### B-08【低·后端】`finish_task` 失败（租约丢失/停机取消）时模型用量不入账
- 位置：`backend/app/services/application_verification.py:548-597`（AiUsageLog 仅在 finish_task 为真时写）；`task_runner.py:28` 停机取消同理
- 影响：日预算偏低计费，用户实际消耗超出账面。与 B-03 叠加。
- 修复方向：usage 入账与任务状态解耦，finally 中按实际发生写入。

### B-09【低·后端】核验收尾只捕 AppError，快照字段损坏时 UUID 转换异常逃逸
- 位置：`backend/app/services/application_verification.py:518-527`
- 触发：input_snapshot 的 applicationId 缺失/损坏（正常路径不产生，仅手动改库或历史数据）。
- 影响：任务滞留 RUNNING 至租约回收，错误信息误导。
- 修复方向：收尾段与模型段采用对称的异常分类。

### B-10【低·后端】career_planning 的 `except Exception` 把 DB 故障也归为模型降级且无日志
- 位置：`backend/app/services/career_planning.py:604-606`
- 影响：规则候选静默降级可接受，但真实故障原因被吞，排障困难。
- 修复方向：按异常类型分流，DB 异常记日志。

### B-11【低·后端】下载接口在行锁+打开事务内同步读文件
- 位置：`backend/app/services/applications.py:444-449`（`LocalStorage.read_bytes()` 同步 I/O）
- 影响：大文件/慢磁盘时事件循环停顿、学生 withdraw 被拖长；简历文件量级小，评低。
- 修复方向：`anyio.to_thread` 或预读后释放锁再返回。

### B-12【低·前端】通知中心单条操作失败清空整个列表
- 位置：`jianli/src/components/NotificationCenter.tsx:49`
- 触发：弱网下点"标为已读"失败 → catch 里 `setData(null)` → 整页只剩错误条。
- 修复方向：单条失败只更新该行状态。

### B-13【低·前端】补证页"已停止自动查询"提示永不消除
- 位置：`jianli/src/components/GrowthWorkspace.tsx:35-44`（主 effect 重置各状态但漏了 `notice`）
- 触发：轮询超时出现提示后，用户成功刷新任务，提示仍残留误导。
- 修复方向：数据成功刷新时清 notice。

### B-14【低·前端】引用编号字面值同文误报，定位"删不掉"
- 位置：`jianli/src/lib/verification-reply-draft.ts:36-39`（`hasCitationId` 全 block 搜索）
- 触发：用户删掉"报告引用编号"行的编号，但正文其他位置（批注/AI 问题原文）恰含 `R1-E1` 字面值 → 定位仍保留，与页面文案"删除编号即移除定位"相悖。
- 修复方向：编号匹配限定在引用编号声明行内。

### B-15【低·前端】锚点滚动随每次列表变化触发，视口被劫持；行被筛掉时滚动静默失效
- 位置：`ApplicationBoard.tsx:38`、`ApplicationList.tsx:30`（`useEffect(...,[items])` 内 scrollIntoView）
- 修复方向：仅在首次加载或显式导航时滚动一次。

### B-16【低·待确认·前端】下载 blob URL 1 秒后撤销
- 位置：`ApplicationBoard.tsx:75`
- 待确认原因：现代浏览器通常已在 1 秒内完成读取，但规范不保证；大文件或延迟启动时可能产生 0 字节下载。
- 修复方向：监听下载完成事件或在更长时间后撤销。
