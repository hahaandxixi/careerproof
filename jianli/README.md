# CareerProof Frontend

Next.js 前端通过同源 `/backend/*` 代理访问 FastAPI，因此登录使用的 HttpOnly Cookie
不需要暴露给浏览器脚本。

## 本地运行

1. 先启动 `../backend`，默认地址为 `http://127.0.0.1:8000`。
2. 如后端地址不同，将 `.env.example` 复制为 `.env.local` 并修改 `BACKEND_ORIGIN`。
3. 启动前端后访问 `http://127.0.0.1:3000`。

当前已接入：注册、登录、退出、登录状态恢复、真实岗位发布/编辑、企业组织、分类搜索分页、简历/项目/作品上传、版本预览、匹配任务、任务失败重试和持久化报告。

## 业务入口

- `/jobs`：从 FastAPI 查询已发布岗位，按方向、城市、工作类型和关键词筛选。
- `/jobs/mine`：企业成员管理自己所属组织的岗位；`/jobs/new` 支持创建组织、保存草稿和发布。
- `/jobs/{id}`：学生选择本人已解析完成的简历和项目版本，生成真实匹配任务。
- `/portfolio`：简历、项目与作品版本历史；项目支持 ZIP、PDF、DOCX、TXT。
- `/materials/{resume|project}/{versionId}`：学生私有的解析预览。
- `/tasks/{taskId}`：实际任务进度、错误、失败重试与完成报告入口。
- `/reports`、`/reports/{reportId}`：后端持久化报告，展示材料版本与逐项证据。

匹配报告当前仅供创建分析的学生本人查看（管理员可按后端权限访问详情），不会自动向岗位所属企业分享。企业侧目前完成组织和岗位管理，尚未开放投递或候选人报告授权流程。

旧 `/api/jobs` 写接口返回 410；页面不再导入内存 `store` 或 TypeScript 演示匹配流程。旧候选人/匹配地址仅保留迁移说明，不展示演示人物和报告。

当前匹配仍是规则分析，未接真实大模型。分数表示材料支持度，不能理解为能力认证或录用概率；超出规则范围的技能不计入分数。岗位分类与文档作品入口已支持多方向，规则覆盖范围以报告实际标注为准。

身份认证由后端校验。前端区分连接失败与真正的 401；网络或服务器错误提供重试，不直接判为未登录。岗位、报告、材料的归属检查不能由前端替代。

## 材料历史与上传重试

- “我的材料”从后端读取当前用户的简历、项目及全部版本，刷新或重新登录后恢复列表。
- 已创建但未上传文件的项目也会显示，可以点击“继续上传”。“上传新版本”复用项目。
- 每次逻辑创建和上传都有独立请求编号。网络失败时保留编号和已创建项目ID，重试复用它们。
- 当前标签页的未完成提交按用户ID暂存于 sessionStorage。这里只保存请求编号和项目说明，
  不保存文件、简历内容或登录凭证。刷新后需要重新选择原文件；材料历史始终以数据库为准。
- 同一上传请求更换了文件内容时，后端返回409；如确实需要提交不同文件，请选择项目的“上传新版本”。
- 旧版本缺少原文件名或任务关联时仍显示历史记录，不伪造实时进度。

使用此版本前，在后端目录执行 `.\.venv\Scripts\alembic.exe upgrade head`。

## 验证

`npm run typecheck` 检查类型，`npm run build` 检查生产构建。Node.js 22.18+ 或24可运行 `npm test`，
验证上传失败、响应丢失、刷新后恢复请求编号、会话刷新并发合并和网络错误分类。
