# CareerProof Frontend

Next.js 前端通过同源 `/backend/*` 代理访问 FastAPI，因此登录使用的 HttpOnly Cookie
不需要暴露给浏览器脚本。

## 本地运行

1. 先启动 `../backend`，默认地址为 `http://127.0.0.1:8000`。
2. 如后端地址不同，将 `.env.example` 复制为 `.env.local` 并修改 `BACKEND_ORIGIN`。
3. 启动前端后访问 `http://127.0.0.1:3000`。

当前已接入：注册、登录、退出、登录状态恢复、真实岗位发布/编辑、企业组织、分类搜索分页、简历/项目/作品上传、版本预览、匹配任务、任务失败重试、持久化报告、AI 职业规划、补证成长闭环、投递授权与双端通知。

## 新机器首次安装

Windows PowerShell中先安装Node.js 22.18+（或24）及npm，再在**解压后的项目根目录**执行：

```powershell
Set-Location jianli
npm ci
Set-Location ..
```

`npm ci`按本目录已提交的package-lock.json安装依赖，不生成账号、不调用模型。还需按[后端说明](../backend/README.md)安装Python依赖、配置本机环境并准备Docker。两侧准备完成后，从根目录运行 `Start-Local.cmd`，由统一入口构建和启动；不要再同时手动启动第二套服务。检查入口为根目录 `Start-Local.ps1 -CheckOnly`，它不等于Docker/数据库、页面或模型连通性验收。

## 隔离复现的前端地址

仅在新解包、已执行 `npm ci` 的独立目录使用。后端先按[隔离说明](../backend/README.md#无外部ai的隔离交付复现)连接专属数据库、禁用外部AI并监听8107。在该目录的jianli中运行：

```powershell
$env:BACKEND_ORIGIN='http://127.0.0.1:8107'
npm run build
.\node_modules\.bin\next.cmd start --hostname 127.0.0.1 --port 3107
```

浏览器打开 `http://127.0.0.1:3107`。修改后端端口后需要设置BACKEND_ORIGIN并重建，不能复用指向8000的旧构建；重启沿用同一构建与配置。这不是日常3000/8000网站或3001的E2E账号环境。

## 业务入口

- `/jobs`：从 FastAPI 查询已发布岗位，按方向、城市、工作类型和关键词筛选。
- `/jobs/mine`：企业成员管理自己所属组织的岗位；`/jobs/new` 支持创建组织、保存草稿和发布。
- `/jobs/{id}`：学生选择本人已解析完成的简历和项目版本，生成真实匹配任务。
- `/portfolio`：简历、项目与作品版本历史；项目支持 ZIP、PDF、DOCX、TXT。
- `/materials/{resume|project}/{versionId}`：学生私有的解析预览。
- `/tasks/{taskId}`：实际任务进度、错误、失败重试与完成报告入口。
- `/reports`、`/reports/{reportId}`：后端持久化报告，展示材料版本与逐项证据。
- `/recommendations`：AI 职业规划，展示证据候选、档位建议与历史规划变化归因。
- `/growth`、`/growth/{taskId}`：补证任务工作台，衔接缺口任务、新版材料与固定报告对比。
- `/applications`：学生查看本人投递状态与企业人工回复，可直达原报告要求与片段。
- `/notifications`：双端站内通知，未读计数与授权跳转。
- `/demo`：合成测试材料入口（所有人物与数据均为虚构）。

匹配报告默认仅供创建分析的学生本人查看；企业只能在学生明确投递授权后查看对应固定报告，投递撤回即失去访问。企业侧提供岗位管理、已授权投递的“岗位要求 × 候选人”对照视图、AI 核验问题草稿与人工回复。

旧 `/api/jobs` 写接口返回 410；早期内存 `store` 与 TypeScript 演示匹配流程已删除。旧候选人/匹配地址仅保留迁移说明，不展示演示人物和报告。

当前主链路使用 DeepSeek 官方 API 对可定位证据作约束分析，并提供 AI 职业规划与企业岗位要求拆解。匹配时未同意外发也可生成本地规则报告，不调用外部模型；明确同意后，模型不可用、达到限额或输出未通过校验时也会降级为规则报告。规则分数表示材料支持度，不能理解为能力认证或录用概率；超出规则范围的技能在报告中标明暂不支持。岗位分类与文档作品入口已支持多方向，实际覆盖范围以报告标注为准。

身份认证由后端校验。前端区分连接失败与真正的 401；网络或服务器错误提供重试，不直接判为未登录。岗位、报告、材料的归属检查不能由前端替代。

## 材料历史与上传重试

- “我的材料”从后端读取当前用户的简历、项目及全部版本，刷新或重新登录后恢复列表。
- 已创建但未上传文件的项目也会显示，可以点击“继续上传”。“上传新版本”复用项目。
- 每次逻辑创建和上传都有独立请求编号。网络失败时保留编号和已创建项目ID，重试复用它们。
- 当前标签页的未完成提交按用户ID暂存于 sessionStorage。这里只保存请求编号和项目说明，
  不保存文件、简历内容或登录凭证。刷新后需要重新选择原文件；材料历史始终以数据库为准。
- 同一上传请求更换了文件内容时，后端返回409；如确实需要提交不同文件，请选择项目的“上传新版本”。
- 旧版本缺少原文件名或任务关联时仍显示历史记录，不伪造实时进度。

使用此版本前，在后端目录执行 `.\.venv\Scripts\alembic.exe upgrade head`。

## 验证

`npm run typecheck` 检查类型，`npm run build` 检查生产构建。Node.js 22.18+ 或 24 可运行 `npm test`（脚本显式启用 TypeScript 类型剥离），
验证上传失败、响应丢失、刷新后恢复请求编号、会话刷新并发合并、网络错误分类，以及投递核验、通知、补证工作流与会话恢复等纯逻辑层行为。
